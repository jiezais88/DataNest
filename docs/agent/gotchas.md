## 一、结构性与环境硬事实（长期有效，AGENTS.md 正文保留精简版）

- **worker 已补上 caffeine 依赖**；不要回退，否则 `DagExecutionSyncService` 初始化会 `ClassNotFoundException`。
- **Addax writer 配置路径已对齐**：代码读的是 `datanest.addax.writer.*`，不是 `datanest.doris.writer.*`。
- **`writer.database` 兜底已删除**：目标库名由同步任务 `target_database` 决定；为空时直接抛异常。
- **`scheduler_job_id` 失效会惰性重注册（PowerJob）**：`sync_job`/`quality_job` 等表的 `scheduler_job_id` 若指向 PowerJob 上已删除的任务（`deleteJob` 是软删 status=99），触发链路按未注册处理自动重新注册；存量 `xxl_job_id` 老值同理，无须手工清理。
- **Nacos API 可能 401**：直接查 `middleware-mysql` 的 `nacos.config_info` 表更可靠。
- **Nacos 3.x 直插 DB 的新配置不会被下发**（2026-08-07 实测 + 源码确认）：Nacos 3.1.1 的读取走 `ConfigCacheService` 内存缓存 + 本地磁盘 dump（`ConfigChainEntryHandler`/`FormalHandler`），**只在启动时从 DB 全量加载**；直接 INSERT/UPDATE `config_info` 的新 dataId，客户端拉取报 `config data not exist`（服务日志表现为 `[Nacos Config] config[...] is empty`）。**正确做法**：用鉴权发布 API——`POST /nacos/v1/auth/login`（nacos/nacos）拿 accessToken → `POST /nacos/v1/cs/configs`（`--data-urlencode "content@文件路径"`）。查可以直接查库，**写必须走 API**（或重启 middleware-nacos 强制重新 dump）。
- **Doris 是外部主机**：不在 docker-compose 里，部署/清理时不要以为重启容器会影响 Doris。
- **worker 启动 unhealthy 不一定是 caffeine**：若日志报其他 `ClassNotFoundException`，说明还有 `provided` 依赖没在消费方声明。
- **Addax 执行日志**：worker 容器内 `/opt/addax/log/sync_{sync_job_id}.log` 和生成的 job json `/opt/addax/job/job_sync_{sync_job_id}.json` 是排查同步失败的第一现场。
- **Nacos 配置修改后可能不实时生效**：部分服务对 `@Value` 注入无热刷新能力，改完配置后需重启对应服务。
- **MailHog 清空**：`DELETE http://localhost:8025/api/v1/messages`（v2 端点会 404）。
- **Windows Git Bash 下 curl 自测中文接口有坑**（2026-08-06 F1 自测踩）：① curl 命令行内联中文 JSON body 会按本地编码（GBK）发出，后端 Jackson 报 `Invalid UTF-8 middle byte`（表象是 9999 系统内部错误）；② curl `--data-binary @/tmp/xxx.json` 读不到 Git Bash 的 `/tmp` 路径（Windows curl 不识别）。**做法**：用 Python `urllib` 写自测脚本（body `ensure_ascii=False` + `encode('utf-8')`，query 用 `urllib.parse.quote` 百分号编码，终端加 `PYTHONIOENCODING=utf-8` 防控制台乱码）。另外登录接口返回结构是 `data.token`（不是 data 直接为 token 字符串）。
- **一个 AsyncAppender 只能挂一个 appender**（2026-08-06 logback 配置踩）：logback 硬限制，挂第二个时启动日志报 `One and only one appender may be attached to AsyncAppender. Ignoring additional appender named [...]`，被忽略的 appender 文件**会创建但永远 0 字节**（表象极具迷惑性：ERROR 在主文件里有、error 文件却是空的）。做法：每个文件 appender 各包一层 AsyncAppender（见 `data-nest-common/src/main/resources/logback-spring.xml`）。排查 logback 行为异常先看容器启动日志里的 `|-WARN in ch.qos.logback...` 行。
- **PowerJob OpenAPI 的 query param 不能 URL 编码**（2026-08-07 P2 联调踩）：`runJob` 的 `instanceParams` 被 `URLEncoder.encode` 后（`,`→`%2C`），**server 端按原样读取不解码**，processor 拿到的是 `%2C` 字面量导致参数解析失败（表象：任务触发成功但 handler 报"参数无效"）。`SchedulerClient.postWithQuery` 对 `instanceParams` 特判不编码。另：`deleteJob` 是软删除（status=99），`fetchAllJob` 仍会列出；`saveJob` 枚举字段 JSON 直接传字符串名（"API"/"STANDALONE"/"BUILT_IN"）；`/openApi/assert` 参数是 query param 不是 JSON body。
- **PowerJob 工作流节点的参数位反直觉**（2026-08-07，详见 docs/powerjob-migration/handoff.md §5）：server `JobNodeHandler` 把**节点 nodeParams 塞进实例的 jobParams 位**，instanceParams 位是 wfContext（initParams）——DAG 节点 processor 读节点身份用 `TaskContext.getJobParams()`。另外：工作流终态时从未运行的节点快照 status=1 且 instanceId=null（不能当 RUNNING 同步，否则执行永不收敛）；嵌套子工作流 dispatch 期失败（如引用了被删的 job）会把父流程永久挂在 RUNNING，需 stopWfInstance 兜底。
- **E2E 种子固定 ID 号段会顶住雪花 ID 打点**（2026-08-08 sprint6 修）：种子若往批次/历史表写 9e18 量级的固定 ID（如 `9000070000000000051`），spec 里 `MAX(id)` 打点会被顶住（`id > marker` 永不匹配），`ORDER BY id DESC LIMIT 1` 也永远先捞到它。约定：E2E 轮询/打点查询统一加 `id < 9000000000000000000` 过滤（见 sprint6 quality-checks/quality-scores 的 `SNOWFLAKE_ID_MAX`）。
- **并发跑多套 playwright 会互踩共享种子**（2026-08-08）：各 sprint 套件共用同一套环境/种子数据，两个 playwright 实例并发时一方 teardown 会删另一方正在用的种子。同一时刻只跑一个 playwright 实例；排查"测试莫名失败"先确认没有别的实例在跑。
- **common 的 `GlobalExceptionHandler` 是 MVC 专属，WebFlux 网关不能注册**（2026-08-05 部署时发现）：`GlobalExceptionHandler` 是 `@RestControllerAdvice`，其 `@ExceptionHandler(NoResourceFoundException.class)` 引用了 `org.springframework.web.servlet.*` 类型；网关是 WebFlux（无 `spring-webmvc`），WebFlux 的 `RequestMappingHandlerAdapter` 反射 introspect 该 advice 方法签名时 `NoClassDefFoundError: NoResourceFoundException` → 网关启动失败。修复：`CommonExceptionAutoConfiguration`（`@AutoConfiguration`）加 `@ConditionalOnWebApplication(type = SERVLET)`，WebFlux 下不注册。**教训**：`@ConditionalOnWebApplication` 等条件注解必须放在 `@AutoConfiguration`/`@Configuration` 配置类上才生效，放在 `@RestControllerAdvice`/`@Component` 这类被组件扫描或 `@Bean` 注册的普通类上无效。后续给 common 新增 MVC 专属 bean 时注意网关(WebFlux)兼容。
- **前端路由不得与 Vite 静态产物目录 `assets/` 同名**（2026-08-07 Sprint7 F1 联调踩）：`app-frontend` nginx `location /assets/` 是构建产物长缓存目录，SPA 路由 `/assets` 会 301 到 `/assets/`、`/assets/xxx` 会 404（仅客户端跳转可用，刷新/直链必挂）。Sprint 7 资产目录路由因此定为 `/asset-catalog`。新增前端顶级路由前先对照 `data-nest-frontend/nginx.conf` 的 location 块。另：`app-frontend` 的 Dockerfile 只 `COPY dist/`，**改前端代码后必须先本地 `pnpm build` 再 `docker compose build app-frontend`**，否则镜像里还是旧产物（buildkit 缓存表象极具迷惑性）。
- **docker exec 传 stdin 必须加 `-i`**（2026-08-08 Sprint7 F3 自测踩）：`docker exec datanest-middleware-postgres psql ... <<EOF` 不加 `-i` 时 stdin 关闭，psql 立即读到 EOF，heredoc 里的 SQL 一条都不执行，且命令整体返回成功（表象：清理"执行成功"但数据还在）。管道/heredoc 传 SQL 一律 `docker exec -i`，或多条 `-c` 拼接。
- **业务包日志默认 info（2026-08-08 配置审计起）**：`shared-common.yaml` 的 `com.datanest` 级别为 `${DATANEST_LOG_LEVEL:info}`（原全量 DEBUG 导致 mapper SQL 刷屏）。排查时在 compose 给对应服务加 `DATANEST_LOG_LEVEL=debug` 重启。例外：`logging.level.*` 走 Spring `LoggingRebinder`，Nacos 推送后**热生效无需重启**（已实证）；其它 `@Value` 配置改后需重启服务。
- **全栈 down/up 启动顺序与重试（2026-08-11 修复）**：① 所有长驻容器已加 `restart: unless-stopped`（nacos-init 为 `on-failure`）——此前全部 `restart: no`，应用 JVM 在 Nacos 未就绪窗口启动失败退出后**永不重试**，这是"down/up 后微服务全挂且 nacos 恢复后不重试"的根因；② nacos 健康检查改用**登录探针**（`POST /nacos/v1/auth/users/login` 能签发 token 才算就绪）——Nacos 3.x 无 readiness 端点（旧 `/nacos/v1/console/health/readiness` 返回 410），`operator/metrics` 报 UP 时 gRPC(9848)/鉴权子系统可能未就绪，探测窗口拉长到 start_period 180s + 30 次重试；③ `init-nacos.sh` 加固：登录失败/单个配置发布响应非 `true` 直接 exit 1（交给 on-failure 重跑，发布幂等），消除「发布失败却 completed_successfully 的假成功」；④ 启动依赖红线：**测试库（test-mysql/test-postgres）不得作为业务服务 depends_on**（app-engineering/app-worker 曾因此被套牢，测试库一停核心业务起不来）；app-worker/app-job 依赖含 `middleware-powerjob(healthy)`；app-frontend 只依赖 app-gateway。
- **Sprint 8 收尾审计补齐（2026-08-11）**：① 定时清理覆盖新表——`quality_score_history` 评分快照并入 governance `POST /internal/quality/cleanup`（`CleanupRequest.scoreHistoryRetainDays`，默认 90 天，复用 qualityCheckHistoryCleanupHandler 调度）；`asset_view_log` 新增 `POST /internal/assets/view-log/cleanup` + app-job `assetViewLogCleanupHandler`（每天 04:40，默认保留 90 天，平台任务 14 个）。② `cdc_pipeline_log` 不清理（只生命周期/告警写，低频，记录在案）。③ 平台无「删除用户」功能（仅停用），T4「删收藏/关注」无触发点；若未来加用户删除，需 governance 补按 user_id 清 asset_favorite/asset_follow 的端点，评论侧「已注销」兜底已就绪。
- **JDK 25 升级坑（2026-08-11，Java 21→25 已全栈落地）**：① **JDK 23+ javac 不再默认运行 classpath 上的注解处理器**——pom 里只有 lombok 依赖、没配 `annotationProcessorPaths` 的模块编译报「找不到符号 getXxx()」；修复 = 每个模块的 maven-compiler-plugin 显式配 annotationProcessorPaths（全量构建先烧出哪个模块缺）。② **Addax 无法在 JDK 25 运行**：`addax.sh` 带 `-Djava.security.manager=allow`，SecurityManager 在 JDK 24 已彻底移除（JEP 486）——worker 镜像走**双 JRE**：应用 JRE 25（ENTRYPOINT 用绝对路径 `/opt/java/openjdk/bin/java`），`/opt/addax/bin/java` shim 指向 JRE 21（PATH 里 /opt/addax/bin 最前，addax.sh 无 JAVA_HOME 逻辑只认 PATH）。③ 服务镜像基底统一 `eclipse-temurin:25-jre-alpine`；lombok 的 `sun.misc.Unsafe` 警告无害。④ 配套配置（shared-common/shared-rpc，Nacos 已发布）：虚拟线程 `spring.threads.virtual.enabled=true`（JDK 25 下 JEP 491 解决 synchronized pin）；优雅停机显式 `spring.lifecycle.timeout-per-shutdown-phase: 15s`；Feign 换 Apache HttpClient 5 连接池（各 api 模块加 `feign-hc5` compile 依赖 + `spring.cloud.openfeign.httpclient.hc5.enabled=true`，替代无池的 JDK HttpURLConnection）。
- **`PG_DATABASE` 无默认值（fail-fast）**：`shared-datasource.yaml` 不再兜底旧 `datanest` 库；本地 IDE 启动必须显式配 `PG_DATABASE` 环境变量（docker 由 compose 注入），避免静默误连已冻结的旧共享库。
- **接口文档用 springdoc 3.0.x，不用 Knife4j（2026-08-08 选型结论）**：Knife4j 停在 4.5.0（绑死 springdoc 2.x / Boot 3），未适配 Boot 4。实现：4 个业务服务（system/engineering/governance/alert）引 `springdoc-openapi-starter-webmvc-ui` + common `DocsAutoConfiguration`（读 `datanest.docs.title/gateway-prefix` 生成 OpenAPI：servers 带网关前缀 + Authorization 头安全方案）；网关引 `springdoc-openapi-starter-webflux-ui` 配 `springdoc.swagger-ui.urls` 聚合（复用既有路由 `/api/<svc>/v3/api-docs`），`SaTokenConfig` 已放行 `/swagger-ui*`/`/webjars/**`/`/v3/api-docs/**`/`/api/*/v3/api-docs/**`。坑：① 网关 `springdoc.api-docs.enabled=false` 会连带关掉 swagger-config 端点导致聚合配置失效（保持默认开启）；② 新服务接文档 = 引依赖 + 配 datanest.docs 两项 + 网关 urls 加一行；③ worker/job 无用户 API 不接文档。④ Windows Git Bash 下 curl 管道到 python 查验中文响应会出 cp936 乱码假象（服务端数据正常），查验中文写临时文件按 UTF-8 读。
- **实时 CDC 独立 Flink 集群依赖矩阵与 5 大坑（2026-08-09 M0 实测，Sprint 8，详见技术文档 §7.2）**：① 集群 lib 必须预置 7 个 jar：`flink-cdc-dist/common/flink2-compat/pipeline-connector-mysql/pipeline-connector-iceberg`（均 `3.6.0-2.2`）+ `mysql-connector-j:8.0.33`（8.0.27 已下架）+ `flink-shaded-hadoop-2-uber:2.8.3-10.0` + `flink-s3-fs-hadoop:2.2.1`，且 `flink-s3-fs-hadoop` **只能放 lib 不能放 plugins/**（放 plugins 会导致作业看不到 S3A 类 + `Delegation token provider with service name s3-hadoop has multiple implementations` 启动失败）；② **`classloader.resolve-order: parent-first` 必须写集群 config.yaml**（`-D` 作业参数不生效），否则 connector 同时在 lib 与 pipeline.jars 双加载 → `org.apache.iceberg.hadoop.HadoopCatalog cannot be cast to org.apache.iceberg.catalog.Catalog`；③ S3A 凭据用容器环境变量 `AWS_ACCESS_KEY_ID`/`AWS_SECRET_ACCESS_KEY`，endpoint/path-style 用 `/opt/flink/conf/core-site.xml` + `HADOOP_CONF_DIR`（iceberg `hadoop.*` catalog 前缀与 Flink `s3.*` 配置均不透传，只有 core-site.xml 生效）；④ **禁开 `execution.checkpointing.unaligned.enabled`**（与 CDC 自定义 partitioner 冲突 → `JobInitializationException`）；⑤ `pekko.ask.timeout` 需 ≥120s（首次提交 SchemaOperator RPC 到协调器易超时）；⑥ Doris 建 Iceberg catalog 的 `s3.endpoint` 必须用 Doris 主机可路由的宿主侧地址（`http://192.168.119.1:9000`，VMnet8），不能写容器名 `middleware-minio`。
- **宿主机 8081 被 nacos 占用**：Flink JobManager REST 宿主端口映射 18081（容器内 8081）；容器内网访问走 `middleware-flink-jobmanager:8081`。
- **Doris Iceberg catalog 的 `s3.endpoint` 用宿主侧 `http://192.168.119.1:9000`**（VMnet8），不能写容器名；湖仓新数据/新表需 `REFRESH CATALOG/TABLE` 后 Doris 可见（realtime 有 refresh-catalog 端点）。
- **docker compose 下 Flink 容器会因「plugins 与 lib 重复 jar」启动即崩且死锁**：容器起 3 秒即退出，无法 exec 清理；正确做法是直接 `docker compose rm -sf` 移除后重建（配置已固化进 `docker/flink/Dockerfile`，不依赖手工 docker cp）。
- **F2 app-realtime 程序化提交/运维实测坑（2026-08-10，Sprint 8 F2）**：① **Flink 集群必须加 `classloader.check-leaked-classloader: false`**（已写入 compose JM/TM 的 FLINK_PROPERTIES）——否则作业停止/重启后 S3A 报 closed classloader，Iceberg 提交全部失败；② CDC 源库账号需 `REPLICATION CLIENT, REPLICATION SLAVE, RELOAD` 权限（快照阶段 `SHOW MASTER STATUS` 需要，M0 用 root 不暴露，testuser 需补授）；③ Flink 2.x 已移除 `SavepointRestoreSettings` 类，savepoint 恢复走配置键 `execution.savepoint.path` + `execution.savepoint.ignore-unclaimed-state=false`；④ Flink 2.2 REST：`/jobs/{id}/vertices` 子资源 404（vertices 内嵌在 `/jobs/{id}` 响应里），stop-with-savepoint body 为 `{"drain":false,"targetDirectory":"s3a://..."}`（无 formatType，集群未配默认目录时 targetDirectory 必填）；⑤ CDC 3.6.0-2.2 iceberg sink **无 upsert 选项**（下发即报 Unsupported options），write_mode 只留在平台层做主键必填校验；⑥ 提交端 pom 依赖集照 `tmp/m0-cdc-verify/pom.xml`（`flink-shaded-guava` 必须显式 33.4.0-jre-20.0 对齐，CDC 传递带 31.1 会炸）；⑦ 新服务别漏 `MyBatisPlusConfig` 分页拦截器（selectPage 无拦截器退化为全量返回 + total=0，F2 评审才抓到）。
- **CDC 高级配置下发实测（2026-08-10）**：① `FlinkPipelineComposer.compose` **只消费 YAML pipeline 段固定键**（name/parallelism/schema.change.behavior 等 PipelineOptions），任意键如 `execution.checkpointing.interval` 写进 YAML pipeline 段**不生效**（3.6.0-2.2 源码确认 + 实测 interval 仍是提交侧默认）——checkpoint 间隔覆盖只能走提交侧 flinkConfig（`FlinkJobService.submit` 的 override 参数）；② parallelism 在 YAML pipeline 段有效（composer 显式 `setParallelism`）；③ **集群 `taskmanager.numberOfTaskSlots:1`**，configJson 并行度 ≥2 的管道会 `NoResourceAvailableException` 无限 RESTARTING（需先扩 slot 或接受仅 1 并行度可用）。
- **PG 源扩展实测坑（2026-08-10，Sprint 8 F2 PG，已全链路跑通）**：① **oracle 与 postgres pipeline connector 不能同时放 lib**——两 jar 内含同名 `org.apache.flink.cdc.connectors.base.*` 类（131 个），oracle 版引用 shaded HikariCP、postgres 版引用未 shade 版，lib 按字母序 oracle 先加载，PG 作业报 `HikariProxyConnection cannot be cast to org.postgresql.core.BaseConnection`；已将 oracle connector + ojdbc 移至 `docker/flink/lib-oracle-pending/`（原因与候选方案见该目录 README），P3 接 Oracle 前必须先解决；② **PG 表 UPDATE/DELETE 前必须 `ALTER TABLE ... REPLICA IDENTITY FULL`**——REPLICA IDENTITY DEFAULT 时变更事件 before=null，反序列化 NPE（`Struct.get(String) because struct is null`）且该事件成毒消息导致无限重启循环；恢复手段 = 建 FULL + 删复制槽（`pg_drop_replication_slot`）+ 重新 initial 快照；③ PG 复制权限检查**不能**用 `pg_has_role(current_user,'replication')`（PG16 报 unrecognized privilege type，replication 是角色属性不是权限），用 `pg_roles.rolreplication OR rolsuper`；④ postgres connector 的 `scan.startup.mode` 只有 initial/snapshot/latest-offset/committed-offset（**无 earliest-offset**，平台层已在保存+组 YAML 双层拦截 PG+EARLIEST_OFFSET）；⑤ PG 的 YAML tables 格式是 `db.schema.table`，route 的 source-table 是 `schema.table`（table-id.include-database 默认 false）；⑥ pgoutput 自动建 `dbz_publication`（FOR ALL TABLES），slot 按 `datanest_cdc_<pipelineId>` 每管道唯一；⑦ PG 预检连维护库 `postgres`，列表连目标库；本期仅支持 public schema。⑧ **复制槽/wal sender 泄漏（2026-08-11 E2E 发现并已修）**：删除管道不清理 PG 复制槽 → 残留槽占满 `max_wal_senders`（默认 10，测试库 8）→ 新 PG 作业全部 `number of requested standby connections exceeds max_wal_senders` 无限 RESTARTING（且失败重试的 startup 态连接会进一步占满名额，雪上加霜）；已在管道删除链路加槽级联清理（`SELECT pg_drop_replication_slot(...) - **质量任务删除有 RUNNING 保护**：任务下存在 `quality_check_batch.status="RUNNING"` 批次时禁止删除（ErrorCode 4218，对齐采集/同步任务语义）。
- **质量执行调度参数带触发类型**：手动/自动经 `QualityCheckTriggerService` 显式传 `jobId:MANUAL` / `jobId:AUTO_TRIGGER`（带冒号，经 PowerJob instanceParams 传递）；**定时触发用注册时保存的纯 `jobId`（无冒号，jobParams）**，`QualityCheckExecuteHandler` 对无冒号 param 默认按 `SCHEDULED` 处理，有冒号则解析 triggerType。排查"定时触发落库成 MANUAL"先看 handler 的 param 解析。
- **质量结果值提取坑（RANGE）**：Doris/MySQL 对空表 `SUM(...) AS out_of_range` 返回 **NULL**（非 0），且 JDBC 列名可能大小写变化。`QualityCheckService.computeRangeRatio` 已对列名大小写不敏感匹配，且 `total=0` 或 `out` 为 NULL 时按 0 处理。改动时保持该语义。
- **质量接口经 gateway 前缀是 `/api/governance/quality/**`**（gateway 只把 `/api/governance/**` 路由到 governance），不是 `/api/quality/**`。直接调 `/api/quality/...` 会得到 gateway 的 `NoResourceFoundException` 404。质量接口实际路径形如 `/api/governance/quality/jobs/page`。
- **质量执行结果表**：`quality_check_batch`（批次）+ `quality_check_detail`（规则明细）。明细含 `result_value`（结果值）与 `result_level`（Sprint 6 分级判定：`PASS`/`WARNING`/`SEVERE`/`UNAVAILABLE`），不评分。批次状态 `RUNNING/SUCCESS/PARTIAL_FAILED/FAILED`（无规则视为 SUCCESS）。
- **质量分级判定（Sprint 6 分级邮件告警）**：阈值判定在 `QualityCheckService.determineLevel`：`value < warning` → PASS；`warning ≤ value < severe` → WARNING；`value ≥ severe`（或无 severe 时 `value ≥ warning`）→ SEVERE；warning/severe 都为空 → PASS（不告警）；SQL 失败 → UNAVAILABLE。批次收尾 `fireBatchAlert` 按任务 `alert_level`（`SEVERE_ONLY` 收 SEVERE；`SEVERE_WARNING` 收 SEVERE+WARNING）过滤达到等级的明细，调 `AlertFiringService.fireBatch` 合并为**一条邮件** + **每条异常写一条 `alert_history`**；`quality_check_batch.alert_sent` 置 1 幂等。**UNAVAILABLE（数据源不可用/SQL 失败）不触发告警**（R2：避免环境抖动误报），只记录 result_level。告警复用 `alert_rule` 体系，扩展对象类型 `QUALITY`（对象=质量任务，`object_id=任务ID`），`triggerConditions` 固定 `["FAILURE"]`，接收用户在「告警中心」创建 QUALITY 规则时选择（质量任务表单仅配置 alert_level，无接收用户控件）。
- **PYTHON 质量规则沙箱（Sprint 7 DG-10）**：`PythonExecutor.executeQualityCheck` 质量模式注入通用 `conn.json` + `read_table(table, where, limit)`（按 type 选 pymysql/psycopg2/oracledb 驱动），收尾自动 `check(read_table(目标表))` 返回 dict 写 `check_result`。**两个实证坑**：① 沙箱 `_FORBIDDEN_MODULES` 禁 `socket` 时纯 Python 的 pymysql 建连必 ImportError（psycopg2/oracledb 是 C 扩展不受影响）——质量模式已放开 socket，**DAG Python 节点保持禁令，其 `read_doris_table` 存量不可用**（是否放开待用户决策）；② Doris 凭据不能用 `System.getProperty("datanest.doris.*")` 读（拿不到 `@Value` 注入值，密码恒为空串认证必败）——统一从 `DorisDataSourceConfig` 静态 getter 取（已修 `resolveDorisConfig`/`PythonConnectionResolver`）。
- **共享单规则质量 job（id=45）`maxInstanceNum=1` 会丢并发触发**：快速连续触发多个单规则执行时，server 侧 "too much instance is running (1 > 1)" 直接丢弃且实例标 FAILED（无重试无告警）。前端批量连续点「执行」会静默丢失。后续如需支持并发，调大该 job 的 maxInstanceNum。
- **批次列表「成功/失败」与「通过/警告/严重/不可用」两列语义不同（Sprint 6 UX）**：`successCount/failedCount` 反映**执行层**（SQL 是否跑成功），`passCount/warningCount/severeCount/unavailableCount` 反映**判定层**（结果是否达标）。SQL 跑成功但结果不达标 → 判「严重」；SQL 跑失败 → 判「不可用」。四档在 `QualityCheckService.toBatchDTO` 按 `result_level` 聚合，勿混淆。

- **`--trace off` 运行**：CodeBuddy safe-delete shim 会拦截 Playwright 清理旧 trace 文件，导致用例失败；运行加 `--trace off`。
- **Flink slot 唯一 → 强串行**：同刻只跑一个 playwright 实例；force-stop/stop 后作业可能残留在集群占 slot，helper 需 `cancelFlinkJobs` + `waitSlotFree`（兜底重启 Flink 集群）。
- **`waitStatus STOPPED` 后主动 cancel Flink 作业**：stop 是 cancel-with-savepoint，DB 变 STOPPED 但作业可能停在 SAVING/CANCELLING 不释放 slot，后续用例会卡死。

- **Nacos 开启鉴权**：`nacosGet`/`nacosPublish` 必须带 accessToken，匿名读返回 403 JSON，`setLagThreshold` 等会把它当配置发布回 Nacos 导致配置损坏、服务启动失败。
- **批量插入源表避免 `WITH RECURSIVE`**：MySQL `cte_max_recursion_depth` 默认 1000，迭代超限报 3636 中止（数据没插进去→无 binlog→无 lag→告警不触发）。用数字表 cross join 生成序列（不受递归限制）。
- **制造 Flink 作业 FAILED 的方式**：DROP 源表是优雅结束（作业 FINISHED 不触发 FAILURE）；DROP Doris 目标表后 sink 写失败 → RESTARTING，需 Flink 集群配置 `restart-strategy.fixed-delay.attempts=3` 限制重启次数才能到 FAILED 终态（shared-realtime.yaml/docker-compose 已配）。
- **DROP Doris 表需带主机地址**：Doris 是外部主机（192.168.119.135:9030），`docker exec ... mysql --host=... --port=...` 不能 `-h/-P` 短参数（PowerShell 把 `-P` 当开关）。Doris 的 Iceberg catalog 表不在 information_schema，用 `SHOW TABLES FROM datalake_catalog.<db>`。
- **`alert_rule_object`/`alert_history` 外键列是 `alert_rule_id`**（非 `rule_id`），cleanup 与断言都按此写。
- **强制停止语义**：force-stop 只改 DB（置 STOPPED、清 flink_job_id/savepoint_path），不清 Flink 作业，需测试侧主动 cancel 释放 slot；savepoint_path 清空、恢复功能不再可用。


## 八、微服务化改造踩坑（阶段 1-5，2026-08-06/07，当前有效）

- **Feign `lb://` 必须依赖 `spring-cloud-starter-loadbalancer`**：governance/alert-service 原本就有，engineering/worker/job 缺失导致启动报 `No Feign Client for loadBalancing defined`，已在三个 pom 补齐。后续给服务加 Feign client 时先确认该依赖。
- **新服务必须显式声明 `spring-boot-starter-validation`**：该依赖在 common 是 provided，而 `GlobalExceptionHandler` 引用 jakarta.validation 类；缺了启动报 `NoClassDefFoundError: jakarta/validation/ConstraintViolationException`（app-alert 踩过）。新服务脚手架时记得带上。
- **启动类 scanBasePackages 只追加 `com.datanest.common.internal`，不要扫整个 common**：避免误装配 common 里的调度/MVC 专属 bean。SchedulerClient 的配置键已改为 `datanest.powerjob.server-address/app-password` 且**均带默认值**（不再像 XXL 时代 `${xxl.job.admin.addresses}` 无默认值那样直接启动失败），但误装配语义仍要避免。
- **`FeignHttpMessageConverters` 并发缺陷（上游 issue #1307）**：spring-cloud-openfeign 已知 bug——该类未初始化时被并发调用，`getConverters()` 返回空/含 null 的列表，症状是并发首次调用偶发 `'messageConverters' must not be empty`，一次性、不再复现。**Workaround**：common `FeignContextWarmup` 启动期遍历 `FeignClientFactory.getContextNames()`，逐 client 子上下文取 `FeignHttpMessageConverters` 并显式调 `getConverters()` 强制初始化。⚠️ 两个关键细节（5.0.2 源码确认）：① 5.x 中该 bean 在 `FeignClientsConfiguration` 里**按 client 子上下文各一个**，主容器没有（只预热主容器会静默跳过）；② 仅取 Decoder bean 不触发转换器初始化，必须显式调 `getConverters()`。依赖升级到含修复的 spring-cloud 版本后可移除本 workaround。
- **Feign 查询/路径参数禁止用 `LocalDateTime`**：Feign 的 Spring ConversionService 会把 LocalDateTime 查询参数按 locale 格式化（如 `from=8/7/26, 6:20 AM`），服务端按 ISO 解析报 500（job 对账 handler 调 `succeeded-between` 踩过）。**规则**：契约的查询/路径参数一律 ISO String，调用方用 `DateTimeFormatter.ISO_LOCAL_DATE_TIME` 格式化；请求体里的 LocalDateTime 走 Jackson 不受影响。
- **无库服务必须排除 DataSource 系自动配置**：worker/job 无 DataSource 时启动报 `Failed to configure a DataSource`，已在两服务 application.yml 排除 `DataSourceAutoConfiguration/DataSourceTransactionManagerAutoConfiguration/MybatisPlusAutoConfiguration`（Boot 4 类名在 `org.springframework.boot.jdbc.autoconfigure` 包，注意不是旧包名）。
- **Flyway 是代码驱动的，yaml 不生效**：项目 jar 里没有 spring-boot-flyway autoconfigure 模块，`spring.flyway` yaml 配置**不生效**；各持库服务靠本地 `FlywayConfig`（@Bean initMethod=migrate，baselineOnMigrate）。**版本比较忽略尾随零**：baseline marker "1" == "1.0.0"，故存量库跳过 V1.0.0、空库正常执行，勿误判为脚本没跑。**`pg_dump --data-only` 不带 setval**：拆库搬数据后序列不自增，须用 DO 块按 max(id) 同步全部序列（阶段 5 已做过一次）。
- **调度状态同步终态保护（SKIPPED 不可逆）**：`DagExecutionSyncService` 按 PowerJob workflow 实例状态同步节点状态时，`isTerminalStatus`（SUCCESS/FAILED/SKIPPED/TERMINATED）不可逆，只允许推进 WAITING/RUNNING。背景：远程化后 HTTP 延迟使 sync 可能在 worker 侧回调（SKIPPED 已落库）后按调度侧 SUCCESS 状态覆盖回去（条件分支非命中节点曾因此 SKIPPED→SUCCESS）。finalizeIfAllDone 复用同一 helper，改动时保持该保护。
- **MapperScan 同名 bean 冲突曾是过渡期手段**：实体/mapper 逐域迁移期间新旧副本同名共存，`@MapperScan` 加过 `nameGenerator=FullyQualifiedAnnotationBeanNameGenerator`。**已全部回退**（旧副本删除后冲突消失），现在各服务只扫本地包，不要再加。
- **组件扫描不受 MapperScan nameGenerator 管**：同名 @Service 被两处扫描时 nameGenerator 无效，需显式 bean 名（曾把 governance 本地 ScoreCalculator bean 名改为 `governanceScoreCalculator`）。entity 模块删除后此类冲突已消失，但新增同名组件时注意。
