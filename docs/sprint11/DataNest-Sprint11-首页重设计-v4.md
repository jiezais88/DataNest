## 1. 背景与问题诊断

v3 落地后用户反馈"丑"。从产品角度复盘，根因不是配色而是**信息架构**：

| # | 问题 | 证据 |
|---|------|------|
| 1 | 值班第一问（"现在有没有事"）没有直接答案 | 需扫 5 张 KPI 卡 + 健康面板才能拼出结论；唯一状态徽章缩在问候语旁 |
| 2 | sparkline 是装饰不是信息 | 「运行中」「近 24h 告警」卡的 sparkline 复用趋势/失败数据，与卡片语义无关 |
| 3 | 趋势图又大又空 | 近 7 天仅 3 天有数据，主视觉区大片留白；且实现偏离 v3 约束用了红+indigo 堆叠柱 |
| 4 | 快捷操作喧闹 | 8 个彩色图标块像手机桌面，对值班运维是低频入口 |
| 5 | 健康面板说术语 | "1 TM · 0 作业" 是 Flink 字段名不是运维语言；异常行无失败原因/等待时长，「处理」全跳同一页 |

## 2. 定位与硬约束

- **核心用户/场景（用户拍板）**：值班运维盯盘——打开首页 3 秒内回答"有没有事 → 什么事 → 去哪处理"。
- **硬约束（继承 v3 用户拍板）**：一屏零滚动（1440×900 / 1920×1080 两档适配）；不用红绿柱状图；语义色只做小面积高亮不做大色块；全部真实接口数据，禁 mock；各区块独立加载独立失败。

## 3. 信息架构：三层注意力递减

```
┌────────────────────────────────────────────────────────────┐
│ L1 态势横幅：状态判定 + 今日计数 + 刷新          （全宽，唯一焦点）│
├──────────────────────────────────────┬─────────────────────┤
│ L2 左：待处理异常工作队列（主区 2/3）   │ L2 右：系统健康 5 项   │
│   每条：类型/对象/原因/等待时长/行内操作 │      快捷入口 4 个    │
├──────────────────────────────────────┴─────────────────────┤
│ L3 近 14 日运行趋势 strip（64px 高 indigo 面积图，全宽沉底）   │
└────────────────────────────────────────────────────────────┘
```

F 型扫描：状态判定 → 异常队列第一行 → 健康面板。取消"5 张 KPI 卡 + 大图 + 8 图标"平铺结构。

## 4. 区块详设

### 4.1 态势横幅（签名元素）

- 左侧：呼吸状态点 + 大字判定「运行正常」/「N 项需关注」(amber) /「N 项故障」(red)。
- 判定逻辑：Doris/Flink DOWN → 故障；有失败待处理/质量异常/数据源连接失败 → 需关注；无任何异常 → 正常。**计数与异常队列对齐**：失败按任务去重（同一任务多次失败只计 1 项）、质量按「规则+表」去重只保留最近一次（2026-08-16 真实数据验证发现：按执行次数计数导致横幅"12 项"vs 队列 4 行自相矛盾）。
- 判定下方一行小字：问候 + 日期（从 v3 的页面主角降级为辅助信息）。
- **中部（v4.1 新增，行业标配）：今日任务状态分布**——一条 8px 分段条（成功 indigo / 失败 red / 运行中 sky / 等待 slate）+ 各段计数，**每段可点击钻取**到执行历史对应状态筛选。红色仅在有失败时以小段出现，不违反"语义色不做大色块"约束（约束针对柱状图主视觉）。
- 右侧：`24h 告警 N` + 更新时间 + 刷新按钮，自动刷新 60s。成功率从横幅移除（移至趋势 strip 标题行），避免指标过载。

### 4.2 待处理异常工作队列（主区，从列表升级为工作台）

每行：`[类型徽标] 对象名` + 副行失败原因（`reason` 截断 1 行）+ `等待时长` + 行内操作。

- 等待时长由 `failedAt`/`checkedAt` 计算；>4h 转 amber、>24h 转 red（值班升级语义，沿用 v3 PRD 约定）。
- 行内操作按类型分派：DAG/同步失败 →「重跑」「日志›」；质量 →「查看报告›」；告警 →「告警中心›」。
- 固定 5 行，超出「全部 N 条 ›」跳执行历史。
- 空态：一行安静的「近 24 小时无异常」，无插画无 emoji。

### 4.3 系统健康（右栏上）——人话化

5 项「状态点 + 人话描述」：数据源「3 正常 · 1 连接失败」；集成任务「2 个运行中」；Flink CDC「正常 · 3 张表同步中」（不出现 TM）；Doris「正常 · 2ms」；平台服务「正常」。DOWN 项整行浅红底。

### 4.4 快捷操作（右栏沉底）

8 → 4（＋同步任务 / ＋DAG / SQL 查询 / ＋数据源，沿用 v3 拍板口径），白底细边框文字按钮，去彩色图标块。

### 4.5 趋势 strip（L3 沉底）

全宽 100px indigo 单色面积图，14 天窗口；失败日曲线上标小红点，hover tooltip；无柱状图、不占主视觉。

### 4.6 文案产品化约定（2026-08-16 用户反馈）

- 质量结果等级一律中文：SEVERE→「严重」、WARNING→「警告」（前端映射，不落英文枚举）。
- 用户可见文案禁止出现服务名/域名等技术术语（如 engineering / governance / alert），按用户心智表述（任务失败、数据质量、系统告警）。

## 5. 数据映射（无需改后端）

| 区块 | 字段来源 |
|------|----------|
| 横幅判定 | `engineering.pendingFailed` + `governance.doris.status` + `realtime.flink.status` |
| 横幅计数 | `todayTotal` / `successRate7d` / `pendingFailed` / `alert.total` |
| 异常队列 | `engineering.failedItems`（type/name/reason/failedAt）+ `governance.qualityIssues`（ruleName/tableName/checkedAt）+ `alert.summary` |
| 健康面板 | `datasource.stats` / `sync.stats` / `realtime.flink+cdcRunning` / `governance.doris` |
| 趋势 strip | `engineering.trend`（后端 7 天 → 需扩 14 天窗口，见 §7） |

## 6. 状态设计

- 每区块独立加载独立失败：单接口挂了就地「加载失败 · 重试」，不拖垮整页。
- 空平台（全新用户）：横幅区显示三步引导（建数据源 → 建同步任务 → 看运行），替代全页空卡。
- 60s 自动刷新 + 手动刷新（沿用现状）。
