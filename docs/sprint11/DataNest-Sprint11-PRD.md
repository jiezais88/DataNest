## 1. 问题陈述

### 1.1 为什么 Sprint 11 做这件事

Sprint 0~10 将平台的数据流通全链路打通：采集 → 同步 → 编排 → 治理 → 资产 → 实时 → 数据服务。但平台本身的**运营安全能力**存在三个显著缺口：

**缺口一：关键操作无可追溯记录。**
数据工程师删除了一个同步任务、管理员修改了某用户的角色、分析师查询了一张机密表——这些动作的「谁做了什么、什么时候、结果如何」全部没有记录。一旦出现数据泄露或误操作，无法事后审查。规格 CM-05/CM-06（操作审计 + 审计查询）一直挂账。

**缺口二：数据访问权限粗粒度，分析师能看到所有数据源。**
Sprint 0 建立了菜单级 RBAC（角色 → 功能模块可见性），但数据源级和库表级权限为零。分析师用 SQL 终端可以查询所有已接入数据源的所有表，包括生产库核心表。分级分类只能通过「机密表拦截」兜底，而不是在访问入口就做权限过滤。规格 CM-03（数据源级权限）一直缺失。

**缺口三：多 DAG 并发执行时任务争抢资源，高优先级任务被低优先级任务拖慢。**
当前所有 DAG 共享同一批执行资源，无队列隔离、无优先级概念。业务关键的 T+1 日报任务和一个开发测试 DAG 竞争同一批资源。规格 DD-15（任务资源队列与优先级）延期至 Sprint 11 交付。

### 1.2 Sprint 11 要达到的状态

> **所有关键操作留痕可查；数据访问按角色限制到数据源/库/表；重要任务不会被测试任务抢占资源。**

## 6. 功能详细交互

### 6.1 审计日志（CM-05/CM-06）

#### 6.1.1 审计覆盖范围

审计日志需覆盖以下 **10 类操作**，缺一不可（G1 验收依据）：

| # | 操作分类 | 具体动作 | 操作对象示例 |
|---|----------|---------|------------|
| 1 | 用户管理 | 创建用户、禁用用户、启用用户、重置密码 | 用户名 |
| 2 | 权限变更 | 数据源权限配置保存、角色创建/编辑/删除 | 角色名 / 数据源名 |
| 3 | 数据源管理 | 创建、编辑、删除、测试连接 | 数据源名称 |
| 4 | 批量同步任务 | 创建、修改、删除、启动执行、停止执行 | 任务名称 |
| 5 | DAG 编排 | 创建 DAG、修改 DAG、删除 DAG、手动触发 | DAG 名称 |
| 6 | SQL 查询 | 执行 SQL（含失败） | SQL 摘要 + 目标数据源 |
| 7 | 数据 API 管理 | 创建、修改、发布、下线 | API 名称 |
| 8 | API Key 管理 | 创建、禁用、启用、删除 | Key 名称（不记录明文） |
| 9 | 数据分级分类 | 改级（含机密降级） | 库名.表名 + 新旧等级 |
| 10 | 执行队列 | 创建、修改、删除队列 | 队列名称 |

> **不记录的操作**：纯浏览类行为（打开页面、查看资产目录、查看列表）不记录；登录成功不记录（登录失败由系统安全日志覆盖，不在本期范围）。

#### 6.1.2 审计记录内容

每条审计记录包含以下信息：

| 字段 | 说明 |
|------|------|
| 操作时间 | 精确到毫秒 |
| 操作人 | 登录用户名 |
| 操作类型 | 创建 / 修改 / 删除 / 执行 / 改级 等 |
| 资源类型 | 用户 / 数据源 / 同步任务 / DAG / SQL 查询 / 数据 API / API Key / 分级分类 / 执行队列 |
| 资源名称 | 操作对象的可读名称 |
| 操作内容 | 简要描述；SQL 查询记录摘要（前 200 字符）+ 返回行数 + 耗时 |
| 操作结果 | 成功 / 失败 |
| 失败原因 | 失败时记录原因摘要（脱敏，不含密码等敏感信息） |
| 客户端 IP | 发起请求的 IP 地址 |

**保留策略**：默认保留 90 天，超期自动清理。

**安全约束**：审计记录**只增不改不删**——任何角色（含超级管理员）都不能修改或删除审计记录；操作内容中不记录密码、API Key 明文、查询结果数据。

### 6.2 RBAC 细粒度权限（CM-02 / CM-03 / CM-04）

> **背景**：Sprint 0 建立了菜单级 RBAC（角色 → 功能模块可见性），Sprint 11 在其基础上补三块：角色管理可视化（CM-02）、数据源/库/表访问权限（CM-03）、功能权限矩阵展示（CM-04）。

#### 6.2.1 角色管理页（系统管理 → 角色管理）

角色分两类：**预置角色**（4 个，系统内置，不可删除、功能权限矩阵只读）和**自定义角色**（管理员创建，可编辑、可删除）。

```
┌──────────────────────────────────────────────────────────────────────┐
│ 角色管理                                          [+ 创建角色]       │
├───────────────┬──────────┬──────────────────────────────┬────────────┤
│ 角色名称      │ 类型     │ 权限概览                     │ 操作       │
├───────────────┼──────────┼──────────────────────────────┼────────────┤
│ 超级管理员    │ 预置     │ 全部功能 ✅                   │ 查看详情   │
│ 数据工程师    │ 预置     │ 数据源/同步/DAG/SQL/数据 API │ 查看详情   │
│ 数据分析师    │ 预置     │ SQL 查询/资产目录            │ 查看详情   │
│ 治理管理员    │ 预置     │ 元数据/标准/质量/分级分类    │ 查看详情   │
├───────────────┼──────────┼──────────────────────────────┼────────────┤
```

**预置角色**：点击「查看详情」→ 弹出功能权限矩阵弹窗（见下方矩阵表，只读）。无编辑/删除入口。

**自定义角色**：支持创建、编辑、删除。

**创建/编辑角色弹窗**：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| 角色名称 | 文本 | ✅ | 全局唯一，2~20 字符，创建后不可修改 |
| 描述 | 文本 | — | 不超过 100 字 |
| 功能权限 | 复选框组（按钮级） | ✅ | 按下方「按钮级权限清单」勾选到具体按钮，至少勾选一项；支持快捷档位（查看档 / 全部档）+ 展开逐按钮细勾 |

> **设计原则**：
> - **快捷档位**：「查看档」一键勾选该模块所有查看类按钮（查看/查看历史/查看监控/查看统计/查看血缘等）；「全部档」勾选全部按钮；也可展开逐按钮细勾，满足精细场景
> - **菜单显隐由按钮权限推导**：某功能模块至少勾选一个按钮 → 对应菜单项显示；一个按钮都未勾选 → 菜单项不渲染
> - **按钮显隐规则**：无权限的按钮**不渲染**（与菜单同原则，不是置灰）；只有「查看」而无「编辑」时，列表页可见但行内无「编辑」按钮，详情页只读
> - **预置角色同样落到按钮级**：4 个预置角色的按钮级权限固化在下方矩阵（只读不可改），自定义角色复用同一套按钮清单
> - 「告警中心」纳入权限清单——当前实现是写死三角色（超管/工程师/治理员），本期随配置化改为权限项驱动
> - 用户管理、角色管理、权限配置、审计日志、执行队列**不开放**给自定义角色——平台管理类能力仅限超级管理员，避免权限发散

#### 6.2.2 数据源权限配置（CM-03）

**入口**：系统管理 → 权限配置

- 维度：角色（4 个预置 + 全部自定义角色）→ 数据源 → 数据库 → 表，三级树形勾选
- 超级管理员角色：始终全量访问，权限树不可修改
- **默认权限：全量可见（含全部非机密表），按需收缩**——所有角色默认看到全部数据源/库/表（机密表除外，走 Sprint 10 机密锁）；管理员按需对特定角色收缩到指定数据源/库/表，收缩后才生效
- 操作颗粒度：勾选整个数据源 = 该数据源下全部库/表可访问；可进一步取消某数据库/某张表

```
┌──────────────────────────────────────────────────────────────────────┐
│ 权限配置                                                             │
│                                                                      │
│ 选择角色：[数据分析师 ▼]     ← 切换角色后右侧权限树实时刷新           │
│                                                                      │
│ ┌── 数据源访问权限 ──────────────────────────────────────────────┐   │
│ │ [全选]  [全不选]                                               │   │
│ │                                                                │   │
│ │ ☑ 📦 doris-production（Doris）                                 │   │
│ │   ☑ 📂 ods_db                                                  │   │
│ │     ☑ 📄 user_core      ☑ 📄 order_fact     ☑ 📄 ...          │   │
│ │   ☑ 📂 dwd_db                                                  │   │
│ │     ☑ 📄 ...                                                   │   │
│ │                                                                │   │
│ │ ☑ 📦 mysql-biz（MySQL）                                        │   │
│ │   ☑ 📂 business_db                                             │   │
│ │     ☑ 📄 product    🔒 user_payment（机密表，不可单独授权）     │   │

```

**交互规则**：

- 勾选/取消数据源 → 级联勾选/取消其下全部库和表
- 勾选/取消数据库 → 级联勾选/取消其下全部表；数据源勾选状态联动（全选才全勾、部分选中显示半选 `[-]`）
- **机密表**（分级分类标记为「机密」的表）：对非超级管理员显示锁定图标，勾选框禁用，悬停提示「机密表，请先在数据分级分类中降级」
- 「保存权限配置」→ 即时生效，影响该角色下所有用户；保存动作记入审计日志（§6.1.1 第 2 类）
- 切换角色时如有未保存修改 → 弹出确认「当前修改尚未保存，是否放弃？」
- 若某数据源尚未成功采集元数据 → 权限树显示数据源节点但无库/表子节点，可整体勾选

#### 6.2.3 权限生效范围

| 入口 | 权限生效方式 |
|------|-------------|
| SQL 查询终端 - 数据源下拉 | 只显示该用户角色有权限的数据源 |
| SQL 查询终端 - 左侧表树 | 只展示有权限的数据库/表；机密表仍显示但锁定（沿用 Sprint 10 机密锁交互） |
| 资产目录 - 浏览与搜索 | 只展示有权限的数据库/表 |
| 数据 API 创建向导 - 选表 | 只能选有权限的表 |
| 批量同步 - 数据源选择 | 只显示有权限的数据源 |

**说明**：无权限访问时，前端入口直接过滤不展示；绕过前端直接请求后端时，返回「无权限访问该数据资源」并记入审计日志（失败结果）。

- 有绑定 DAG 时删除队列 → 阻止删除，提示「队列 critical 有 3 个 DAG 绑定，请先将这些 DAG 改绑其他队列后再删除」
- 队列有运行中任务时同样阻止删除
- 队列的创建/修改/删除记入审计日志（§6.1.1 第 10 类）
- **权限**：仅超级管理员可管理队列

#### 6.3.2 DAG 队列与优先级绑定

DAG 创建/编辑表单在「调度配置」区域下方新增两个字段：

| 字段 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| 执行队列 | 下拉选择 | default | 选择此 DAG 归属的执行队列 |
| 执行优先级 | 单选（高 / 中 / 低） | 中 | 同队列内高优先级任务优先获得执行资源 |

**调度行为**：

- 同一队列内执行顺序：**高 > 中 > 低**；相同优先级按提交时间先到先执行
- 队列达到最大并发时，新提交任务进入等待队列，按上述规则排序
- 队列「当前运行 / 等待任务」数量在队列列表页实时可见（自动刷新）

| 列名 | 内容 |
|------|------|

| 优先级 | 高 / 中 / 低（徽章颜色区分：红 / 橙 / 灰） |

- 五项状态点：**数据源（24/26）、集成任务（活跃数）、Flink CDC（运行数）、Doris（延迟）、平台服务**；四色语义：● 绿正常 / ● 黄降级 / ● 红故障 / ● 蓝计划维护，颜色配图标/文字（不单独依赖色觉）
- 状态点 + 数值并列展示，异常项（如 Doris 延迟）琥珀色文字高亮

**④ 快捷操作（右栏下，沉底）**

- 动作入口（动词开头），与按钮级 RBAC 联动，无权限入口不渲染：**＋同步任务 / ＋新建 DAG / SQL 查询 / 数据源**（按角色增补：数据分析师加「数据 API」、治理管理员加「数据质量」等）
- 视觉上与系统健康卡片同宽、紧贴其下，共同贯通右栏两行

**⑤ 待处理异常（行动层，左下，占 2/3 宽）**

- 内容：**失败任务** + **质量告警** 混排，按严重度 + 时间排序
- 每行要素：**类型徽标**（同步失败=红 / 质量规则=红 / 告警=琥珀）+ 对象名 + 距今时间 + 行内动作：失败任务给「重跑」，其余「去处理」；**整行可点击**跳转对应页面
- **超时升级**：失败/告警超过 4 小时未处理的行视觉升级（加深底色）
- **责任边界可感知**：标题旁标注「你的任务与负责的表」，明确这是**个人责任圈**而非全平台告警——全平台告警归告警中心
- 无异常时：轻量态「一切正常，暂无需要处理的事项」
- 上限：固定显示 3~5 行（保证一屏不滚），超出显示「全部 ›」跳转对应列表页

#### 6.4.3 空态与新用户引导

- **全新用户**（平台无任何任务）：KPI 区替换为三步引导卡「接入数据源 → 创建同步任务 → 配置调度」，带步骤进度；出现首个任务后自动切换为正式仪表盘
- **严禁 mock 数据/假图表充数**——真实用户会误以为系统故障或数据造假

#### 6.4.4 数据原则

- 各区块数据**全部来自真实接口**，禁止前端写死
- 「待处理异常 / 系统健康」要求接近实时（用户登录即看最新）；KPI 允许 5 分钟级延迟；运行趋势允许 10 分钟级延迟
- 各区块独立加载、独立失败：某一区块接口异常时显示「加载失败，点击重试」，不影响其他区块
