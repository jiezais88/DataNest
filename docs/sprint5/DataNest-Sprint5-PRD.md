# Sprint 5：血缘可视化、全局告警中心与 DAG 控制流增强 PRD

> **版本**：v1.0 | **日期**：2026-08-02 | **作者**：产品通
>
> **Sprint 目标**：让治理管理员和分析师能够直观地看懂数据血缘链路，让平台告警覆盖更广、管理更集中，让数据工程师能够编排更复杂的条件分支和可复用的子
> DAG 流水线。

---

## 1. 问题陈述

### 1.1 为什么 Sprint 5 做这件事

Sprint 4 把数据血缘「埋了下去」：SQL/Python/同步任务执行后，平台已经知道哪张表来自哪张表、来自哪个 DAG
节点。但这份血缘数据还只是一张张记录表，用户看不到、用不顺。

同时，Sprint 4 的告警是跟着 DAG 走的，同步任务和采集任务失败仍然要靠人到各自模块里查看；告警规则分散，不好统一管理。

另外，Sprint 3/4 的 DAG 节点都是「线性执行」：上游成功，下游就执行。工程师还无法表达「如果清洗结果为空，就走告警分支」「如果某个指标异常，就走补偿分支」；也无法把一条常用子流水线封装成可复用的子
DAG。

所以 Sprint 5 的核心命题是： **让血缘看得见、让告警管得住、让 DAG 编得更灵活**。

### 1.2 当前用户怎么做的（痛点）

| 现在                                                      | Sprint 5 之后                                                  |
|-----------------------------------------------------------|----------------------------------------------------------------|
| 血缘记录在数据库里，治理员要手动写 SQL 才能查上下游       | 在元数据详情页一键打开血缘图谱，点选节点即可追溯来源或影响范围 |
| 字段口径出问题，要翻 SQL 代码才能找到它从哪个字段映射而来 | 字段级血缘直接展示列→列的映射链路                              |
| 同步任务/采集任务失败没人知道，等用数时才发现             | 统一告警中心可配置所有任务类型的邮件通知                       |
| DAG 规则分散在各模块，不知道全局有哪些告警                | 系统管理下集中查看和管理所有告警规则                           |
| 工程师想根据上游结果走不同分支，只能复制多条 DAG          | DAG 中直接拖入条件分支节点，按表达式选择下游路径               |
| 常用子流程（如统一清洗、统一校验）在每个 DAG 里重复配置   | 把子流程封装成子 DAG，在父 DAG 中一键引用                      |

### 1.3 Sprint 5 要达到的状态

> 治理管理员进入「元数据管理」→ 找到 `dwd.orders` → 点击「血缘图谱」→ 看到 `ods.orders`、`ods.order_logs` 汇入 `dwd.orders`
> ，再汇入 `dws.order_summary` → 点击 `dwd.orders.amount` 字段 → 看到它来自 `ods.orders.amount` →
> 选择「影响分析」，高亮所有下游表和字段，确认修改该字段会影响哪些报表。
>
> 数据工程师进入「数据开发」→ 在 DAG 画布上拖入「条件分支」节点 → 配置「当上游清洗结果行数 > 0 时走正常分支，否则走空数据告警分支」→
> 保存执行 → 平台按条件自动选择分支路径。
>
> 平台管理员进入「系统管理 → 告警中心」→ 看到所有 DAG、同步任务、采集任务的告警规则 → 统一启用/停用、统一选择接收用户。

#### 6.2.2 图谱交互

- **缩放与平移**：支持鼠标滚轮缩放、拖拽画布。
- **节点点击**：点击非当前表节点，切换到该表的详情页（或在新标签页打开）。
- **影响分析**：点击「影响分析」后，用户再点击某节点，高亮该节点到当前表之间的所有下游路径。
- **溯源分析**：点击「溯源分析」后，用户再点击某节点，高亮该节点到当前表之间的所有上游路径。
- **重置视图**：取消高亮，恢复默认布局。

#### 6.2.3 字段级血缘下钻

在表级图谱中，点击当前表的「字段血缘」按钮，切换到字段级视图：

- 字段选择器列出当前表的所有字段。
- 默认展示选中字段的完整上下游链路。
- 支持同时选择多个字段进行对比。

#### 6.4.2 条件分支节点

双击条件分支节点，弹出配置：

```
┌─ 条件分支配置 ────────────────────────────────────────────┐
│                                                           │
│  节点名称 *                                               │
│  [数据量判断______________]                               │
│                                                           │
│  分支 1（默认分支）                                        │
│  分支名称：[正常流程________]                              │
│  条件表达式：[${upstream.row_count} > 0________]          │
│                                                           │
│  分支 2                                                   │
│  分支名称：[空数据告警______]                              │
│  条件表达式：[${upstream.row_count} == 0_______]          │
│                                                           │
│  [+ 添加分支]                                             │
│                                                           │
│                    [取消]  [保存]                          │
│                                                           │
└───────────────────────────────────────────────────────────┘
```

**规则**：

- 条件分支节点至少包含 2 个分支。
- 每个分支配置一个分支名称和一个条件表达式。
- 表达式支持引用上游节点的输出变量（如 `row_count`、`status`）。
- 按分支顺序匹配，第一个满足条件的分支被执行；均不满足时执行默认分支。
- 每个分支引出一条出线，连接到不同下游节点。

#### 6.4.3 子 DAG 节点

双击子 DAG 节点，弹出配置：

```
┌─ 子 DAG 配置 ─────────────────────────────────────────────┐
│                                                           │
│  节点名称 *                                               │
│  [统一清洗流程____________]                               │
│                                                           │
│  选择子 DAG *                                             │
│  [请选择 DAG ▼]                                           │
│                                                           │
│  执行方式                                                 │
│  ○ 同步执行（等待子 DAG 完成后再继续）                    │
│  ● 异步执行（触发后继续，不关心子 DAG 结果）              │
│                                                           │
│                    [取消]  [保存]                          │
│                                                           │
└───────────────────────────────────────────────────────────┘
```

**规则**：

- 子 DAG 必须处于「已启用」状态。
- 不允许循环引用：子 DAG 不能直接或间接引用父 DAG。
- 同步执行时，子 DAG 失败则父 DAG 中该节点失败。
- 子 DAG 的执行历史在父 DAG 的执行详情中可跳转查看。
- 本期不支持子 DAG 的参数透传与覆盖。

#### 6.4.4 画布连线规则

- 条件分支节点的每个分支只能引出一条出线。
- 普通任务节点仍可按原有规则引出多条出线（表示并行下游）。
- 子 DAG 节点只能引出一条出线（表示子 DAG 执行完成后继续）。

## 7. 引用关系与删除校验总表

| 删除对象     | 被谁引用    | 处理方式                                   |
|--------------|-------------|--------------------------------------------|
| DAG          | 子 DAG 节点 | 禁止删除，列出引用它的父 DAG               |
| DAG          | 告警规则    | 删除 DAG 时级联删除关联告警规则            |
| 同步任务     | 告警规则    | 删除同步任务时级联删除关联告警规则         |
| 采集任务     | 告警规则    | 删除采集任务时级联删除关联告警规则         |
| 条件分支分支 | 下游节点    | 删除分支前校验是否连接下游节点，提示先移除 |

## 10. 风险与对策

| #  | 风险                       | 影响               | 对策                                                            |
|----|----------------------------|--------------------|-----------------------------------------------------------------|
| R1 | 字段级血缘数据不完整       | 字段级链路缺失     | 优先展示已有字段级血缘，缺失部分提示用户补充 SQL 注释或手动标注 |
| R2 | 血缘图谱节点过多时渲染卡顿 | 用户体验下降       | 默认只展示一层上下游，支持逐层展开                              |
| R3 | 条件分支表达式书写错误     | 分支选择不符合预期 | 提供常用表达式模板和实时语法校验                                |
| R4 | 子 DAG 循环引用            | 执行死循环         | 保存时检测循环引用并阻断                                        |
| R5 | 告警规则分散与统一入口冲突 | 状态不一致         | 统一入口和快捷入口操作同一数据源，任何入口修改都实时同步        |
| R6 | 子 DAG 失败影响父 DAG      | 父 DAG 执行失败    | 同步执行时子 DAG 失败父节点即失败；异步执行不影响父 DAG         |
