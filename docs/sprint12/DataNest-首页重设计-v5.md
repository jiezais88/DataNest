# DataNest 首页重设计 v5：运营仪表盘

> 日期：2026-08-17 ｜ 状态：方案待评审
> 原型：`DataNest-首页原型-v5.html`（1440×900 实拍渲染，已评审一版布局）
> 前身：Sprint 11 F5 v4.1「值班态势总览」（本方案**推倒重来**，非增量修改）

---

## 1. 为什么重做

v4.1 的主区是「待处理异常工作队列」（占 2/3 宽）。异常多的时候它是工作台，**但只要异常为 0~1 条，主区就塌成一片空白**——页面信息量由「运气」决定。这是值班台思维，不是仪表盘思维。

**产品定位（用户拍板）**：首页 = **仪表盘**。评判标准不是「异常时多好处理」，而是「任何状态下都一眼看懂平台」。

## 2. 设计原则

1. **信息密度恒定**：每个区块在任何状态下都有有效信息。没有任何区块以「异常」为唯一内容来源。
2. **四感回答四个问题**：规模感（平台里有什么）→ 态势感（跑得怎么样）→ 风险感（有没有事）→ 行动入口（接下来干什么）。
3. **一屏零滚动**（1440×900 / 1920×1080），语义色只做小面积高亮，全部真实接口数据。
4. **异常降级为普通一员**：待处理异常从「主区」降为「三栏卡之一」。它是风险信号，不是页面主角。

## 3. 信息架构

```
┌────────────────────────────────────────────────────────────────┐
│ R1 问候 + 平台状态徽标 + 24h 告警 + 刷新               （轻量行）│
├────────┬────────┬──────────┬──────────┬─────────────────────────┤
│ R2 统计卡×5：数据源 │ 数据表 │ 调度任务 │ 数据API │ 待处理异常(风险卡)│
├───────────────────────────────────────┬────────────────────────┤
│ R3 运行态势（14 日面积图，今日状态      │ 系统健康 5 项            │
│   分段条收进卡头，成功率收进副标题）     │ 快捷操作 4 入口          │
├──────────────────┬────────────────────┴────────────────────────┤
│ R4 待处理异常(紧凑) │ 失败任务排行(近14日) │ 最近运行(feed)        │
└──────────────────┴────────────────────┴────────────────────────┘
```

与 v4.1 的本质差异：

| 维度 | v4.1 值班台 | v5 仪表盘 |
|------|------------|-----------|
| 主区内容 | 待处理异常队列（异常驱动） | 运行态势图（状态无关，恒有内容） |
| 异常的位置 | 页面主角（2/3 宽） | 三栏之一（1/3 宽，紧凑） |
| 无异常时 | 主区塌陷 | 不受影响（TOP 排行 + 动态 feed 填充） |
| 平台规模 | 无呈现 | R2 统计卡（数据源/表/任务/API） |
| 状态分布条 | 独立横幅 | 收进趋势卡头（少一层） |

## 4. 区块详设与数据映射

### R1 问候行
问候 + 日期 + 平台状态徽标（正常/需关注/故障，判定逻辑沿用现有口径）+ 24h 告警 + 更新时间 + 刷新。**数据**：现有 4 域聚合，无新增。

### R2 统计卡 ×5（规模感 + 唯一风险卡）
| 卡 | 大数字 | 副行 | 数据来源 |
|----|--------|------|----------|
| 数据源 | 总数 | `● N 正常 · M 连接失败` | 现有健康项扩展（health 里已有正常/失败计数） |
| 数据表 | 元数据表总数 | `▲ N 近 7 天新增` | **新增小聚合**（governance metadata_table count + created_at 近 7 天） |
| 调度任务 | DAG+同步任务总数 | `今日已运行 N 次` | **新增小聚合**（engineering dag/sync_job count；今日运行现有 todayTotal） |
| 数据 API | API 总数 | `近 24h 调用 N 次` | **新增小聚合**（data-service api 数 + 调用统计） |
| 待处理异常 | N（amber 高亮卡） | `最早已等待 X · 去处理 ›` | 现有 pendingFailed + failedItems，整卡点击钻取 |

卡片语义：前 4 张是「规模+即时状态」，永远有数字；风险卡用 amber 左边条 + 浅底，是全页唯一视觉警报点。

### R3 运行态势（主视觉）
- 14 日 indigo 面积图（沿用 v1.0.2 修好的 8px 内边距实现），失败日红点。
- **今日状态分段条收进卡头右侧**（成功/失败/运行中/等待，每段可点钻取执行历史——v4.1 的行业标配组件保留但不再独占横幅）。
- 近 7 天成功率收进标题副行。
- **数据**：现有 home/kpis trend + today 分布，无新增。
- 右栏：系统健康 5 项（沿用 v4.1 人话化口径）+ 快捷操作 4 入口，均无改动。

### R4 三栏（都有恒常内容）
| 栏 | 内容 | 空态 | 数据来源 |
|----|------|------|----------|
| 待处理异常 | 紧凑行（类型徽标+对象+原因+等待时长+行内重跑），≤3 行 + 全部 N 条 › | 一行安静「近 24 小时无异常」（仅占 1/3 栏，不塌页） | 现有 failedItems |
| 失败任务排行 | 近 14 日按失败次数 TOP5：名次+任务名+最近失败时间+次数，行点击钻取 | 「近 14 日零失败」 | **新增小聚合**（dag_execution+sync_job_history group by 任务 order by failed_count desc limit 5） |
| 最近运行 | 执行 feed：状态点+任务名+结果+耗时+相对时间（DAG/同步/采集混排） | 「暂无运行记录」（仅全新平台） | **新增小聚合**（三表 union 按 start_time desc limit 8） |

### 空平台（全新用户）
保留现有三步引导空态（R2~R4 整体替换），不另外设计。

## 6. 设计决策（待拍板）

| # | 决策点 | 建议 |
|---|--------|------|
| V5-D1 | 待处理异常降级为三栏之一 | ✅ 推荐（解决"空"的核心手段） |
| V5-D2 | 状态分布条收进趋势卡头，取消独立横幅 | ✅ 推荐（少一层，密度更高） |
| V5-D3 | R2 第 4 卡「数据 API」是否保留 | 建议保留（数据服务是平台卖点；无 API 时显示 0 也合理）。也可换「CDC 管道」卡 |
| V5-D4 | 风险卡颜色 | amber（警告级，全页唯一高亮卡）；有 DOWN 级故障时可升级 red 边条 |
| V5-D5 | 状态分段条配色 | **成功段用 indigo 不用绿**（2026-08-17 用户质疑红绿突兀后拍板方向）——全页色彩语义收敛为一条规则：**indigo = 正常/体量，red = 失败/警报（唯一红色，小面积），amber = 警告，sky = 运行中**；趋势图红点保留（白心描边小点，全页唯一失败警示点）；健康/feed 的米粒级状态点保留绿/红语义 |
