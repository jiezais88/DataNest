# DataNest Sprint 12 PRD：开源发布准备（一键部署 + GitHub 发布）

> 版本：v1.0 | 日期：2026-08-17
> 对应路线图：产品规格文档 §15 Sprint 13（开源发布准备），**范围已裁剪**——用户拍板只做路线图的 ①（一键部署脚本 + 部署文档）与 ⑥（GitHub Release 物料准备），并追加实际发布操作；②用户手册、③API 文档站、④贡献指南、⑤示例数据集 + Demo 视频不做。
> 用户角色说明：本 Sprint 的"用户"不是平台终端用户，而是**开源使用者**——克隆仓库后想在本地把 DataNest 跑起来评估的数据工程师/团队。

---

## 1. 问题陈述

### 1.1 为什么 Sprint 12 做这件事

Sprint 0~11 交付了完整的数据中台能力（采集 → 同步 → 编排 → 治理 → 资产 → 实时 → 数据服务 → 安全与调度治理），但平台目前**只对开发者友好，对开源使用者不友好**：

1. **跑不起来**：新用户拿到仓库后，需要自己摸索「先 mvn 构建、再 pnpm build、再 compose up」的顺序，任何一步环境缺失（JDK 版本不对、pnpm 没装、Doris 没配）都是踩坑式报错，评估成本高。
2. **Doris 是隐性门槛**：Doris 是同步链路的目标端，但它不在 compose 里、当前指向开发环境的外部主机 `192.168.119.135`。新用户不知道要自备 Doris、也不知道在哪配，sync 功能开箱即坏。
3. **门面过时**：根 README 停留在 Sprint 5（模块结构、JDK 21、npm、前端 3000 端口等均已过时），开源第一印象与实际能力严重不符。
4. **发布缺位**：仓库无 LICENSE（法律上等于"保留所有权利"，别人不敢用）、无远程 remote、无版本号与 CHANGELOG，不具备开源发布条件。

### 1.2 Sprint 12 要达到的状态

- 一个具备基本环境（Docker + JDK + Node）的用户，**克隆仓库后执行一条命令**即可把 DataNest 全栈跑起来，脚本在环境缺失/ Doris 未配置时给出人话指引而非堆栈报错。
- README 准确反映当前能力与技术栈，新用户 5 分钟内理解「这是什么、能干什么、怎么跑」。
- 仓库具备 Apache-2.0 LICENSE、CHANGELOG、版本号，完成 GitHub v1.0.0 发布。

## 3. 非目标

- 不做用户使用手册、API 文档站（springdoc 聚合页已够用）、贡献指南、示例数据集与 Demo 视频（路线图裁剪，用户拍板）。
- 不做预构建镜像发布（Docker Hub/GHCR）——交付形态为**一键脚本本地构建**（用户拍板）；镜像发布留作后续可选项。
- 不把 Doris 放进 compose（用户拍板：保持外部 Doris + 文档指引）。
- 不改动任何平台业务功能；本 Sprint 只允许部署/文档/物料类变更。
- 不做 CI/CD 流水线、多架构镜像、Helm Chart 等进阶发布形态。

| 角色 | 诉求 |
|------|------|
| 开源评估者（数据工程师） | 想快速判断 DataNest 是否适合团队；耐心有限，跑不起来就走 |

### 核心用户故事

- **US-1（评估者）**：我克隆仓库后运行 `./deploy.sh`，脚本告诉我缺什么（或一切顺利），十几分钟后我能打开登录页用 admin 登录，看到首页仪表盘。
- **US-2（评估者）**：我没有 Doris，脚本/文档明确告诉我「同步与数仓功能需要一个外部 Doris，这样装/这样配」，我配好后填入地址，脚本校验连通性再继续。
- **US-3（落地者）**：我想彻底清理环境，文档里有一条命令能删干净容器、卷和镜像。
- **US-4（路过 star 党）**：我看 README 截图和能力清单，30 秒内明白这是个一站式数据中台，技术栈现代。

## 6. 功能详细要求

### 6.1 F1 一键部署脚本

- **形态**：`data-nest/deploy.sh`（bash；Windows 用户走 Git Bash，文档注明）。不做 PowerShell 版（控制范围）。
- **流程**：① 环境预检（docker/docker compose 可用、JDK 25、Maven 3.9+、Node 18+、pnpm；缺哪项报哪项 + 安装指引链接，一次性报全）→ ② Doris 配置检查（见下）→ ③ `mvn clean install -DskipTests` → ④ 前端 `pnpm install && pnpm build` → ⑤ `docker compose up -d --build` → ⑥ 轮询等待容器 healthy（超时给出日志排查指引）→ ⑦ 打印访问入口（网关 8080、默认账号、PowerJob/Nacos/MinIO 控制台）。
- **Doris 配置**：脚本读取 `.env`（或交互式询问）Doris 主机/端口/账号；未配置时明确提示「同步与数仓功能不可用」并给两个选择：填入 Doris 信息继续 / 跳过（平台其余功能可用，同步功能后续配好再启用）。已配置则做连通性校验（JDBC 或 9030 端口探测），不可达时人话报错。
- **失败处理**：任何一步失败即停，打印失败阶段与对应日志位置；不允许「报错但继续跑」。
- **幂等**：重复执行可覆盖更新（构建 + up -d），不产生重复资源。

### 6.2 F2 部署文档

- 独立文档 `docs/deploy.md`（或 README 快速开始 + docs 详细版，实施时定），内容：
  - 环境要求（准确版本：Java 25、Maven 3.9+、Node 18+/pnpm、Docker + Compose；内存建议 ≥16GB）
  - 快速开始（一条命令路径）
  - **外部 Doris 配置指引**：Doris 是什么/为什么需要/单节点安装要点（FE+BE 最小配置）/DataNest 侧配置项
  - 中间件与端口清单（以当前 docker-compose.yml 为准，含 MinIO/Flink/Kafka/MailHog）
  - 常见问题（端口冲突、内存不足、容器 unhealthy 排查、国内镜像加速）
  - 彻底卸载（容器 + 卷 + 镜像清理命令）

### 6.3 F3 开源物料

- **LICENSE**：Apache-2.0 全文，仓库根目录。
- **README 重写**（根 README.md，中文为主）：
  - 项目简介 + 能力全景（按 Sprint 0~11 实际交付：数据源/同步/DAG 编排/血缘/质量/资产目录/实时 CDC/数据服务/审计/RBAC/执行队列/首页仪表盘）
  - 当前技术栈（Java 25 + Spring Boot 4、PowerJob 5.1.2、Nacos、Flink CDC、React 18 + Vite + pnpm 等，逐项核对现状）
  - 当前仓库结构（三层目录：data-nest-libs / data-nest-apis / data-nest-services + frontend）
  - 快速开始（指向 deploy.sh 与部署文档）
  - 截图（首页仪表盘 + DAG 编辑器 + 血缘图谱 + 资产目录等 4~6 张，存 `docs/screenshots/`）
  - License 声明
- **CHANGELOG.md**：按 Sprint 汇总 v1.0.0 能力（可从各 Sprint handoff/PRD 提炼），遵循 Keep a Changelog 精简格式。
- **版本号**：v1.0.0（首个开源发布）。

### 6.4 F4 GitHub 发布

- 远程仓库由**用户创建**（公开仓库，仓库名用户定）；Agent 负责：配置 remote、推送 main 全量历史、打 tag `v1.0.0`、创建 Release。
- **Release Notes**：亮点能力清单 + 截图 + 快速开始指引 + 已知限制（外部 Doris 依赖、仅中文 UI、Windows 需 Git Bash）。
- **发布前卫生检查**（必做）：仓库内无密码/token 之外的敏感残留核查（现有默认密码均为本地开发口令，README 中保留但标注"本地默认值，生产必改"）；`data-nest/tmp/`、`data/` 等本地产物目录不进发布（核对 .gitignore）；flink/lib 下的 jar 体积评估（是否影响 push，必要时给获取脚本替代直传）。
- 推送与 Release 属外向操作，执行前逐项与用户确认。

## 7. 边界与约束

- 不修改业务代码逻辑；如发现部署相关的既有 bug（如脚本路径问题），最小修复并记录。
- 文档中的账号/密码均为本地开发默认值，统一加「生产环境必须修改」提示，不在本 Sprint 做密钥改造。
- README 重写需保留并更新「文档索引」（指向 docs/ 下现行文档），不再逐 Sprint 罗列过时结构。

## 8. 验收标准

### F1：一键部署脚本

- AC-1：删除本地全部构建产物（target/dist/镜像）后执行 `./deploy.sh`，一次跑通，最终 `docker compose ps` 全部 healthy，`http://localhost:8080` 可登录。
- AC-2：分别模拟 docker 未启动、JDK 版本不足、pnpm 缺失，脚本均一次性报全缺失项 + 人话指引，退出码非 0。
- AC-3：未配置 Doris 时脚本明确提示影响范围并允许跳过；填入不可达 Doris 地址时明确报连通性失败。
- AC-4：重复执行脚本幂等，不产生重复容器/配置。

### F2：部署文档

- AC-5：按文档从零（仅文档列出的环境要求）走完部署无卡点。
- AC-6：文档中的端口、账号、命令与 docker-compose.yml / 实际实现逐一核对一致。

### F3：开源物料

- AC-7：根目录存在 Apache-2.0 LICENSE。
- AC-8：README 中无过时表述（JDK 21、npm、前端 3000、Sprint 5 截止的能力清单、旧模块结构等全部消除）。
- AC-9：CHANGELOG v1.0.0 条目覆盖 Sprint 0~11 全部能力域。

### F4：GitHub 发布

- AC-10：v1.0.0 tag 与 Release 在 GitHub 可访问，Release Notes 含截图与快速开始。
- AC-11：推送内容不含本地产物（tmp/data/test-results 等）与敏感信息。
