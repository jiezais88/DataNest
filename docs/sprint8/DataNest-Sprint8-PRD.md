# Sprint 8：资产目录深化 + 实时 CDC 管道 + 质量报告 PRD

> **版本**：v1.0 | **日期**：2026-08-09 | **作者**：产品通
>
> **Sprint 目标**：在 Sprint 7 资产目录「找得到、看得懂、敢使用」基础上，让资产目录**可协作、可沉淀、可引导**（标签/收藏/关注/评论/热度）；打通平台第一条**实时数据链路**（MySQL Binlog → Doris，架构级新增 realtime-service）；并为治理侧补齐**质量报告完整版**（多维趋势 + 问题清单 + 导出），让质量成果「可汇报、可考核」。

## 1. 问题陈述

### 1.1 为什么 Sprint 8 做这件事

Sprint 2~7 已把「采集、开发、治理、血缘、质量、资产发现」全部打通：分析师能搜到表、看懂表、敢用表。但三条链路仍是空白：

**缺口一：资产目录「只读」，无法协作沉淀。**
分析师找到一张表后，既不能收藏方便下次再用，也不能标记「这是一张可靠的核心表」，更无法告诉同事「这张表有坑」——每个人都在重复「问人 → 找表 → 验质量」的老路。规格文档 DC-06~09（标签/收藏关注/评论/热度）正是为此设计，让资产目录从「静态清单」变成「活的社区」。

**缺口二：数据只有「批量」，没有「实时」。**
当前所有数据接入都是 Addax 批量同步 + 定时采集，业务数据库的变更要等下一次定时调度才能看到（分钟~小时级）。规格文档 DI-04（CDC 实时采集）与模块七 RC-01（实时 CDC 入湖）从 MVP 起就是 P0 能力，但一直未启动。路线图把「实时 CDC 管道」明确排入本期，作为 DataNest 的第一条实时链路。

**缺口三：质量数据沉淀了，但没有「汇报出口」。**
Sprint 6 质量体系 + Sprint 7 Python 规则已经持续产出检查批次、四档分级、表级评分，但治理管理员**拿不出一张面向管理层的质量报表**——没有按表/库维度的趋势，没有问题清单，无法向领导汇报治理成效。质量报告 DG-07 在规格文档 §15.1 明确排入 S8（Sprint 6 只做了接口预留的数据底座），本期补齐完整版。

所以 Sprint 8 的核心命题是：**让资产可协作沉淀、让数据实时流动、让质量可汇报考核**。

### 1.2 当前用户怎么做的（痛点）

| 现在                                                                   | Sprint 8 之后                                                             |
|------------------------------------------------------------------------|---------------------------------------------------------------------------|
| 分析师找到好表只能记在自己的小本本里，同事互相问「那张表在哪」           | 收藏常用表、打标签（如「核心表/谨慎使用」），资产按标签/热度快速发现       |
| 表结构变了、数据更新了，用数的人毫不知情，跑出结果才发现不对             | 关注表后，表变更动态自动出现在「我的关注」，可及时感知                     |
| 用数人对表质量有意见只能私下吐槽，反馈不到负责人                         | 详情页评论讨论，形成「发现 → 反馈 → 改进」闭环                             |
| 业务库变更要等下次定时同步（分钟~小时级），无法支撑实时场景              | CDC 管道秒级捕获 MySQL Binlog 变更，实时写入 Doris                         |
| 治理管理员汇报治理成效时拿不出报表，只能口头描述「做了很多质量检查」     | 质量报告：多维趋势图 + 问题清单 + CSV 导出，可汇报可考核                   |

### 1.3 Sprint 8 要达到的状态

> 分析师在资产详情页点「收藏」并给 `dwd.orders` 打上「核心表」标签，下次从「我的收藏」一键进入；关注该表后，某天采集到表结构变更（新增字段），「我的关注」页出现变更动态。
>
> 数据工程师在「数据工程 → CDC 管道」新建一条管道：选择业务 MySQL → 勾选 `orders` 表 → 目标 Doris `dwd.orders` → 保存启动。之后业务库的每次增删改都在秒级同步到 Doris，管道页实时展示当前延迟与累计变更数。
>
> 治理管理员打开「数据治理 → 质量报告」，选择「最近 30 天 · 交易域」，看到四档分布趋势折线、评分趋势、评分最低 Top 10 问题表清单，一键导出 CSV 用于汇报。

### 6.2 数据标签（DC-06）

资产详情页头部新增标签区，资产列表/搜索结果显示标签：

```
┌─ 资产详情：dwd_orders ─────────────────────────────────────────────┐
│  dwd / dwd_orders   [交易域] [订单]  ⭐85   核心表 · 每日更新        │
│                                                                     │
│  🏷 标签：[核心表] [高可用] [+ 添加标签]                             │
│          ┌ 输入标签名，回车创建/复用，可多标签                      │
│  ── 基础信息 ──  ── 字段列表 ──  ── 血缘图谱 ──  ── 质量 ──        │
└─────────────────────────────────────────────────────────────────────┘
```

**交互说明**：
- **打标**：资产详情页添加标签（输入即建，复用已有同名标签）；标签随表展示，点击标签跳转资产列表按该标签筛选。
- **标签权限**：所有角色可打/删标签（分析师协作诉求，规格 DA-04）；标签是「平台级标签」而非个人标签。
- **筛选与搜索**：资产首页新增标签筛选（下拉/标签云）；Sprint 7 搜索接口已预留标签维度（`searchAssetTables` 五维含标签），本期补全实际匹配与返回。
- **删除表**：表删除时其标签绑定关系一并清理。

> **标签模型**：`asset_tag`（标签字典）+ `metadata_table` 关联（多对多或数组列），新表/字段设计见技术文档。Sprint 7 已在 `metadata_table` 预留标签展示位，接口需补 `tags` 字段回填。

│  [上一页] [1] [下一页]                                             │
└─────────────────────────────────────────────────────────────────────┘

**交互说明**：
- 详情页「关注 / 已关注」按钮（铃铛图标）与收藏按钮并列。
- **变更来源**：复用现有元数据采集变更明细 `collect_change_detail`（`ADDED_TABLE / DELETED_TABLE / MODIFIED_TABLE`），关注表在采集到变更时产生站内动态。
- **我的关注**：独立菜单页，展示关注表列表 + 每张表最近变更动态（时间 + 变更摘要），最新在前。
- **通知方式**：本期仅**站内动态**（NG8：不做主动邮件推送）。

### 6.6 实时 CDC 管道（DI-04 / RC-01 / RC-03 部分）

> **架构说明（用户确认架构级新增）**：本期新增 **realtime-service**（`data-nest-realtime`，容器 `app-realtime`），内嵌 Flink CDC MiniCluster，独立于现有 7 服务注册 Nacos、走 Gateway `/api/realtime/**`。独立新库 `datanest_realtime` 持有 cdc_pipeline/执行记录等表（第 5 个业务库，独立 Flyway）。目标落点为 **Doris + Iceberg 湖仓层**：CDC 数据先入 Iceberg 湖仓表（JDBC Catalog 基于 PostgreSQL/MySQL），再通过 Doris 外部表（`Iceberg Catalog`）查询，严格对齐规格文档 §17 与模块七的「CDC 入湖」语义。基础设施需新增 MinIO（Iceberg 文件存储）+ Iceberg 表格式。

#### 6.6.1 CDC 管道配置向导

```

│                                                                     │
│  ② 源配置                                                            │
│  源数据源 *   [业务 MySQL (test-mysql) ▼]                            │
│  源数据库 *   [business_db ▼]          (自动读取该数据源库列表)       │
│  同步表 *     [☑ orders  ☑ order_items  ☐ users]   (勾选多表)         │
│  同步模式     ● 全量 + 增量（默认）  ○ 仅增量（需先建快照）           │
│  启动位点     ● 从最新  ○ 从最早                                       │
│                                                                     │
│  ③ 目标配置                                                          │

**向导约束**：
- **源**：本期支持 **MySQL**（binlog 开启校验；Flink CDC 连接器生态内 PG/Oracle 留作后续，规格 DI-04 要求至少 MySQL CDC）。
- **目标**：CDC 数据先入 **Iceberg 湖仓表**（JDBC Catalog 基于 middleware-postgres，文件存储使用内置 MinIO），再通过 **Doris Iceberg External Catalog** 查询，对齐规格文档模块七「CDC 入湖」语义。
- **基础设施**：本期新增 **MinIO** 容器（对象存储）+ Iceberg 表格式（Flink CDC 内嵌 Iceberg Sink）。
- **全量 + 增量**：默认启动先做一次全量快照，再持续捕获增量变更；`仅增量` 需表已存在快照。
- **校验**：保存前校验源数据源连通性、binlog 是否开启、MinIO 可写、目标库可访问；失败给出明确错误。

│  [新建管道]  [全部/运行中/已停止/异常]                                │

│  │ 用户同步   users       dwd       已停止   —        3,215    [▶][📝][📄][🗑] │
│  └────────────────────────────────────────────────────────────────┘ │
│  状态徽章：运行中(green) / 已停止(gray) / 异常(red)                   │
│  操作：启停切换 / 编辑（需停止）/ 日志 / 删除（运行中确认后先停再删）  │
└─────────────────────────────────────────────────────────────────────┘
```

**监控与日志**：
- **当前延迟**：端到端延迟 = Binlog 事件时间 - Doris 外部表最后可见快照时间（管道页 + 列表列），> 30 秒标红（考虑 Iceberg commit + Doris 刷新延迟，适当放宽于规格 RC-01 的 5 秒目标）。
- **累计变更**：管道启动以来捕获的行变更总数（含全量 + 增量，从 Flink CDC metrics 统计）。
- **运行日志**：管道日志抽屉（Checkpoint 记录、binlog 位点、Iceberg snapshot 提交、错误堆栈），可刷新/清屏。

**删除校验**：删除 CDC 管道前提示会停止数据同步；管道不引用数据源级联（删除数据源时校验仍有管道引用，提示先删除管道——见 §7）。

## 7. 引用关系与删除校验总表

| 删除对象          | 被谁引用                                       | 处理方式                                                             |
|-------------------|------------------------------------------------|----------------------------------------------------------------------|
| 数据源            | CDC 管道（源）                                 | 删除数据源前校验仍有管道引用，提示先删除/停止管道                     |
| 元数据表          | 标签 / 收藏 / 关注 / 评论 / 质量报告           | **表删除时级联清理标签绑定、收藏、关注、评论**                        |
| 标签              | 表（标签绑定）                                 | 删除标签时自动解绑所有表引用，不阻断删除                             |
| 用户              | 收藏 / 关注 / 评论                             | **用户删除：保留评论历史（标记"已注销"）；删除其收藏、关注数据**      |
| CDC 管道          | Iceberg 湖仓表 / MinIO 文件                    | 删除管道先停止运行，确认后删除元数据；不自动删除已写入 Iceberg 的表数据（需手动清理） |
| 质量任务/规则     | 质量报告（历史数据）                           | 沿用 Sprint 6：历史保留不级联删除，按保留天数清理                     |

> **关注/收藏/评论的归属**：均为个人维度（user_id），删除用户时保留历史评论（显示"已注销"）、删除收藏/关注数据。以上策略已于 2026-08-09 用户确认。
