# Sprint 1：数据源连接与元数据采集 PRD

> **版本**：v2.3 | **日期**：2026-07-24 | **作者**：产品通
>
> **Sprint 目标**：让数据工程师能在 DataNest 中安全地接入 MySQL、PostgreSQL、Doris
> 三类数据源；让治理管理员能创建并管理元数据采集任务，把源库表结构自动采集成平台元数据。
>
> **一句话交付标准**：工程师 5 分钟内添加一个 MySQL 数据源，治理员创建一个元数据采集任务并执行，任务成功后元数据管理页自动出现该数据源的表和字段信息。

---

## 1. 问题陈述

### 1.1 为什么 Sprint 1 做这件事

Sprint 0 已经搭好门和锁——用户能登录、有角色。Sprint 1 要让平台 **有数据可看、有任务可管**。

没有数据源连接，后面的同步、开发、治理、资产目录都是空中楼阁。同时，如果元数据采集没有任务化、没有历史记录，治理管理员就无法知道：

- 什么时候采过？
- 采成功了还是失败了？
- 源库结构变更后有没有重新采？
- 每次采集影响了多少张表、多少个字段？

所以 Sprint 1 的核心命题是： **把外部数据源"接进来"，并把元数据采集变成可管理、可追溯的任务。**

### 1.2 当前用户怎么做的（痛点）

| 现在                                   | Sprint 1 之后                                  |
|----------------------------------------|------------------------------------------------|
| 数据源信息散落在各工程师本地配置文件里 | 统一在平台注册，加密存储                       |
| 新同事不知道有哪些表、字段什么意思     | 创建采集任务并执行后，表名/字段名/注释一目了然 |
| 连接密码明文写在脚本里                 | 密码加密存储，界面显示脱敏                     |
| 元数据靠 Excel 或 Confluence 维护      | 采集任务自动同步，改动后重新执行任务           |
| 不知道上次采集什么时候、成没成功       | 每次执行都有历史记录和完整日志                 |

### 1.3 Sprint 1 要达到的状态

> 工程师登录 → 进入「数据源」→ 添加 MySQL 数据源 → 测试连接 → 保存 → 治理员进入「元数据采集任务」→ 创建任务 → 选择数据源 →
> 执行 → 进入「元数据管理」→ 自动看到采集到的表和字段。

### 5.3 元数据采集任务

元数据采集任务为 **异步任务**，支持 **手动触发**和 **Cron 定时触发**。采集粒度到「数据源 →
库/Schema」：一个任务绑定一个数据源，可选该数据源下的一个或多个库/Schema。不同库/Schema 可并行采集，同一数据源下不同任务不互斥。

> 注：任务由调度执行器触发，平台侧任务状态只展示「未执行 / 运行中 / 正常 / 失败」，不展示「排队中」。

**字段说明**：

- 「立即执行」：保存任务并触发一次调度执行器采集
- 「保存」：仅保存任务，不执行
- 「取消」：关闭抽屉

> 无论触发方式是手动还是定时，都显示「立即执行」按钮，方便保存后立即验证。

**库/Schema 拉取规则**：

- 选择数据源后，点击「选择库/Schema」下拉，后台连接该数据源并拉取库/Schema 列表
- 下拉显示加载中状态，失败时提示「拉取库/Schema 失败：连接超时」
- MySQL 显示 database；PostgreSQL 显示 schema；Doris 显示 database
- 若数据源未连接成功，下拉不可用

#### 5.3.5 执行任务

点击「执行」后：

1. 按钮短暂进入 loading 状态（约 1 秒），随后恢复
2. 任务状态直接变为「运行中」
3. 列表轮询刷新状态，不需要等待执行完成
4. 用户可离开页面，执行完成后状态自动刷新
5. 失败后行内显示红色失败提示，可点击「历史」查看详情

**执行中提示**：

```
核心库采集  正在执行中...  已采集 23/45 个表
```

**失败提示**：

```
核心库采集  执行失败：连接 order_db 超时
```

**异步说明**：

- 点击执行后，请求提交到调度执行器并立即返回，前端不阻塞
- 同一任务内多个库/Schema 可并行采集
- 同一数据源下不同任务互不阻塞
- 执行进度通过轮询刷新列表

## 7. 验收标准

### 7.1 功能验收

| #     | 验收项                 | 通过标准                                                                                                       |
|-------|------------------------|----------------------------------------------------------------------------------------------------------------|
| AC-1  | 添加 MySQL 数据源      | 填写正确信息后测试连接成功，保存后列表出现该数据源                                                             |
| AC-2  | 添加 PostgreSQL 数据源 | 同 AC-1                                                                                                        |
| AC-3  | 添加 Doris 数据源      | 同 AC-1                                                                                                        |
| AC-4  | 连接失败提示           | 故意填错密码，提示"用户名或密码错误"或"连接失败"                                                               |
| AC-5  | 密码不泄露             | 数据库中密码为加密形态；列表和编辑页均不显示真实密码                                                           |
| AC-6  | 创建元数据采集任务     | 选择一个数据源和多个库/Schema，保存后任务列表出现该任务                                                        |
| AC-7  | 手动执行任务           | 点击执行后任务状态变为「运行中」，完成后变为「正常」；前端不阻塞                                               |
| AC-8  | 定时触发任务           | 配置 Cron 后到达指定时间自动执行                                                                               |
| AC-9  | 全量+增量采集          | 首次执行全量采集；第二次执行仅同步变更，保留未变更表的注释                                                     |
| AC-10 | 历史记录完整           | 每次执行生成历史记录，包含执行时间、状态、耗时、库/表/字段数                                                   |
| AC-11 | 完整日志               | 失败任务可查看 ERROR 级别日志；成功任务可查看 INFO 级别执行日志                                                |
| AC-12 | 变更统计               | 历史详情中显示新增/删除/修改的表和字段数量                                                                     |
| AC-13 | 元数据展示             | 任务执行成功后，元数据管理页自动出现对应数据源的表结构                                                         |
| AC-14 | 编辑注释               | 治理员编辑表/字段注释后刷新不丢失；增量采集不覆盖人工补充的注释                                                |
| AC-15 | 删除任务               | 删除任务后任务列表消失，历史记录被级联删除，已采集元数据保留                                                   |
| AC-16 | 删除数据源             | 未被采集任务引用时可删除；删除后列表消失，已采集元数据保留并标记源已下线；若被引用则弹窗阻止删除并列出引用任务 |
| AC-17 | 权限隔离               | 数据工程师和数据分析师看不到「元数据采集任务」菜单；数据分析师看不到「数据源」菜单                             |

### 7.2 非功能验收

| #     | 验收项       | 通过标准                                   |
|-------|--------------|--------------------------------------------|
| NAC-1 | 连接测试超时 | 连接不可达时 10 秒内返回失败，不卡死       |
| NAC-2 | 采集性能     | 100 张表的数据源全量采集 < 30 秒           |
| NAC-3 | 并发采集     | 多个任务同时执行不互相阻塞                 |
| NAC-4 | 错误隔离     | 某个数据源采集失败不影响同任务中其他数据源 |
| NAC-5 | 日志性能     | 单次执行产生 1000 条日志不卡顿             |

## 8. 风险与对策

| #  | 风险                             | 影响           | 对策                                                                          |
|----|----------------------------------|----------------|-------------------------------------------------------------------------------|
| R1 | 不同数据库的元数据查询语法差异大 | 开发周期延长   | 先支持 MySQL/Doris（MySQL 协议），PostgreSQL information_schema 与 MySQL 接近 |
| R2 | 用户填写的连接信息错误率高       | 测试连接体验差 | 测试连接时给出具体错误分类（超时/认证失败/库不存在）                          |
| R3 | 密码加密方案选错导致后续难换     | 安全债务       | Sprint 0 已确定 AES-256-GCM + 密钥放 Nacos security 配置                      |
| R4 | 定时任务调度可靠性               | 错过执行时间   | 使用调度框架，任务状态持久化，支持错过触发策略                                |
| R5 | 增量采集判断逻辑复杂             | 开发量增大     | 首次 Sprint 1 可简化增量策略：按表名+字段名对比，忽略字段顺序变化             |
| R6 | 多任务/多库并发对源库造成压力    | 影响业务库     | 同一任务内多个库/Schema 可并行，Sprint 2 补充并发资源配额和限流               |
