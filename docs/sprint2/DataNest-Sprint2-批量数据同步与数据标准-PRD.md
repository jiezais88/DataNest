# Sprint 2：批量数据同步与数据标准 PRD

> **版本**：v1.3 | **日期**：2026-07-27 | **作者**：产品通
>
> **Sprint 目标**：让数据工程师能创建批量同步任务，将已接入数据源的数据写入 DataNest 内置的 Doris
> 存储引擎；让治理管理员能定义和管理数据标准，并对已有元数据进行标准合规检查。同步完成后自动更新元数据，让治理链路闭环。

---

## 1. 问题陈述

### 1.1 为什么 Sprint 2 做这件事

Sprint 1 完成了两件事： **接入数据源** 和 **采集元数据**。但现在工程师面临新问题：

- **数据还在外面**：虽然数据源接入了，但数据本身还在源库里，没有进 DataNest 的存储引擎。后面要做开发、治理、查询，都需要数据先进来。
- **同步后又要手动采集**：Sprint 1 里批量和采集是两件事。工程师同步完数据，治理员还得手动跑一次采集任务才能看到新表——链路是断的。
- **没有标准就谈不上治理**
  ：元数据采进来了，但表名五花八门、字段类型随心所欲。治理管理员需要一个工具来定义"什么叫好"，并检查现状是否符合标准。

所以 Sprint 2 的核心命题是： **把数据真正"搬进来"，并在搬完之后自动补全元数据，同时把治理的第一块砖（数据标准）砌上去**。

### 1.2 当前用户怎么做的（痛点）

| 现在                                           | Sprint 2 之后                                      |
|------------------------------------------------|----------------------------------------------------|
| 工程师手动写 Addax 配置文件，一个任务一个 json | 在平台上配置源表 → Doris 目标表，可视化字段映射    |
| 同步完数据，元数据还是旧的                     | 同步成功后自动触发元数据更新                       |
| 新增数据源后不知道表里有什么数据               | 点击数据源旁的「预览」按钮，直接看前 100 行        |
| 同步任务失败了不知道，等用数据时才发现         | 失败时收到告警通知；可配置自动重试                 |
| 表名和字段名没有统一规范                       | 治理员定义命名标准和字段类型标准，一键检查不合规项 |
| 新同事不知道表名该叫什么、字段类型该用什么     | 数据标准成为团队的单点参考                         |

### 1.3 Sprint 2 要达到的状态

> 工程师登录 → 进入「批量数据同步」→ 创建任务 → 选源表 + 选 Doris 目标库 → 映射字段 → 执行 → 同步完成 →
> 元数据管理页自动出现新表 → 治理员进入「数据标准」→ 定义命名规范 → 一键检查 → 看到不合规的表和字段。

### 1.4 关键概念：内置 Doris 与外部数据源

DataNest 自带一套 **内置 Doris 集群**作为数据存储引擎。它是平台的一部分，随平台一起启动，不是用户手动添加的"外部数据源"。

**内置 Doris vs 外部 Doris 数据源**：

|                          | 内置 Doris                                   | 外部 Doris 数据源                   |
|--------------------------|----------------------------------------------|-------------------------------------|
| 来源                     | 平台自带，随部署自动创建                     | 用户在「数据源」页面手动添加        |
| 在「数据源」页面是否出现 | 不出现                                       | 出现，可进行连接测试、编辑、删除    |
| 在「元数据管理」是否出现 | **默认存在**，节点名为「Doris（内置）」      | 只有创建采集任务并执行后才出现      |
| 元数据来源               | 批量同步任务写入表时自动注册，不需要采集任务 | 通过元数据采集任务从外部 Doris 拉取 |
| 写入方式                 | 批量同步任务以 Addax Stream Load 写入        | 不写入（外部数据源只读连接）        |
| 可添加/删除/编辑         | 不可删除，不可编辑连接信息                   | 可由工程师增删改                    |

**内置 Doris 在元数据管理中的表现**：

```
📋 元数据管理（左侧树）
├── 🏠 Doris（内置）               ← 平台自带，默认存在，始终置顶
│   ├── ods                        ← 同步任务的目标库（库名可自定义）
│   │   ├── orders                 ← 同步完成后自动注册
│   │   └── products               ← 同步完成后自动注册
│   └── dwd                        ← 同步任务的目标库（库名可自定义）
│       └── orders_log             ← 同步完成后自动注册
├── 📦 order_db                    ← 外部 MySQL（用户添加 + 采集任务采集）
│   └── production
│       ├── users
│       └── orders
└── 📦 doris_olap                  ← 外部 Doris（用户手动添加 + 采集任务采集）
    └── db01
        └── analytics_table
```

**关键行为**：

- 内置 Doris 的元数据 **不在 Sprint 1 的采集任务范围之内**。采集任务只采集外部数据源。内置 Doris 的元数据由 Sprint 2
  的同步任务在写入成功后自动注册。
- 内置 Doris 中的库由用户在创建同步任务时指定（见 5.2.2「目标 Doris 库」字段），支持从已有库中选择或手动输入新建。
- 用户在「元数据管理」中可以浏览内置 Doris 的表结构、查看字段详情、编辑注释，与浏览外部数据源的表体验一致。

## 2. 目标

| #   | 目标                                       | 验收标准                                                                                            |

**列表字段说明**：

| 字段         | 说明                                                                                                                               |
|--------------|------------------------------------------------------------------------------------------------------------------------------------|
| 任务名称     | 用户自定义，全局唯一                                                                                                               |
| 触发方式     | 手动 / 定时（Cron）                                                                                                                |
| 调度状态     | 仅定时任务展示：已启用（调度生效中）/ 已停用（用户关闭了调度）/ —（手动任务无此列）。通过操作区的「停用调度」/「启用调度」按钮切换 |
| 下次执行时间 | 仅定时任务展示：根据 Cron 表达式动态计算的下一次触发时间；手动任务显示「—」；已暂停的任务显示「已暂停」                            |
| 源 → 目标    | 格式「数据源.库/表 → Doris 库.目标表」                                                                                             |
| 同步模式     | 全量 / 增量（显示增量字段名）                                                                                                      |
| 状态         | 成功 / 未执行 / 失败 / 运行中                                                                                                      |
| 最近执行     | 最近一次执行时间，从未执行显示「—」                                                                                                |
| 操作         | 执行 / 编辑 / 删除 / 历史；定时任务额外显示「停用调度」或「启用调度」                                                              |

**状态说明**：

| 状态   | 含义                                   |
|--------|----------------------------------------|
| 运行中 | 正在执行同步                           |
| 成功   | 最近一次执行成功                       |
| 失败   | 最近一次执行失败（含重试耗尽后仍失败） |
| 未执行 | 创建后从未执行                         |

**筛选说明**：

- 「全部状态」下拉选项：运行中、成功、失败、未执行
- 「全部触发方式」下拉选项：手动、定时
- 搜索支持按任务名称模糊匹配
- 默认每页 20 条，支持切换 10/20/50

**操作按钮**：

- 「执行」：触发一次同步执行
- 「编辑」：进入编辑弹窗
- 「删除」：弹出二次确认
- 「历史」：进入该任务的历史记录页

#### 5.2.5 执行任务

- 成功：系统自动将目标 Doris 表的字段结构注册到「元数据管理」模块中。Doris 作为 DataNest

**停用与启用调度**：

- 仅定时任务在列表中显示「停用调度」/「启用调度」按钮。点击后切换调度开关状态，调度状态随之在「已启用」和「已停用」之间切换。

### 5.5 失败重试与告警

#### 5.5.1 失败重试

- 重试次数和间隔在创建/编辑任务时配置（见 5.2.2）
- 重试逻辑：第一次执行失败 → 等待重试间隔 → 第二次执行 → … → 全部重试耗尽 → 任务状态标记为「失败」
- 重试期间任务状态保持「运行中」，列表中显示当前重试次数
- 任何一次重试成功，任务状态变为「成功」，后续不再重试
- 若用户手动点击「执行」触发了新执行，重试计数重置

#### 5.5.2 告警通知

- 同步任务所有重试耗尽后仍失败时，发送告警通知
- 通知渠道由系统级配置决定（不在 PRD 中指定具体渠道）
- 告警内容包含：任务名称、源表、目标表、失败时间、错误摘要

## 7. 验收标准

### 7.1 功能验收

| #     | 验收项                | 通过标准                                                                                                                |
|-------|-----------------------|-------------------------------------------------------------------------------------------------------------------------|
| AC-1  | 创建全量同步任务      | 选择 MySQL 源表 → Doris 目标表，字段自动映射，保存后任务列表出现该任务                                                  |
| AC-2  | 手动执行全量同步      | 点击执行 → 状态变为运行中 → 同步完成 → 状态变为成功，数据写入 Doris 目标表                                              |
| AC-3  | 增量同步              | 配置增量字段为 updated_at，首次执行全量，第二次仅同步新增/修改行                                                        |
| AC-4  | 定时同步              | 配置 Cron 表达式后到达指定时间自动执行                                                                                  |
| AC-5  | 同步后自动注册元数据  | 同步成功 → 元数据管理页中「Doris（内置）」节点下自动出现新表，无需额外采集                                              |
| AC-6  | 失败自动重试          | 配置重试 3 次、间隔 1 分钟；人为使任务失败 → 自动重试 3 次 → 状态仍为失败                                               |
| AC-7  | 重试成功后停止        | 配置重试 3 次，第 2 次重试成功 → 状态变为成功，不再执行第 3 次                                                          |
| AC-8  | 失败告警通知          | 任务所有重试耗尽后仍失败 → 系统发送告警通知                                                                             |
| AC-9  | 数据预览 — 数据源     | 点击数据源列表「预览」→ 左侧显示库/Schema 树 → 点击表名 → 右侧展示前 100 行                                             |
| AC-10 | 数据预览 — 元数据管理 | 在元数据管理表详情页点击「预览数据」→ 弹出该表前 100 行                                                                 |
| AC-11 | 保存后自动采集        | 新增数据源时勾选「保存后立即采集元数据」→ 保存 → 采集任务列表出现自动创建的任务 → 任务执行完成 → 元数据管理页出现对应表 |
| AC-12 | 新建命名规范          | 填写规范名、选表/字段、选匹配方式、填规范值，保存后规范列表出现该项                                                     |
| AC-13 | 新建字段类型标准      | 填写标准类型名、标准数据类型，保存后类型标准列表出现该项                                                                |
| AC-14 | 合规检查              | 配置命名规范和字段类型标准后，点击合规检查 → 选择检查范围 → 查看不合规项列表                                            |
| AC-15 | 检查结果跳转          | 点击不合规项「查看」→ 跳转到元数据管理页中对应表/字段详情                                                               |
| AC-16 | 权限隔离              | 治理员看不到「批量数据同步」菜单；分析师看不到「数据标准」菜单；工程师看不到「数据标准」菜单                            |

## 8. 风险与对策

| #  | 风险                                     | 影响                                    | 对策                                                                |
|----|------------------------------------------|-----------------------------------------|---------------------------------------------------------------------|
| R1 | Addax 写 Doris 的 Stream Load 配置复杂   | 用户需要了解 Doris FE/BE 地址和导入参数 | 产品层封装 Doris 连接信息，用户只需选择目标库和填表名               |
| R2 | 增量字段配置错误（如选了没有索引的字段） | 增量同步性能极差                        | 下拉列表中标红不推荐的字段类型（如 varchar），并提供字段说明        |
| R3 | 同步过程中源表结构变更                   | 字段映射失效，同步失败                  | 执行时先校验源表字段，与任务配置映射不一致时给出明确提示            |
| R4 | 同步数据量过大导致 Doris 写入压力        | Doris BE 节点 OOM                       | 单任务一次同步上限为 1000 万行，超阈值提示用户分批（Sprint 3 优化） |
| R5 | 命名规范与正则表达式配置门槛高           | 治理员配错正则导致误报                  | 正则匹配方式旁边提供常用示例（如 `^ods_.*$`）                       |
