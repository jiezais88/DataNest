### 0.5 造数 SQL（已执行，当前环境已带脏数据）

> **当前环境已插入 2 条脏数据**（见下方 A/B），你直接跑检查就能看到「严重」档；不想看严重档可先清理（见 D）。

```sql
-- A. orders 造 1 条金额为负的脏数据 → 自定义SQL「异常金额」检查变「严重」（当前环境【已插入】 id=99）
INSERT INTO orders (id,user_id,order_no,total_amount,status) VALUES (99,1,'O202607290099',-50,'PAID');
-- B. orders 造 1 条 status 为 NULL 的脏数据 → 完整性（按 status 字段）非空率>0 → 警告/严重（当前环境【已插入】 id=97）
INSERT INTO orders (id,user_id,order_no,total_amount,status) VALUES (97,1,'O202607290097',200,NULL);
-- C. 注意：order_no 有 UNIQUE+NOT NULL 约束，无法造「唯一性违规」（会撞唯一索引）。
--    唯一性检查 COUNT(*)-COUNT(DISTINCT order_no) 在数据正常时恒为 0 → 恒「通过」。用它验证「通过/不告警」场景。
-- D. 清理造数（回归到干净数据，所有检查恢复「通过」）
DELETE FROM orders WHERE id IN (97,99);
```

## 六、标准合规

> 入口：`数据治理 → 标准合规`（`/governance/compliance`）。命名规范/字段类型标准入口：`数据治理 → 数据标准`（`/governance/data-standards`）。
> **合规数据源用**：`mysql`（testdb）。

### 6.1 立即扫描 + 三格统计 + 清单

- **前置**：先建好命名规范 + 字段类型标准（见下方 6.1A/6.1B 填表数据），让扫描能产出不合规项
- **填表数据（6.1A 新增字段类型标准）**：
    - 标准名称 `*`：`BIGINT 主键标准`
    - 分类：选 **数值**
    - 允许的字段类型 `*`：点选 **BIGINT**、**INT**
    - 描述（可选）：`主键字段专用标准`
- **填表数据（6.1B 新增命名规范·字段名）**：
    - 规范名称 `*`：`ID 字段命名规范`
    - 适用对象：选 **字段名**
    - 规则类型：选 **后缀**
    - 规则值 `*`：`_id`
    - 关联字段类型标准 `*`：选 6.1A 建的 `BIGINT 主键标准`
    - 优先级：`1`
- **操作步骤**：
    1. 进「数据标准」，按 6.1A 建字段类型标准，按 6.1B 建命名规范
    2. 进标准合规页，选合规数据源 `mysql`
    3. 点「立即扫描」，勾选检查数据源与检查项目（命名规范+字段类型标准），开始扫描

- **验收标准**：
    - [ ] 扫描完成弹窗关闭、列表刷新
    - [ ] 三格统计：不合规项 / 已忽略 / 合规率
    - [ ] 列表展示对象路径、对象类型（表名/字段名）、违规类型徽章（命名规范=黄、字段类型=红）、标准要求、实际值、忽略状态
    - [ ] 不选数据源时提示「请选择检查数据源」

> **预期不合规项**：`orders` 表字段 `id/order_id/product_id/user_id` 等以 `_id` 结尾但类型不全是 BIGINT/INT 的（如 `order_id` 是 bigint 合规，但可看到非主键/类型不符的字段），以及 `my_users` 空表字段。正常会扫出若干条「命名规范」和「字段类型」违规。

### 6.2 筛选：数据源 / 违规类型 / 忽略状态

## 七、分级邮件告警

> 入口：`系统管理 → 告警中心`（`/system/alert-center`）+ 数据治理质量任务。邮件查看：MailHog http://localhost:8025
> **接收用户固定选**：`admin`（admin@datanest.io）

### 7.1 创建 QUALITY 告警规则

- **填表数据（新增告警规则）**：
    - 规则名称 `*`：`质量任务失败告警`
    - 对象类型 `*`：选 **质量任务**
    - 对象 `*`：搜索并选择任务① `核心业务表完整性检查`
    - 触发条件 `*`：勾选 **失败**（默认）
    - 接收用户 `*`：选择 `admin`
    - 启用告警规则：开启
- **操作步骤**：
    1. 告警中心 → 新增告警规则，按上面数据填，保存
- **验收标准**：
    - [ ] 对象类型下拉有「质量任务」，对象可搜索选择
    - [ ] 保存后规则出现在列表，对象类型徽章「质量任务」

### 7.2 分级判定 + 合并邮件

- **前置**：为任务①建一条「严重」规则 + 一条「警告」规则（阈值设置见 §3.1），任务①告警触发等级=严重 + 警告
- **操作步骤**：
    1. 质量任务页点任务①「执行」
    2. 查看 MailHog 与告警历史
- **验收标准**：
    - [ ] 检查历史明细：严重规则「严重」、警告规则「警告」
    - [ ] 合并一封邮件，主题含「质量任务『核心业务表完整性检查』执行失败（2 项）」，正文含「[严重]」「[警告]」「共 2 项」
    - [ ] 告警历史写入 2 条，发送状态「发送成功」

> **实现提示**：当前环境已按 §0.5 造数（id=99 金额-50、id=97 status=NULL），按 §3.1 建 3 规则后直接执行任务①即可看到分级：自定义SQL「异常金额」=**严重**、完整性「订单状态」=**警告**、唯一性=通过。合并邮件应含「[严重]」「[警告]」共 2 项。

### 7.3 告警幂等 + 负向场景

- **操作步骤**：
    1. 防重窗口内再次执行任务①，查看告警历史
    2. 执行「SQL 失败」任务（→不可用）
    3. 执行「阈值内通过」任务（→通过）
    4. 执行 SEVERE_ONLY 任务（含严重+警告规则，任务②）
- **验收标准**：
    - [ ] 重复执行不新增告警历史（幂等）
    - [ ] 「不可用」「通过」不产生告警（防误报）
    - [ ] SEVERE_ONLY 只对严重规则告警，警告被排除，邮件仅含「[严重]」无「[警告]」

> **实现提示**：「SQL 失败」可对 `my_users` 空表建一条引用不存在字段的规则触发「不可用」；「通过」为不造数时的全通过任务。

### 7.4 告警中心历史页 QUALITY 记录 + 检查历史分级徽章

- **操作步骤**：
    1. 告警中心「告警历史」Tab，对象类型选「质量任务」点查询
    2. 质量检查历史查看任务①批次详情
- **验收标准**：
    - [ ] 告警历史展示该任务记录，对象类型徽章「质量任务」、发送「发送成功」
    - [ ] 检查历史明细严重规则「严重」徽章、警告规则「警告」徽章

## 执行建议

1. **环境**：前端 `http://localhost:3000`，网关 `http://localhost:8080/api`；XXL-JOB Admin `http://localhost:8088`（admin/123456）；MailHog `http://localhost:8025`（收告警邮件，清空用 `DELETE http://localhost:8025/api/v1/messages`）；质量执行依赖真实数据源 `mysql` + app-worker 执行节点。

2. **执行顺序**（推荐按数据流）：
   - 规则模板库 → 质量任务/规则（配置层）
   - 质量检查历史（执行层，含手动/定时/自动三种触发）
   - 表级质量评分 → 血缘质量徽章（评分联动）
   - 标准合规（独立）
   - 分级邮件告警（收尾联动）

3. **填表数据速查（本环境真实值）**：
   - 数据源：一律选 `mysql`（testdb）
   - 目标表：`orders`（订单主表）/ `order_items` / `products` / `users` / `my_users`（空表）
   - 完整性（按字段）：模板选**完整性检查**，检查字段选 `status`，阈值 `0.1/0.2`（当前 null_rate≈0.17 → 警告）
   - 唯一性：模板选**唯一性检查**，检查字段选 `orders.order_no`，阈值 `0.1/0.3`
   - 自定义 SQL：`SELECT COUNT(*) AS bad_cnt FROM {table} WHERE total_amount < 0`，阈值 `0.01/0.05`（命中金额<0 → 严重）
   - 告警接收用户：`admin`
   - 造数（要跑「严重」档时）：见 §0.5，对 testdb 执行 INSERT/DELETE

4. **重点回归**：
   - 检查历史判定徽章：**「不可用」灰色不要误读为成功**
   - 定时触发落库触发方式应为「定时」非「手动」
   - UNAVAILABLE / PASS 不触发告警（防误报）
   - 严重规则强制压至低分区
