## 一、规则模板库

> 入口：`数据治理 → 规则模板库`（`/governance/quality-templates`）

### 1.1 页面加载 + 内置模板

- **操作步骤**：
    1. admin 登录 → 数据治理 → 规则模板库
- **验收标准**：
    - [ ] 标题「规则模板库」，统计卡片（模板总数/内置/自定义）
    - [ ] 表格展示四类内置模板（完整性/唯一性/值域范围/自定义 SQL），来源徽章「内置」

### 1.2 新增 + 编辑 + 启停自定义模板

- **操作步骤**：
    1. 新增自定义模板：填名称、选类型、填结果指标与 SQL 模板，勾选启用，保存
    2. 编辑该模板名称，保存
    3. 停用该模板，再启用
- **验收标准**：
    - [ ] 新增后列表出现，来源「自定义」、状态「启用」
    - [ ] 编辑后列表刷新为新名称
    - [ ] 停用后状态「停用」，启用后恢复

### 1.3 删除自定义模板 + 内置不可删

- **操作步骤**：
    1. 删除一个自定义模板（确认弹窗）
    2. 查看「完整性检查」内置模板操作列
- **验收标准**：
    - [ ] 自定义模板删除后消失
    - [ ] 内置模板无删除按钮

### 1.4 模板批量应用（联动质量规则）

- **操作步骤**：
    1. 进入质量规则页，选某任务，点「模板批量应用」
    2. 选模板（如完整性检查）+ 选一张表，点「生成规则」
- **验收标准**：
    - [ ] 规则列表出现按模板批量生成的规则
    - [ ] 同一模板+同一表重复应用不重复建（幂等）

## 二、质量任务

> 入口：`数据治理 → 质量任务`（`/governance/data-quality`）

### 2.1 新增质量任务（三种触发配置）

- **操作步骤**：
    1. 新增任务：填名称 + 选数据源范围，保存
    2. 再新增：勾选「定时调度」填 Cron `0 0 2 * * ?`，保存
    3. 再新增：勾选「自动触发」绑定对象类型=同步任务并选具体任务，保存
- **验收标准**：
    - [ ] 基础任务保存后列表出现，状态「启用」
    - [ ] 定时任务 Cron 列展示，调度状态、下次执行时间正常
    - [ ] 自动触发任务「自动触发」列展示「同步任务」
    - [ ] 勾选定时但不填 Cron 时提示「开启定时调度时请输入 Cron 表达式」

### 2.2 开启定时调度（XXL-JOB 注册）

- **操作步骤**：
    1. 为带 Cron 的任务点「开启定时调度」
    2. 打开 XXL-JOB Admin（http://localhost:8088），查看 executor 组下新增了该任务
    3. 在 XXL-JOB Admin 对该任务执行「执行一次」（trigger）
    4. 回质量检查历史页查看批次
- **验收标准**：
    - [ ] 开启调度后 XXL-JOB Admin 出现该质量任务的调度任务
    - [ ] trigger 后质量检查历史出现**触发方式=定时**的批次
    - [ ] 关闭调度后批次不再自动产生

### 2.3 编辑 / 详情 / 启停任务

- **操作步骤**：
    1. 任务行点「详情」查看只读信息
    2. 点「编辑」改名称保存
    3. 点「停用」再「启用」
- **验收标准**：
    - [ ] 详情抽屉只读（无保存按钮，名称禁用）
    - [ ] 编辑后列表刷新
    - [ ] 停用/启用状态徽章正确切换

### 2.4 删除任务（含告警引用保护）

- **操作步骤**：
    1. 删除一个未被引用的任务（确认弹窗）
    2. 先在某任务上建 QUALITY 告警规则，再尝试删除该任务
- **验收标准**：
    - [ ] 未引用任务删除后消失
    - [ ] 被引用任务删除被阻断，提示并列出引用它的告警规则名

### 2.5 筛选：关键字 / 状态

- **操作步骤**：
    1. 搜索框输入任务名关键字，点查询
    2. 状态筛选举「停用」，点查询
- **验收标准**：
    - [ ] 关键字筛选正确
    - [ ] 状态=停用 时仅显示停用任务
    - [ ] 重置恢复全部

## 三、质量规则

> 入口：`数据治理 → 质量规则`（`/governance/quality-rules`）

### 3.1 新增规则（三类）

- **操作步骤**：
    1. 新增「完整性」规则：选表 + 阈值（警告 0.5/严重 0.8），保存
    2. 新增「唯一性」规则：选字段（如 id）+ 阈值，保存
    3. 新增「自定义 SQL」规则：填 `SELECT COUNT(*) AS total FROM 表`，保存
- **验收标准**：
    - [ ] 三种类型徽章正确（完整性/唯一性/自定义 SQL）
    - [ ] 完整性整表规则「检查字段」列显示「整表」；唯一性显示所选字段
    - [ ] 阈值列展示正确

### 3.2 预览 SQL

- **操作步骤**：
    1. 在自定义 SQL 规则行点「预览 SQL」
- **验收标准**：
    - [ ] 弹窗「规则执行 SQL 预览」展示实际执行 SQL

### 3.3 编辑 / 启停 / 删除规则

- **操作步骤**：
    1. 编辑规则名称保存
    2. 停用再启用
    3. 删除（确认弹窗）
- **验收标准**：
    - [ ] 编辑后列表刷新
    - [ ] 停用/启用状态正确
    - [ ] 删除后消失

### 3.4 筛选：关键字 / 类型 / 状态 / 所属任务

- **操作步骤**：
    1. 分别按类型、状态、所属任务筛选，点查询
- **验收标准**：
    - [ ] 各筛选正确，重置恢复全部

## 四、质量检查历史

> 入口：`数据治理 → 质量检查历史`（`/governance/quality-checks`）

### 4.1 手动执行任务 → 批次落库 + 分级明细

- **操作步骤**：
    1. 在质量任务页点某任务「执行」
    2. 进质量检查历史页，触发方式选「手动」点查询
    3. 点该批次「查看明细」
- **验收标准**：
    - [ ] 出现该任务批次，触发方式「手动」
    - [ ] 批次状态正确（含成功+失败规则=部分失败）
    - [ ] 明细「批次概览」字段完整
    - [ ] **规则明细分级徽章正确**：通过=「通过」(绿)、警告=「警告」(黄)、严重=「严重」(红)、SQL 失败=「不可用」(灰)——**灰色「不可用」不要误读为成功**
    - [ ] 成功规则展示结果值；失败规则展示错误信息，可展开「执行 SQL」

### 4.2 单规则执行 → 独立批次

- **操作步骤**：
    1. 在质量规则页点某规则「执行」
    2. 回质量检查历史页刷新
- **验收标准**：
    - [ ] 出现任务名「单规则执行」的批次，状态正确（成功/失败）

### 4.3 筛选：触发方式 / 状态 / 时间

- **操作步骤**：
    1. 分别按触发方式、批次状态筛选，点查询
    2. 用时间范围控件
- **验收标准**：
    - [ ] 各筛选正确
    - [ ] 清空时间范围时提示「请选择执行时间范围」

### 4.4 自动触发链路（同步任务成功触发质量任务）

- **操作步骤**：
    1. 新建同步任务（含绑定该质量任务的自动触发配置）
    2. 执行同步任务使其成功
    3. 回质量检查历史，触发方式选「自动触发」
- **验收标准**：
    - [ ] 出现该质量任务的批次，触发方式「自动触发」

## 七、分级邮件告警

> 入口：`系统管理 → 告警中心`（`/system/alert-center`）+ 数据治理质量任务

### 7.1 创建 QUALITY 告警规则

- **操作步骤**：
    1. 告警中心 → 新增告警规则
    2. 对象类型选「质量任务」，选择具体质量任务，触发条件勾「失败」，选接收用户（需有邮箱），保存
- **验收标准**：
    - [ ] 对象类型下拉有「质量任务」，对象可搜索选择
    - [ ] 保存后规则出现在列表，对象类型徽章「质量任务」

### 7.2 分级判定 + 合并邮件

- **操作步骤**：
    1. 配置 SEVERE_WARNING 任务（含一条严重规则 + 一条警告规则）
    2. 质量任务页点「执行」
    3. 查看 MailHog 与告警历史
- **验收标准**：
    - [ ] 检查历史明细：严重规则「严重」、警告规则「警告」
    - [ ] 合并一封邮件，主题含「质量任务『名称』执行失败（2 项）」，正文含「[严重]」「[警告]」「共 2 项」
    - [ ] 告警历史写入 2 条，发送状态「发送成功」

### 7.3 告警幂等 + 负向场景

- **操作步骤**：
    1. 防重窗口内再次执行主链路任务，查看告警历史
    2. 执行「SQL 失败」任务（→不可用）
    3. 执行「阈值内通过」任务（→通过）
    4. 执行 SEVERE_ONLY 任务（含严重+警告规则）
- **验收标准**：
    - [ ] 重复执行不新增告警历史（幂等）
    - [ ] 「不可用」「通过」不产生告警（防误报）
    - [ ] SEVERE_ONLY 只对严重规则告警，警告被排除，邮件仅含「[严重]」无「[警告]」

### 7.4 告警中心历史页 QUALITY 记录 + 检查历史分级徽章

- **操作步骤**：
    1. 告警中心「告警历史」Tab，对象类型选「质量任务」点查询
    2. 质量检查历史查看主链路任务批次详情
- **验收标准**：
    - [ ] 告警历史展示该任务记录，对象类型徽章「质量任务」、发送「发送成功」
    - [ ] 检查历史明细严重规则「严重」徽章、警告规则「警告」徽章

## 执行建议

1. **环境**：前端 `http://localhost:3000`，网关 `http://localhost:8080/api`；XXL-JOB Admin `http://localhost:8088`（admin/123456）；MailHog 查看告警邮件；质量执行依赖真实数据源 + app-worker 执行节点。

2. **执行顺序**（推荐按数据流）：
   - 规则模板库 → 质量任务/规则（配置层）
   - 质量检查历史（执行层，含手动/定时/自动三种触发）
   - 表级质量评分 → 血缘质量徽章（评分联动）
   - 标准合规（独立）
   - 分级邮件告警（收尾联动）

3. **重点回归**：
   - 检查历史判定徽章：**「不可用」灰色不要误读为成功**
   - 定时触发落库触发方式应为「定时」非「手动」
   - UNAVAILABLE / PASS 不触发告警（防误报）
   - 严重规则强制压至低分区
