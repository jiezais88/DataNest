# Sprint 6：数据质量管理 PRD

> **版本**：v1.1 | **日期**：2026-08-04 | **作者**：产品通
>
> **Sprint 目标**：让治理管理员能够为元数据目录中的表配置质量规则，用真实数据执行校验，按「通过 / 警告 /
> 严重」分级并邮件告警，产出表级质量评分并联动血缘展示，同时自动扫描不符合数据标准的表和字段，让数据「可信、可控、可考核」。

## 1. 问题陈述

### 1.1 为什么 Sprint 6 做这件事

Sprint 5 把数据血缘「看得见」了，治理管理员能知道数据从哪来、往哪去。但数据的 **可信度**
还是空白：一张表里的空值率是多少？主键是否唯一？金额字段是否超出合理范围？——当前只能靠人肉写 SQL
查，没有统一的规则配置、没有分级、没有告警、没有持续的趋势。

同时，Sprint 2 已交付了 **数据标准**（命名规范、字段类型规范），但只做到了「定义」，没有「执行」——标准与实际的表和字段之间有没有偏差，全靠人工比对，没有自动扫描。

规格文档 v2.0 的数据质量管理模块（DG-04/05/07/08）正是为此设计：规则配置、监控告警、质量报告、标准合规。Sprint 5 的非目标也明确把
NG7（自动根据血缘推荐质量规则）、NG8（血缘与数据质量评分联动）指向本期。

所以 Sprint 6 的核心命题是： **让数据质量管得住、看得见、算得出分、联得上血缘、对得上标准**。

### 1.2 当前用户怎么做的（痛点）

| 现在                                                     | Sprint 6 之后                                                    |
|----------------------------------------------------------|------------------------------------------------------------------|
| 治理员要手写 SQL 到源库/Doris 查空值率、唯一性，重复劳动 | 在「数据质量」页配置规则模板，一键对多表批量应用，点「立即执行」 |
| 质量异常没人知道，用数时才发现                           | 检查结果分级，严重/警告自动邮件告警                              |
| 不知道某张表整体健康度，审计时拿不出数据                 | 每张表产出 0-100 质量评分，元数据详情页与血缘图谱节点直接展示    |
| 标准只定义了但没落地，不知道哪些表和字段不合规           | 标准合规检查自动扫描并标记不符合命名/字段类型规范的表和字段      |
| 质量是「一次性抽查」，没有趋势                           | 每次检查结果落库，趋势图展示质量随时间变化                       |

### 1.3 Sprint 6 要达到的状态

> 治理管理员进入「数据治理 → 数据质量」→ 创建「dwd 核心质检」质量任务，为该任务下 `dwd.orders` 配置「完整性：amount 非空率 ≥
> 99%」「唯一性：order_id 唯一」两条规则 → 点击「立即执行」→ 平台在目标 Doris 上真实执行聚合 SQL，统计出 `amount` 空值率
> 1.2%（警告）、`order_id` 重复 0 条（通过）。
>
> 该任务挂了定时调度（统一 cron），每天 02:00 自动检查；某次检查 `amount` 空值率升到
> 3.5%（严重），平台自动向接收用户发邮件告警，并在元数据详情页与血缘图谱节点标红该表。
>
> 治理员进入「标准合规检查」，看到 `ods.orders` 的表名不符合「ods_ 前缀 + 下划线」规范、`ods.userName`
> 字段名用了驼峰而非下划线，一键标记并导出问题清单。

**规则字段说明**：

| 字段          | 必填 | 说明                                                                  |
|---------------|------|-----------------------------------------------------------------------|
| 规则名称      | ✅   | 任务内唯一标识规则                                                    |
| 规则类型      | ✅   | 完整性 / 唯一性 / 值域范围 / 自定义 SQL（可选自模板）                 |
| 选择表        | ✅   | 从元数据目录选择表，自动带出其所属数据源（校验在真实数据源上执行）    |
| 检查字段      | 条件 | 唯一性/值域范围必填；完整性**可选**（不填则统计整表空值率，口径见下） |
| 警告/严重阈值 | ✅   | 判定为警告/严重的结果阈值，执行结果超过阈值即对应分级                 |
| 权重          | —    | 默认 1，用于评分加权                                                  |
| 启用状态      | —    | 默认启用                                                              |

**批量应用（模板库）**：任务内「模板批量应用」→ 选择 **一个规则模板** + **多张表** → 为每张表生成独立规则实例，可单独编辑/停用/执行（对应
D3，引入 `quality_rule_template`）。

**四类规则模板**：

| 类型       | 校验 SQL 逻辑                           | 示例                                                       |
|------------|-----------------------------------------|------------------------------------------------------------|
| 完整性     | 空值率 = NULL/空值行数 / 总行数         | 检查 `amount` 空值率 ≤ 1%                                  |
| 唯一性     | 重复行数 = COUNT - COUNT(DISTINCT 字段) | 检查 `order_id` 重复数 = 0                                 |
| 值域范围   | 越界行数 = 字段值超出 [min,max] 的行数  | 检查 `amount` 越界率 = 0（0 ≤ 值 ≤ 100000）                |
| 自定义 SQL | 用户自定义返回单个统计值的 SQL          | `SELECT COUNT(*) FROM ... WHERE 波动率 > 10%` 返回越界行数 |

> **整表空值率口径（完整性不填字段时）**：空值行占比 = 存在 **至少一个 NULL/空值字段**的行数 ÷
> 总行数，即「这张表里有多少比例的记录不完整」。完整性填写字段时，则统计该字段的空值行占比，口径一致。
>
> **实现注记**：所有校验 SQL 均采用 **聚合写法**（`COUNT(*)`、`COUNT(DISTINCT ...)` 等）返回单行结果，以规避平台
> `GenericSqlExecutor` 的结果集截断（200 行）与 5 秒查询超时限制；校验在规则所挂表的 **数据源**（`datasource_connection`
> ）上真实执行。

### 6.3 质量检查执行

#### 6.3.1 执行时机

| 触发方式         | 说明                                                                                                                                   |
|------------------|----------------------------------------------------------------------------------------------------------------------------------------|
| 手动触发         | 任务列表/规则列表点「执行」或「批量执行」，立即创建一次检查批次（手动为默认能力，始终可用）                                            |
| 定时调度         | **每个质量任务统一配置 Cron**，任务下所有规则跟随；仿既有 XXL-JOB handler，新增 `qualityCheckHandler` 每分钟扫描到期的任务 cron 并执行 |
| 任务完成自动触发 | 任务**绑定到具体任务**（DAG 节点或同步任务），该任务执行完成后自动触发本任务全部规则检查                                               |

> 三种时机可叠加：手动始终可用；定时与任务完成自动触发为任务级可选能力（可同时开启）。同一任务在防重窗口内的重复触发合并为一次检查。

### 6.4 质量告警

- **复用告警体系**：Sprint 5 的 `alert_rule` / `alert_history` 全链路复用，仅需扩展新的对象类型 `QUALITY`（ **对象 =
  质量任务**，即 `object_id` 为任务 ID），并支持 `alert_type=FAILURE`（质量异常）的告警。
- **触发等级（可开关）**：在 **任务级**配置「仅严重」或「严重 + 警告」两种触发等级，执行结果达到所选等级即触发邮件告警。
- **告警收敛（合并）**： **同一次检查批次**中多条规则/多张表同时达到触发等级时， **合并为一条邮件**（引入检查批次
  batchId），正文逐条列出所有异常项（规则名、对象表、执行结果、判定等级），避免告警轰炸。
- **告警内容**：邮件正文包含规则名称、对象表、执行结果值、判定等级、检查时间、跳转链接。
- **接收用户**：在告警规则中按既有流程选择接收用户（取平台用户邮箱）。
- **入口**：「系统管理 → 告警中心」新增对象类型「质量」的规则配置；质量任务编辑处也可直接配置告警（两入口同源同步）。

```

│  对象类型 *                                                   │
│  [质量 ▼]                                                     │
│  对象 *                                                       │
│  [请选择质量任务 ▼]  已选：dwd 核心质检                       │
│  触发条件 *                                                   │
│  ● 仅严重   ○ 严重 + 警告                                     │
│  接收用户 *                                                   │
│  [请选择用户 ▼]  已选：张三、李四                              │
│  启用状态                                                     │
│  [☑ 启用]                                                     │
│                    [取消]  [保存]                              │
└───────────────────────────────────────────────────────────────┘
```

### 6.5 表级质量评分与血缘联动

#### 6.5.1 质量评分

- 每张表综合其 **最近一次**所有启用规则检查结果，产出 0-100 分。
- **规则权重**：每条规则可配置权重（如 `amount` 非空率权重 3、`order_id` 唯一权重 1），评分按权重加权，反映规则对业务的重要性。
- **算法（加权）**：
    1. 基础分 = 100 ×（通过规则的权重之和 ÷ 全部启用规则权重之和）。
    2. 警告规则、严重规则分别按权重折算扣分。
    3. 扣分分值为 **全局可配置项**（治理员可在设置中调整，如警告扣分 / 严重扣分 / 低分区阈值），无需改代码。
    4. 最终分 = 基础分 − 警告扣分 − 严重扣分，取 0-100；存在严重规则时强制压至低分区并标记健康度「差」。

    - 示例：表挂 2 条规则，`amount 非空率`（权重 3）通过、`order_id 唯一`（权重 1）警告 → 基础分 = 100× (3/4) = 75，扣警告分（假设
      -10）= 65 分。

> 评分算法、权重、扣分分值均文档化并作为配置暴露，避免"黑盒"造成评分失真（见 R3）。

#### 6.5.3 血缘图谱节点联动

- 表级血缘图谱（Sprint 5 `LineageGraphPage`）中， **所有表节点**都在原有名称下方展示质量评分徽章（`qualityScore`
  ），背景色按健康度区间显示绿/黄/红，使质量覆盖度一目了然。
- **未配置任何质量规则的表**展示灰色「—」徽章，标识「暂无质量数据」，不阻塞血缘渲染，便于治理员识别待补规则的节点。

### 6.6 标准合规检查

#### 6.6.1 扫描入口

「数据治理 → 标准合规」进入，基于 Sprint 2 交付的数据标准（命名规范 + 字段类型规范）对元数据自动扫描：

```
┌─ 标准合规 ───────────────────────────────────────────────────┐
│                                                               │
│  [扫描结果] [规则模板]                                         │
│                                                               │
│  上次扫描：2026-08-04 02:00  [立即扫描]                        │
│                                                               │
│  ───────────── 不合规项 ─────────────                         │
│  类型    对象              标准要求                实际       状态   操作  │
│  表名    ods.orders        ods_ 前缀 + 下划线      orders    不合规 [查看][忽略]│
│  字段名  ods.userName      小写下划线               userName  不合规 [查看][忽略]│
│  字段类型 ods.amount       数值类型                VARCHAR   不合规 [查看][忽略]│
│                                                               │
│  [导出问题清单]                                                │
└───────────────────────────────────────────────────────────────┘
```

#### 6.6.2 交互规则

- 合规检查基于 **数据标准的分组与规则**（命名规范、字段类型规范）自动比对 `metadata_table` / `metadata_column`。
- 不合规项支持「查看」（跳转到对应表/字段详情）、「忽略」（标记后不再告警）。
- **忽略粒度**：按 **具体不合规项**忽略（如「`ods.userName` 字段名驼峰」这一条），不做整表/整规则粗粒度忽略。
- **取消忽略**：支持取消忽略，被忽略项可重新回到问题清单，误报可撤销。
- 支持「导出问题清单」（CSV）。
- 扫描结果可配置定时执行（复用 XXL-JOB handler），与质量检查共用调度基础设施。

### 6.7 质量报告（P1）

- 按**「单表 / 单库 / 按数据源」**三个维度生成质量报告（暂不含「项目」维度，因元数据表与项目无直接关联）。
- **报告周期**：支持自定义时间区间（默认最近 30 天）。
- 报告包含：表质量评分分布、规则通过率、检查结果趋势、问题清单（严重/警告规则及最近检查）。
- 支持导出 PDF/CSV，作为治理成效汇报材料。

| 删除对象          | 被谁引用                       | 处理方式                                                       |

| 数据标准分组/规则 | 标准合规检查结果               | 删除标准规则时级联删除对应合规检查结果                         |

> `QualityCheckHistoryCleanupHandler` 定时清理；删除质量规则时不级联删除历史。

## 10. 风险与对策

| #  | 风险                           | 影响           | 对策                                                                   |
|----|--------------------------------|----------------|------------------------------------------------------------------------|
| R1 | 校验 SQL 结果集过大/执行超时   | 校验失败或卡顿 | 校验统一采用聚合 SQL 返回单行结果，规避截断与 5 秒超时；失败跳过该规则 |
| R2 | 数据源不可用导致校验失败       | 检查结果缺失   | 数据源不可用时规则检查标记「不可用」，不产生误告警                     |
| R3 | 质量评分算法不合理导致误判     | 评分失真       | 评分算法文档化；权重、扣分分值均作为配置暴露，可调不需改代码           |
| R4 | 告警轰炸（质量反复严重）       | 收件人麻木     | 复用 60 秒防重 + 同次检查多条异常合并为一条邮件 + 可选「仅严重」       |
| R5 | 标准合规扫描误报               | 问题清单噪音   | 支持按具体项「忽略」，并支持取消忽略，误报可撤销                       |
| R6 | 任务完成自动触发与定时触发重叠 | 重复检查       | 同任务在防重窗口内的重复触发合并为一次检查                             |
