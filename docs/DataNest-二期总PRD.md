## 1. 二期定位与目标

### 1.1 定位

一期（Sprint 0~12）交付了**完整的一站式数据中台 MVP**——"建数据 → 管数据 → 用数据"七位一体闭环已打通并开源发布（v1.0.x）。
二期的定位是 **从"能用"走向"生产可用、可规模化"**：

> 一期证明 DataNest 能完成一条完整数据链路；二期要让这条链路**在真实的多团队、生产化、实时化场景下依然可靠、安全、可协同、可观测**。

### 1.2 二期总目标

| # | 目标 | 一句话 | 衡量标准 |
|---|------|--------|----------|
| P2-G1 | 企业级多租户 | 一个实例支撑多个组织/团队的数据隔离与自助使用 | 租户间数据/资源/配置严格隔离；新租户开通 < 10 分钟 |
| P2-G2 | 企业级认证与安全 | SSO 接入 + 数据安全（脱敏/加密/申请审批） | 支持主流身份协议；敏感数据查询可脱敏、访问需审批 |
| P2-G3 | 生产级可靠性 | 存储与关键链路具备冗余与恢复能力 | 核心存储副本可配；元数据可备份恢复 |
| P2-G4 | 实时计算产品化 | 用 SQL 编排流处理任务（窗口/CEP），复用 Flink | 流任务可视化创建→提交→监控闭环；延迟秒级 |
| P2-G5 | 实时治理一体化 | 流任务自动产出血缘 + 实时数据质量 | 流链路血缘自动生成；流数据质量可配置可告警 |
| P2-G6 | DataOps 工程效能 | 数据变更可版本化、可回滚、可审计、可观测 | 任务配置有版本对比与回滚；变更链路可追溯 |
| P2-G7 | 能力补全与体验 | 补齐一期 P1/P2 高频遗留项 | 一期遗留项按优先级收敛，无断档能力 |

### 1.3 二期非目标（明确不做）

| # | 非目标 | 原因 |
|---|--------|------|
| P2-NG1 | **AI 智能化**（text-to-SQL / 数据智能体 / 语义层 / AI 质量规则推荐 DG-11） | 用户拍板二期不做；依赖 LLM 接入与长期产品化，留待三期 |
| P2-NG2 | **BI 可视化 / 仪表盘自研** | 延续一期 NG1，社区有 Superset/Metabase 成熟方案 |
| P2-NG3 | **ML 模型训练平台** | 延续一期 NG2 |
| P2-NG4 | **字段级数据权限** | 延续 Sprint 11 N1，投入产出比低，机密字段拦截已覆盖 |
| P2-NG5 | **告警渠道扩展（钉钉/企微/Webhook）** | 已在一期取消（规格 §15.1），延续 |
| P2-NG6 | **自研流处理引擎** | 已拍板复用 Flink SQL，不自研 |

### 3.1 主线优先级与依赖

- **主线一（企业级）** 是二期**先行主线**：多租户是底座性改造，影响后续所有主线的数据隔离语义，必须先做。
- **主线二（实时深化）** 依赖 Sprint 8/9 的 CDC + 监控告警底座，与主线一解耦，可并行启动。
- **主线三（DataOps）** 依赖主线一（租户/环境隔离）与一期 DAG/版本底座，排在主线一之后。
- **主线四（补全遗留）** 是碎片项，穿插在各主线间、按优先级与用户价值随时插入，不占独立主 Sprint。

## 4. 主线一：企业级能力

> **用户价值**：让 DataNest 能被一个组织内的**多个团队**安全共享，能接入**企业统一身份**，能对**敏感数据**做访问控制，能保证**数据不丢**。
> 这是二期最重要的主线，解决"单实例 = 单团队"的生产落地瓶颈。

### 4.1 子模块 A：完整多租户（P0，二期核心）

> **决策**：用户拍板打破一期 NG3 非目标，做**完整多租户**（租户级数据/资源/配置隔离）。

**产品语义**：租户 = 一个独立使用 DataNest 的**组织/公司**（一个企业一个租户，组织内再按团队/角色划分）。租户之间的数据、数据源、任务、DAG、质量规则、告警配置、数据服务 API 等**全部资源**互不可见、互不可用。

**功能需求**：

| ID | 功能 | 描述 | 验收标准 |
|----|------|------|----------|
| MT-01 | 租户模型 | 平台存在多个租户；预置「默认租户」承接一期存量数据（升级无损） | 升级后现有数据全部归默认租户，行为不变 |
| MT-02 | 租户生命周期 | 超级管理员创建/编辑/启停租户（名称、描述、配额） | 停用租户后其用户不可登录/不可操作 |
| MT-03 | 数据隔离 | 所有业务资源（数据源/任务/DAG/元数据/质量/资产/数据 API）按租户过滤 | 租户 A 无法在任何接口/界面看到租户 B 的数据 |
| MT-04 | 用户与租户 | 单账号可加入多个租户，登录后切换当前租户；所有操作作用于当前租户 | 切换租户后仅能访问该租户的资源；跨租户数据严格隔离 |
| MT-05 | 租户级配额 | 租户可配置数据源数、任务数、存储量等配额上限 | 超配额时明确提示并阻止创建 |
| MT-06 | 跨租户审计 | 超管可跨租户查看审计日志与使用情况 | 审计记录带租户标识，可按租户筛选 |
| MT-07 | 租户内 RBAC | 租户内沿用一期三级数据权限 + 自定义角色，权限边界限定在本租户；**数据权限默认全量可见、按需收缩** | 租户管理员只能管理本租户的角色与权限 |

**关键设计约束**：
- 所有持库业务表加 `tenant_id`，数据访问层统一过滤（技术方案归各 Sprint 技术文档）。
- 单账号多租户：`sys_user` 与 `tenant` 多对多，登录后进入默认租户、可切换；租户上下文贯穿会话与请求。
- 租户内数据权限沿用一期**默认全量可见、按需收缩**策略（租户边界为硬隔离、租户内为软收缩）。
- 内置 Doris 数仓是共享引擎，需按库/目录做租户命名空间隔离（如租户专属 database），避免跨租户表访问。
- PowerJob、告警、数据服务等跨服务资源需带租户上下文透传。

### 4.2 子模块 B：SSO 身份接入（P0）

| ID | 功能 | 描述 | 验收标准 |
|----|------|------|----------|
| SSO-01 | OIDC/OAuth2 接入 | 对接主流身份提供商（Keycloak/Auth0/企业 OIDC），实现登录跳转与自动建号 | 配置后可从 IdP 登录，首次登录自动创建并绑定用户 |
| SSO-02 | LDAP/AD 接入 | 对接企业内部 LDAP/AD 目录 | 可按组织单元同步用户与角色映射 |
| SSO-03 | 角色映射 | IdP 的组/角色映射到 DataNest 角色与租户 | 映射规则可配置，登录后权限正确 |
| SSO-04 | 本地登录共存 | SSO 与本地账号密码登录可共存、可开关 | 可强制 SSO 或保留混合登录 |
| SSO-05 | 密码策略强化 | 密码复杂度、过期、登录失败锁定（一期 UM-07） | 策略可配置，锁定阈值生效 |

### 4.3 子模块 C：高可用与数据可靠性（P1）

| ID | 功能 | 描述 | 验收标准 |
|----|------|------|----------|
| HA-01 | Doris 多副本 | 表副本因子可配，节点故障数据不丢（SE-09） | 副本数 > 1 时单节点故障查询不受影响 |
| HA-02 | 元数据备份恢复 | 业务库（PG）定期备份与恢复演练 | 可按备份恢复至历史时点 |
| HA-03 | 关键配置备份 | Nacos 配置、Doris 元数据备份 | 配置可恢复 |
| HA-04 | 服务健康自愈 | 服务异常退出的自动重启与探活 | 关键服务故障后可自愈 |

> **说明**：一期为单机 Docker Compose 部署，二期"高可用"定位为**数据可靠性与可恢复性**（副本 + 备份），而非分布式多节点水平扩展（Doris 多副本为存储层，服务层多副本留待未来）。

### 4.4 子模块 D：数据安全（P0/P1）

| ID | 功能 | 描述 | 验收标准 |
|----|------|------|----------|
| DS-01 | 动态脱敏 | 按角色/敏感度对查询结果动态脱敏（手机号/身份证/邮箱等） | 低权限用户查询敏感字段得到脱敏结果 |
| DS-02 | 列级加密 | 对指定敏感列透明加密存储（打破一期 NG4 部分） | 加密列落库为密文，授权用户查询可解密 |
| DS-03 | 数据申请审批流 | 对受限数据（机密表/受保护数据源）发起访问申请，审批后临时/长期授权（DC-12） | 申请→审批→授权→到期回收闭环；审批留审计 |
| DS-04 | 审计合规加强 | 敏感数据访问、导出、授权等操作加强审计 | 敏感操作全量留痕、可按对象/主体检索 |

## 5. 主线二：实时链路深化

> **用户价值**：让工程师**用 SQL 就能写实时计算**（窗口聚合、CEP 事件识别），不必学 Flink/Spark Streaming；实时链路同样**自动出血缘、可做数据质量**。
> **技术路线（已拍板）**：复用已内嵌的 Flink 2.2.1 Session 集群，做**可视化流任务编排 + Flink SQL 提交与监控**，不自研流处理引擎。

### 5.1 子模块 A：流处理 SQL 编排（P0，核心）

| ID | 功能 | 描述 | 验收标准 |
|----|------|------|----------|
| ST-01 | 流任务可视化编排 | 向导式定义流任务：源（CDC 管道/实时表）→ Flink SQL（窗口/聚合/CEP）→ 目标（湖仓/Doris） | 无需手写 YAML，表单 + SQL 编辑器即可创建流任务 |
| ST-02 | 流处理 SQL 支持 | 支持 TUMBLE/HOP/SESSION 窗口、聚合、JOIN、MATCH_RECOGNIZE（CEP） | 常见窗口聚合与事件模式识别可运行 |
| ST-03 | 流任务生命周期 | 流任务的创建/提交/启停/删除，复用 Flink REST 与 Sprint 9 监控底座 | 启停状态实时同步，删除级联清理 |
| ST-04 | 流任务监控 | 吞吐/延迟/错误/重启指标趋势（复用 Sprint 9 指标历史体系） | 详情页可看趋势图与运行状态 |
| ST-05 | 流任务告警 | 复用 app-alert，新增 STREAM_JOB 告警对象类型 | 作业失败/延迟超阈值邮件告警 |
| ST-06 | 多源 JOIN | 实时流与维度表（Doris/湖仓）的 JOIN（RC-12） | 流表 JOIN 维度表可运行 |

### 5.2 子模块 B：流批一体血缘（P0）

| ID | 功能 | 描述 | 验收标准 |
|----|------|------|----------|
| LB-01 | 流任务血缘 | 流处理 SQL 自动解析血缘，接入现有血缘图谱（RC-09/08） | 流任务的源表→目标表血缘自动生成、可视化 |
| LB-02 | 流批血缘融合 | 离线血缘与实时血缘在同一图谱展示 | 可追踪"实时表 → 下游离线表"的混合链路 |

### 5.3 子模块 C：实时数据质量 + 观测（P1）

| ID | 功能 | 描述 | 验收标准 |
|----|------|------|----------|
| RQ-01 | 实时数据质量 | 流处理链路嵌入质量校验（空值/唯一/阈值），异常告警（RC-11） | 实时质量规则可配置、命中可告警 |
| RQ-02 | 背压观测 | 流任务背压/消费滞后可见（RC-10） | 背压指标可视化，便于容量判断 |
| RQ-03 | 外部监控对接 | 指标对接 Prometheus/Grafana（一期 NG7） | 可选暴露 metrics 端点 |

## 6. 主线三：DataOps 工程效能

> **用户价值**：让数据开发像软件工程一样——**改动能回滚、多环境隔离、发布可审计、运行可观测**，降低"改错一个任务影响生产"的风险。

| ID | 功能 | 描述 | 验收标准 |
|----|------|------|----------|
| DO-01 | 任务版本管理完整版 | DAG/同步任务配置的历史版本、差异对比、一键回滚（DD-08） | 可查看任意历史版本差异，可回滚 |
| DO-02 | 环境管理 | dev/test/prod 多环境隔离，任务按环境发布 | 同一任务可在多环境独立运行，互不影响 |

## 8. Sprint 路线图

> 二期从 **Sprint 13** 起，规划 **7 个 Sprint**（Sprint 13~19），每个 2~3 周。
> 主线一先行，主线二并行，主线三随后，主线四穿插。

```
Sprint 13：多租户底座（主线一·核心，P0）
  ├── MT-01~07 完整多租户（租户模型/隔离/配额/审计/租户内 RBAC）
  ├── 存量数据归默认租户，升级无损
  └── 内置 Doris 租户命名空间隔离

Sprint 14：SSO + 认证安全（主线一）
  ├── SSO-01~05（OIDC/LDAP/角色映射/本地共存/密码策略）
  └── 登录链路与审计加固

Sprint 15：高可用 + 数据安全（主线一）
  ├── HA-01~04（Doris 多副本/备份恢复/自愈）
  └── DS-01~04（动态脱敏/列级加密/数据申请审批流/审计合规）

Sprint 16：流处理 SQL（主线二·核心，P0）
  ├── ST-01~06（流任务可视化编排/Flink SQL 窗口 CEP/生命周期/监控告警/多源 JOIN）
  └── LB-01 流任务血缘（并行启动）

Sprint 17：流批一体血缘 + 实时数据质量（主线二）
  ├── LB-02 流批血缘融合
  └── RQ-01~03（实时质量/背压观测/Prometheus 对接）

Sprint 18：DataOps 工程效能（主线三）
  ├── DO-01~06（版本管理/环境/CI-CD/补数重跑/可观测/资源管理）

Sprint 19：补全遗留 + 体验打磨 + 二期收尾（主线四）
  ├── LF-01~05 高优先遗留项
  ├── LF-06~10 中优先（按余量取舍）
  └── 全链路回归 + 文档/Release 收尾
```

### 8.1 关键依赖与并行策略

- **Sprint 13 是硬前置**：多租户改造是全链路数据隔离底座，必须在 SSO、DataOps、遗留项等涉及"按租户隔离"的改造之前完成。
- **Sprint 16/17（实时）与 Sprint 13~15（企业级）解耦**，可在团队资源允许时并行启动（实时链路不依赖租户改造即可开发，但上线需适配租户上下文）。
- **主线四（遗留项）不设独立大 Sprint**，而是每个 Sprint 留出 20% 余量消化 LF 项；Sprint 19 集中收尾。

## 9. 成功指标体系

### 9.1 北极星指标

> **生产可用租户数 / 周活跃用户数（WAU）** —— 衡量二期"生产化"目标是否达成：有多少真实团队在多租户隔离下持续使用。

### 9.2 驱动指标

| 指标 | 目标 | 衡量方法 |
|------|------|----------|
| 租户开通时长 | 新租户开通 < 10 分钟 | 租户创建到可用的操作步骤统计 |
| 租户隔离正确性 | 0 起跨租户数据泄露 | 安全测试 + 审计抽查 |
| SSO 接入成功率 | 主流 IdP 一次配置成功率 > 90% | 部署/支持统计 |

| 实时链路血缘完整度 | 流任务血缘自动生成率 100% | 有血缘流任务 / 总流任务 |
| 任务回滚成功率 | 版本回滚成功率 > 95% | DataOps 版本管理统计 |
| 元数据可恢复性 | 备份恢复演练成功率 100% | HA 演练 |

## 10. 风险与开放问题

### 10.1 主要风险

| # | 风险 | 影响 | 缓解 |
|---|------|------|------|
| R1 | **多租户改造面大**：所有持库表 + 跨服务上下文 + 共享引擎（Doris/PowerJob）都要加租户隔离，改动横跨全部服务 | 工期长、回归风险高 | Sprint 13 单独成 Sprint；存量归默认租户保证无损；全链路 E2E 回归 |
| R2 | **内置 Doris 是共享引擎**，租户命名空间隔离需在库/目录层设计，避免跨租户表访问 | 数据泄露 | Doris 租户专属 database + 连接级校验，禁止跨租户 catalog 访问 |
| R3 | **完整多租户 vs 一期"默认全量可见"权限模型** | 语义需明确 | 租户边界为硬隔离、租户内权限沿用一期"默认全量可见、按需收缩"软收缩策略 |
| R4 | **Flink SQL 流任务的产品化复杂度**：SQL 校验、UDF 管理、状态恢复对用户透明度 | 流任务可用性 | 复用 Sprint 9 Checkpoint/Savepoint 底座；提供模板化 SQL 降低门槛 |
| R5 | **单机部署下的"高可用"边界** | 期望错位 | 明确二期 HA = 数据可靠性（副本+备份），非分布式扩展 |

### 10.2 已定稿问题（原开放问题 Q1~Q5，按倾向方案落地）

| # | 问题 | 定稿结论 |
|---|------|----------|
| Q1 | **租户-用户模型** | **单账号多租户可切换**：用户可加入多个租户，登录后切换当前租户 |
| Q2 | **SSO 协议优先级** | **OIDC/OAuth2 优先**（通用标准），企业微信/钉钉作为后续渠道 |
| Q3 | **列级加密范围** | **仅敏感列加密**（配合分级分类），全库加密不做 |
| Q4 | **版本号策略** | **v1.1.0 起步**（多租户视为 1.x 演进；若重大不兼容再升 2.0） |
| Q5 | **多租户与开源定位** | **开源版保留多租户**，企业版差异化另议 |
