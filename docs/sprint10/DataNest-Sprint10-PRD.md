# Sprint 10：数据服务（SQL 查询终端 + 数据 API + API 网关 + 实时推送 + 数据分级分类）PRD

> **版本**：v1.3 | **日期**：2026-08-12 | **作者**：产品通
>
> **Sprint 目标**：在 Sprint 8/9 打通实时链路、资产目录具备协作能力的基础上，让平台沉淀的数据资产**真正「对外可消费」**——分析师有 SQL 查询终端，业务系统有数据 API（含 Key 认证/限流/熔断/调用统计），实时链路有 WebSocket 订阅推送；同时补上数据服务的前置安全能力「数据分级分类」，让机密数据不出中台。

---

## 1. 问题陈述

### 1.1 为什么 Sprint 10 做这件事

Sprint 0~9 的平台把「采集 → 同步 → 编排 → 治理 → 资产 → 实时」全链路做通了，数据资产目录也已可搜索、可协作。但**数据仍然「进得去、出不来」**——所有数据都停在中台内部，没有一个面向消费侧的出口：

**缺口一：分析师没有 SQL 查询终端。**
资产目录里能看到表、能预览前 100 行，但分析师想跑自己的分析 SQL（JOIN、GROUP BY、窗口函数）只能开第三方客户端连 Doris/MySQL，或找工程师跑任务再导出。规格 DS-01 的「在线 SQL 查询终端」一直没做。查询历史、结果导出 CSV/Excel 更是空白。

**缺口二：业务系统没有数据 API。**
中台沉淀的表，业务系统要消费只能「工程师手工导一份 Excel」或「给业务开库直连」。没有标准化的 RESTful API、没有 Key 认证、没有限流熔断、没有调用统计——规格 DS-02/DS-03/DS-04 全部缺失。数据资产的「API 地址」入口（规格 DA-05 / DE-12）在资产详情页是空话。

**缺口三：实时数据没有对外通道。**
Sprint 8/9 打通了 CDC 管道 + 流处理监控，但实时数据只进 Iceberg/Doris，业务系统无法实时订阅变更（DS-05 / RC-05 的 WebSocket 推送）。「数据变更订阅」能力为零。

**缺口四：数据分级分类缺失，机密数据裸奔。**
规格 DG-09（数据分级分类：公开/内部/机密）一直 P1 挂账，Sprint 10 之前数据服务无任何敏感度控制。一旦开放 SQL 终端和对外 API，机密表就会和公开表一样可查可导——**必须在开放数据服务的同时补上分级分类这道闸**（规格 §15.1 已把 DG-09 归属数据服务期）。

所以 Sprint 10 的核心命题是：**给中台开一扇「数据服务」的门**——查询、API、实时推送三个出口 + 分级分类一道闸，让数据资产真正可消费、可控、可计量。

### 1.2 当前用户怎么做的（痛点）

| 现在 | Sprint 10 之后 |
|------|----------------|
| 分析师要跑分析 SQL 只能开第三方客户端连库，权限裸奔、无审计 | 平台内 SQL 查询终端，只读 SQL + 超时中断 + 历史留存 + 结果导出，行为可审计 |
| 业务系统要数据靠工程师手工导 Excel，一版一导、口径易漂移 | 一键生成 RESTful API，参数化查询 + 分页，业务系统按 Key 自取 |
| 想实时拿到数据变更没有通道，只能轮询数据库 | WebSocket 订阅 CDC 管道变更，业务系统长连接实时接收 |
| 对外 API 无认证无限流，泄漏了也不知道谁在调 | API Key 认证 + 限流熔断 + 调用量/耗时/错误率统计 |
| 机密表在资产目录人人可见、人人可导 | 表级敏感度分级（公开/内部/机密），SQL 查询/API 生成按级设防 |

### 1.3 Sprint 10 要达到的状态

> 数据分析师在「SQL 查询终端」选择 Doris 数据源，运行 `SELECT region, COUNT(*) FROM dws_orders GROUP BY region`，5 秒返回 3 行结果，导出 CSV 用于分析报告；这条查询进了他自己的历史记录。
>
> 数据工程师把 `dws_orders` 表一键生成 RESTful API `GET /open-api/v1/dws_orders?region=华东&page=1&pageSize=20`，生成一个 API Key 交给业务系统；业务系统带 Key 调用，超限返回 429，调用量/耗时在「API 监控」可见。
>
> 业务系统通过 WebSocket 订阅 `orders-sync` 管道，订单表每笔 INSERT/UPDATE 变更在 10 秒内推送到订阅端。
>
> 治理管理员把 `dws_customer_phone` 标记为「机密」，此后该表在 SQL 终端默认隐藏、不能一键生成对外 API——机密数据被挡在数据服务闸门之外。

### 6.2 SQL 查询终端（DS-01）

```
┌─ SQL 查询终端 ─────────────────────────────────────────────────────┐
│  数据源 ▼ [内置 Doris | MySQL:xxx | PostgreSQL:xxx | …]   运行▶ 停止 │
│  ┌──────────────────────────────────────────────────────────┐      │
│  │ SELECT region, COUNT(*) AS cnt                          │      │
│  │ FROM dws_orders                                        │      │
│  │ GROUP BY region                                        │      │
│  │ ;  （Monaco 编辑器，语法高亮，Ctrl+Enter 运行）           │      │
│  └──────────────────────────────────────────────────────────┘      │
│  用时 0.45s · 返回 3 行（最多 1000 行）        [导出 CSV] [导出 Excel] │
│  ┌──────────────────────────────────────────────────────────┐      │
│  │ region   cnt                                            │      │
│  │ 华东      12845                                          │      │
│  │ 华北      9832                                           │      │
│  │ 华南      7621                                           │      │
│  └──────────────────────────────────────────────────────────┘      │
│  查询历史（本会话页签，点击回填）                                      │
└────────────────────────────────────────────────────────────────────┘
```

**交互说明**：
- **数据源选择**：下拉展示「内置 Doris」+ 平台全部数据源（复用数据源列表，仅展示状态 NORMAL/ONLINE 的）；数据源连接信息由后端统一持有，前端只传 id。
- **只读校验**：后端对 SQL 做**只读白名单校验**——仅允许 `SELECT` / `WITH` / `SHOW` / `DESC` / `EXPLAIN` 开头的语句，含 `;` 多语句时逐条校验；命中 INSERT/UPDATE/DELETE/DDL（CREATE/ALTER/DROP/TRUNCATE）返回 6xxx 错误并拒绝执行。
- **超时中断**：单次查询默认 60s（可配），超时后端中断连接并返回超时错误；前端「停止」按钮可主动取消。
- **结果上限**：单次返回最多 **1000 行**（对齐 `DorisSqlExecutor` 现有上限），超过显示「结果已截断，仅展示前 1000 行」。
- **导出**：CSV（带 BOM，沿用导出规范）/ Excel（xlsx，复用 `XlsxExportHelper`），文件名 `{数据源}_{表}_{yyyyMMdd_HHmmss}`。
- **查询历史**：按登录用户留存（保留 30 天），展示 SQL/数据源/用时/行数/时间，点击回填编辑器；支持清空自己的历史。
- **机密表控制（D1 定稿）**：**默认隐藏 + 命中拦截**——机密表默认不出现在数据源表列表/自动补全/表选择器中；SQL 中显式引用机密表时返回明确拦截提示（如「表 dws_customer_phone 为机密级，无权查询」）。
- **资产页直达**：资产详情页「去查询」→ 跳到 SQL 终端并预填 `SELECT * FROM 库.表 LIMIT 100`、选中对应数据源。

**技术底座复用**：后端执行直接复用 task-core 的通用查询能力（`DorisSqlExecutor` 查询模式 + common `JdbcPreviewHelper` 的多数据源 JDBC 直连），新增**只读白名单 + 超时 + 通用数据源（非仅 Doris）执行端点**；前端编辑器复用已有 Monaco（DAG `SqlEditorModal` 同款）。

### 6.3 数据 API 生成（DS-02）

```
┌─ 新建 API ─────────────────────────────────────────────────────────┐
│  第 1 步 · 选择数据表                                                 │
│  数据源 ▼ 内置Doris     库 ▼ datanest    表 ▼ dws_orders            │
│  （也可从资产目录/元数据列表点「生成 API」带入）                       │
│  表敏感度：公开（内部/机密不可生成对外 API）                            │
│                                                                    │
│  第 2 步 · 配置接口                                                   │
│  API 名称 *  [订单区域统计]         API 路径 * /open-api/v1/orders  │
│  请求方法    [GET]                                                   │
│  参数化筛选  ☑ region（等值）  ☑ status（等值）  ☐ 范围（min/max）     │
│  排序字段    [cnt DESC]        分页  ☑ 启用（page/pageSize 默认 1/20）│
│  返回字段    ☑ 全选：region, cnt, amount, phone                     │
│            （机密列自动去选不可勾选）                                  │
│  自动生成文档 ☑（OpenAPI 描述，含参数说明）                            │
│                                                                    │
│  第 3 步 · 绑定 API Key                                              │
│  ☑ 绑定已有 Key [业务-订单组 ▼] 或 ○ 新建 Key                         │
│  [预览 API 文档]                [完成创建]                            │
└────────────────────────────────────────────────────────────────────┘
```

**交互说明**：
- **来源**：从资产详情/元数据「生成 API」一键带入（表+库+数据源），或向导手选。
- **API 预览（2026-08-12 定稿）**：第 1 步选表即生成**接口雏形实时预览**（目标卡展示生成路径与请求方法，如 `GET /open-api/v1/orders`，带复制；下方为**暴露字段清单**——公开字段默认全量勾选、可参数化字段标注，**机密级字段自动锁定灰置不可勾选**，不进入 API 响应），后续步骤可修改路径/参数/字段。创建向导不再重复展示源表信息卡。
- **分级拦截（D1/D2 定稿）**：**机密表不可生成对外 API**（按钮置灰 + 提示「表敏感度为机密，禁止对外提供 API」）；**内部表默认禁止，超管可单表强制开白并留审计**（见 T6）——机密数据不出中台的核心闸门。
- **参数化**：从表字段选择「等值筛选（`field=value`）」与「范围筛选（`min_field`/`max_field`）」；查询条件组合为 AND。
- **分页排序**：默认启用 `page`（从 1 开始）/`pageSize`（默认 20，上限 100）/`orderBy`/`orderDir`。
- **返回字段裁剪**：默认全字段，可取消选择；**机密级列自动移除**（若字段级敏感度未来启用，见 NG5）。
- **自动文档**：创建时生成 OpenAPI 描述（路径/参数/返回结构），API 详情页可查看与复制调用示例（curl）。
- **生命周期**：状态机 `CREATED（未发布）→ PUBLISHED（可调用）→ DISABLED（下线）→ 删除`；删除需确认（影响在线业务），软删保留调用统计。

```
│  临时测试     启用    0        5        0         07-20    [启用][删除]│
│  [新建 Key]  ┌─ 新建 Key ────────────────────────────────┐          │
│              │ Key 名称 * [业务-订单组]                   │          │
│              │ 限流 QPS   * [50]（该 Key 下所有 API 共享）│          │
│              │ 绑定 API    [☑ 订单区域统计 ☑ 订单明细]   │          │
│              │ 生成后仅展示一次：K-xxxx-xxxx-xxxx        │          │
│              └───────────────────────────────────────────┘          │
└────────────────────────────────────────────────────────────────────┘
```

**交互说明**：
- **API Key**：创建时生成一次性明文（格式如 `K-xxxxxxxx`），仅展示一次，后端只存哈希；Key 支持启用/禁用/删除；禁用后调用立即 401。
- **近 7 天调用列（2026-08-12 定稿）**：Key 列表展示「近 7 天调用」聚合值，识别**僵尸 Key（近 7 天 0 调用，灰显）**；列表页提示「近 7 天调用为 0 的 Key 建议停用，防止长期闲置引发泄露风险」。
- **快捷禁用/启用（2026-08-12 定稿）**：操作列提供**快捷禁用/启用**（启用态 Key 一步禁用、禁用态 Key 一步启用），泄露场景 1 步处置，不必进入编辑；操作列按钮顺序：查看 / 编辑 / 启用或禁用 / 删除。
- **Key-API 绑定**：一个 Key 可绑定多个 API，一个 API 可被多个 Key 调用；API 下线后相关 Key 调用返回 404。
- **调用认证**：对外 API 统一入口 `/api/data-service/open-api/**`（网关放行 + 服务侧校验 `X-API-Key` 头），无 Key/失效/未绑定返回 401，限流超限返回 429（响应带 `Retry-After`）。
- **限流**：粒度 = Key × API（Key 级总 QPS + 每 API 级 QPS 取小）；基于 Redis（已有 middleware-redis）计数器滑动窗口。
- **熔断**：后端目标数据源连续异常（如查询 5s 超时）触发熔断（半开探测），熔断期间返回 503；复用既有 Resilience4j 语义。
- **API 生命周期**：发布/下线/删除；下线中的 API 网关返回 404「API 已下线」。
- **网关形态**：对外入口复用现有 Gateway 路由 `/api/data-service/**`（StripPrefix=1），API Key 校验在数据服务侧过滤器完成（与现有 `/internal/**` 令牌模式并列但独立）。

### 6.6 数据实时推送（DS-05 / RC-05：WebSocket 对外订阅）

```
┌─ CDC 管道详情 → 实时订阅 ───────────────────────────────────────────┐
│  订阅地址：ws://gateway/api/data-service/ws/events                  │
│  认证方式：Header X-API-Key: K-xxxxxxxx                             │
│  订阅示例：                                                          │
│    { "op": "subscribe", "pipelineId": 12 }                          │
│  变更事件示例：                                                      │
│    { "pipelineId": 12, "table": "orders", "opType": "INSERT",       │
│      "data": { "id": 1024, "amount": 99.9 },                        │
│      "ts": "2026-08-12T10:00:01Z" }                                 │
│  [复制订阅地址] [复制示例代码]                                        │
│  说明：仅 PUBLISHED 状态管道可订阅；每变更事件端到端延迟 < 10s          │
└────────────────────────────────────────────────────────────────────┘
```

**交互说明**：
- **订阅协议**：业务系统经 WebSocket 长连接，连接时带 `X-API-Key` 头（**D3 定稿**：复用 API Key 体系，**Key 直接绑定管道即获得订阅权**，见 T7）；连接后发 `subscribe` 消息订阅指定管道。
- **事件内容**：CDC 管道捕获的**行级变更事件**（INSERT/UPDATE/DELETE，含变更后行数据 JSON + 管道 id + 表名 + 时间戳）。事件来源 = realtime 侧 CDC 链路扩展（Flink CDC 捕获变更 → 事件总线 → 数据服务 WebSocket 分发），端到端延迟 < 10s（规格 RC-05）。
- **推送形态**：分布式分发（多连接按管道 fan-out）；断线自动重连由业务端负责（平台提供心跳 ping/pong，60s）。
- **对外地址**：`/api/data-service/ws/events`（Gateway 路由 → 数据服务 WebSocket 端点）。
- **文档**：管道详情页新增「实时订阅」页签展示订阅地址/认证/协议/示例代码；全角色可看，实际订阅需 Key。
- **与 realtime 的边界**：realtime 负责捕获变更事件（新增事件发布点，不改现有监控/指标链路）；数据服务负责 WebSocket 连接管理 + Key 校验 + 分发。两者经 internal Feign 或事件通道解耦（**D4 待 M0 调研定案**）。

- **打标方式**：分级管理页单选/批量勾选 → 设为某级；资产详情页也可单表改级（治理员/超管）。
- **策略联动**（分级 → 数据服务闸门，D1/D2 定稿）：

- **与现有分类的关系**：复用 `metadata_table` 的 `data_domain`/`data_topic`（业务分类）字段体系，**新增独立敏感度字段**（如 `sensitivity_level`），两者互不干扰；`asset_classification` 仍是数据域/主题两级业务分类，不动。

## 9. 验收标准

### 9.1 功能验收

| # | 验收项 | 通过标准 |
|---|--------|----------|
| AC-1 | SQL 只读查询 | 分析师在内置 Doris 执行 SELECT/多表 JOIN 成功返回；INSERT/UPDATE/DDL 被拦截并给出明确错误 |
| AC-2 | 超时与截断 | 构造慢查询（如 `SELECT SLEEP(120)`）在 60s 被中断；返回行 >1000 时提示截断 |
| AC-3 | 导出 | 查询结果导出 CSV/Excel 成功，中文正常，文件名符合规范 |
| AC-4 | 查询历史 | 历史按用户留存，点击回填 SQL，30 天清理生效 |
| AC-5 | API 创建 | 公开表可一键生成 API；参数化/分页/排序配置生效；自动文档可预览 |
| AC-6 | API Key 认证 | 无 Key 调用 401；错误 Key 401；禁用 Key 401；正确 Key 200 |
| AC-7 | 限流 | Key QPS=5 时第 6 次调用 429 且带 Retry-After；恢复窗口后可再调用 |
| AC-8 | 熔断 | 数据源不可用时连续失败触发熔断，返回 503；恢复后半开探测通过自动闭合 |
| AC-9 | 调用统计 | API 详情展示调用量/成功率/平均耗时/P95，趋势与明细与调用行为一致 |
| AC-10 | WebSocket 推送 | 业务端持绑定该管道的 Key 订阅运行中管道，源库 INSERT/UPDATE/DELETE 变更 10s 内收到事件；无 Key/未绑定管道订阅被拒 |
| AC-11 | 分级拦截 | 机密表：SQL 终端默认不出现在表列表、显式查询被拦截、API 生成入口置灰、管道不可订阅；内部表：可查、不可生成对外 API（超管强制开白后可见并留审计） |
| AC-12 | 分级审计 | 改级操作（含超管开白）写入审计日志，可查谁/何时/从哪级到哪级 |
| AC-13 | 资产联动 | 资产详情页展示敏感度标签；「去查询」带表跳转 SQL 终端；「生成 API」带表跳转向导 |

## 10. 风险与对策

| # | 风险 | 影响 | 对策 |
|---|------|------|------|
| R1 | 多数据源 SQL 执行差异（MySQL/PG/Doris 语法、分页关键字不同） | 查询终端在部分数据源报错 | 复用 `JdbcPreviewHelper` 已封装的类型分支（分页/标识符/URL）；首次只放开 MySQL/PostgreSQL/Doris，Oracle/SQLServer 驱动与测试就绪再放（NG10） |
| R2 | 慢查询拖垮源库 | 影响业务库性能 | 只读 + 超时中断（默认 60s）+ 单连接超时 + 连接池隔离；运维可配超时 |
| R3 | API Key 泄露被滥用 | 数据外泄/配额被刷 | Key 只存哈希 + 一次性展示 + 可禁用；限流 + 调用统计 + 审计；泄露即禁用重签 |
| R4 | 分级分类误标（机密误标公开） | 敏感数据经 API 外泄 | 默认「公开」仅对新建表；内部/机密需显式打标；机密表双端拦截 + 变更审计；改级需治理员 |
| R5 | WebSocket 长连接资源占用 | 连接数膨胀 | 心跳 60s + 空闲断开 + 单 Key 并发连接上限；管道级 fan-out 复用 |
| R6 | 变更事件实时获取依赖 realtime 链路扩展 | 推送延迟或事件丢失 | M0 技术调研先行：确认 CDC 事件捕获方式（Flink CDC 旁路输出 / 日志解析）与延迟；失败降级「断线重连 + 全量刷新」提示 |
| R7 | 调用统计表膨胀 | DB 压力 | 异步写入 + 30 天清理 + 按天/小时聚合表；明细表定期归档 |
| R8 | 数据服务与 realtime 解耦不彻底 | 两服务强耦合 | WebSocket 网关在数据服务，事件来源 realtime 内部端点/事件通道；realtime 变更不影响数据服务可用性 |
| R9 | 网关对外路径与现有鉴权冲突 | 对外 API 被登录态拦截或绕过 | 对外 `open-api` 与 `ws` 路径在网关明确路由；API Key 校验在服务侧独立过滤器，与现有 Sa-Token 登录态互不干扰 |
