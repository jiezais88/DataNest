# Sprint 4：Python 任务、参数化、监控告警与血缘上报 PRD

> **版本**：v1.0 | **日期**：2026-08-01 | **作者**：产品通
>
> **Sprint 目标**：让数据工程师在 DAG 中编排 Python 任务，通过参数化让同一条流水线适配不同场景；让平台在 DAG
> 失败时主动通知，并让 SQL 任务的产出自动进入血缘链路，为后续治理闭环奠基。

---

## 1. 问题陈述

### 1.1 为什么 Sprint 4 做这件事

Sprint 3 把 SQL 任务和同步任务串成了 DAG，但数据工程师很快会发现：

- **SQL 不是万能的**：有些数据清洗逻辑用 Python 写更自然（复杂文本解析、自定义算法、调用外部 API 预处理），但平台里还无法放置
  Python 节点。
- **同一条 DAG 不能复用**：昨天跑一遍"2026-07-30"的账单，今天想跑"2026-07-31"，只能复制一条 DAG 改 SQL 里的日期。
- **失败了没人知道**：DAG 失败只有登录平台才能发现，晚上定时任务挂了，第二天业务用数时才暴露。
- **加工出来的表不知道哪来的**：SQL 任务建了一堆表，但元数据管理里只看到"有一张表"，看不到它是哪个 DAG、哪个节点产出的，更看不到上游依赖。
- **多表同步的配置还停留在字段层面**：Sprint 3 后端已为多表同步和速率限流预留了字段，但前端仍是单表流程，工程师无法真正使用。

所以 Sprint 4 的核心命题是： **扩展 DAG 的任务类型、让 DAG 可参数化复用、让失败可被感知、让加工结果自动进入血缘链路**。

### 1.2 当前用户怎么做的（痛点）

| 现在                                                   | Sprint 4 之后                                              |
|--------------------------------------------------------|------------------------------------------------------------|
| 需要写 Python 的逻辑只能在平台外跑，再手动同步进 Doris | 在 DAG 画布上直接拖入 Python 节点，与 SQL/同步节点统一编排 |
| 每天跑不同日期的数据要复制多条 DAG                     | 一条 DAG 配置 `$biz_date` 参数，手动触发时可覆盖日期       |
| DAG 失败靠人登录平台查看                               | 失败/超时自动发送邮件，附带失败节点和错误摘要              |
| SQL 产出的新表找不到上游来源                           | 元数据详情页显示"来源：DAG-XXX / 节点-YYY"                 |
| 一个同步任务只能配一张源表                             | 一个同步任务可选多张源表，并统一设置限速                   |
| DAG 改坏了只能手动重建                                 | 保存历史自动生成版本，支持对比和回滚                       |

### 1.3 Sprint 4 要达到的状态

> 工程师进入「数据开发」→ 打开 DAG 画布 → 拖入 Python 节点写数据清洗脚本 → 在 DAG 参数区定义
> `$biz_date` → 连接 SQL 节点和同步节点 → 保存 → 手动触发时输入日期 → DAG 执行失败 → 工程师收到邮件，点开链接直达执行历史
> → 修复后回滚到上个稳定版本继续开发。
>
> 治理员进入「元数据管理」→ 看到 Python/SQL 任务产出的新表 → 表详情显示来源 DAG 和节点 → 血缘链路可追溯到上游同步任务。

#### 6.3.2 Python 执行环境

- 调用 DataNest 服务所在机器的本地 Python 3 解释器。
- Sprint 4 仅支持 Python 标准库，不提供 pip 安装第三方库能力。
- 资源限制：
    - 超时：默认 30 分钟，可在节点级覆盖。
    - 内存：默认 2GB，超出则 OOM 终止。
    - 禁止危险操作：禁止执行文件删除、网络访问、子进程启动等（通过白名单 API 控制）。

#### 6.3.3 内置 helper（平台注入的上下文函数）

Sprint 4 提供以下内置函数，脚本中可直接调用：

| 函数                           | 说明                                                                  |
|--------------------------------|-----------------------------------------------------------------------|
| `read_doris_table(table)`      | 读取 Doris 表，返回 pandas DataFrame（依赖运行环境是否已安装 pandas） |
| `write_doris_table(df, table)` | 将 DataFrame 写入 Doris 表                                            |
| `get_param(name)`              | 获取 DAG 参数值                                                       |
| `log(message)`                 | 输出日志，会进入节点执行日志                                          |

> 注：Sprint 4 仅支持 Python 标准库；pandas 是否可用取决于部署环境。若环境未安装 pandas，`read_doris_table` 可降级返回
> list/dict，或脚本自行使用标准库处理。

#### 6.3.4 元数据自动注册

Python 节点正式执行成功后，若脚本中调用了 `write_doris_table`，目标表自动注册到元数据管理。 注册逻辑复用 SQL 任务的
`MetadataRegistrationService`，但需新增 Python 节点回调路径（目前只有 `/dev/internal/sql/callback`）。 注册时同步写入
`来源 DAG / 来源节点` 信息，见 6.6.3。

**参数字段**：

| 字段     | 必填 | 说明                                                      |
|----------|------|-----------------------------------------------------------|
| 参数名称 | ✅   | 字母/数字/下划线，3-30 位，DAG 内唯一，不能与系统变量重名 |
| 参数类型 | ✅   | STRING / NUMBER / DATE / BOOLEAN                          |
| 默认值   | ✅   | 根据类型校验；DATE 类型使用日期选择器                     |
| 必填     | —    | 手动触发时是否必须填写                                    |
| 描述     | —    | 可选，最多 200 字                                         |

#### 6.4.2 参数在节点中的引用

SQL 节点和 Python 节点均支持通过 `${paramName}` 引用参数：

```sql
-- SQL 节点示例
INSERT INTO doris.dwd.orders_${env}
SELECT *
FROM doris.ods.orders
WHERE dt = '${biz_date}';
```

```python
# Python 节点示例
date = get_param('biz_date')
df = read_doris_table(f'doris.ods.orders_{date}')
```

系统变量引用方式与参数一致：

```sql
WHERE dt = '${biz_date}';
```

#### 6.4.3 参数替换规则

- 替换时机：DAG 执行前，由后端统一替换。
- 未定义的占位符保留原样，并记录警告日志。
- 类型校验：NUMBER 类型替换时校验是否为数字；DATE 类型按 `yyyy-MM-dd` 格式替换。
- 特殊字符转义：SQL 字符串中的单引号需要正确转义，防止注入。

- 仅重新执行该实例中状态为 FAILED 或 SKIPPED 的节点。

- 上游依赖已成功的失败节点，直接以其结果开始执行。
- 重跑生成新的执行实例，原失败记录保留。


**字段说明**：

| 字段         | 必填 | 说明                                                     |
|--------------|------|----------------------------------------------------------|
| 启用速率限制 | —    | 复选框，默认不勾选                                       |
| 读取速率上限 | 否   | 对源端数据库的读取速度限制，单位为 **MB/s**，不填不限制  |
| 写入速率上限 | 否   | 对目标 Doris 的写入速度限制，单位为 **行/s**，不填不限制 |

> **为什么读写单位不同**：读取侧主要消耗源库网络/IO 带宽，用 MB/s 更直观；写入侧直接对应 Doris 的写入行数，用 行/s
> 更便于衡量数据同步进度。
>
> 限流场景：生产环境的源库不能承受全速读取；或 Doris 集群写入压力大需要控制。

| AC-19 | 权限隔离         | 治理员不可编辑 DAG/参数/Python 节点；分析师仅可查看                                                            |
| AC-20 | 同步任务引用校验 | 删除被 DAG 引用的同步任务时，弹窗阻断列出 DAG 名称                                                             |

## 10. 风险与对策

| #  | 风险                       | 影响                       | 对策                                                              |
|----|----------------------------|----------------------------|-------------------------------------------------------------------|
| R1 | Python 脚本执行时间不可控  | 占用服务资源，影响其他任务 | 超时强制终止 + 内存限制 + 独立进程运行                            |
| R2 | Python 脚本安全风险        | 恶意脚本破坏系统或泄露数据 | 白名单 API + 禁止文件/网络/子进程 + 沙箱目录隔离                  |
| R3 | 参数替换注入风险           | SQL 注入                   | 占位符替换时做类型校验和特殊字符转义                              |
| R4 | SQL 血缘解析不支持复杂语法 | 血缘链路缺失               | Sprint 4 覆盖常见 CTAS/INSERT/CREATE VIEW；复杂语法留 Sprint 5    |
| R5 | 邮件发送失败               | 告警漏发                   | 异步发送 + 失败重试 + 后台日志记录                                |
| R6 | 多表同步字段类型不一致     | 写入失败                   | 保存前预校验同名不同型字段，强制用户确认                          |
| R7 | DAG 版本数据膨胀           | 存储成本增加               | 版本快照只存 diff，或限制保留最近 N 个版本（Sprint 4 先全量保留） |
| R8 | 重跑失败节点状态一致性     | 成功节点结果与实际不一致   | 重跑前锁定原执行记录，成功节点结果只读                            |
