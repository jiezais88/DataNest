## 2. 测试数据策略（自播种自清理）

### 2.1 种子数据

- **Doris 测试表 2 张**（内置 Doris datasourceId=-1，库 `datanest`）：
  - `e2e_s13_orders`（order_id BIGINT, region_id BIGINT, amount DECIMAL(12,2), order_date DATE, remark VARCHAR）—— 6 行（华东/华南/华北 各 2）
  - `e2e_s13_region`（region_id BIGINT, region_name VARCHAR）—— 3 行（华东/华南/华北）
  - 建表/插数经平台 SQL 终端 API `POST /data-service/sql-console/execute`（admin token）执行 DDL+DML —— 与 sql-console.spec.ts 同一路径，幂等（先 DROP IF EXISTS）
  - **元数据**：直接 SQL 插 `metadata_table`（datasource_id=-1, database_name='datanest', source_type='BUILTIN_DORIS', sensitivity_level='PUBLIC'）+ `metadata_column`（仿 sprint7 seedMetadata 模式）；涉及表权限/敏感度/血缘全部依赖它
- **临时用户 2 个**（`e2e_s13_engineer` / `e2e_s13_analyst`，经 POST /system/users，cleanup SQL 删）：
  - engineer：绑定自定义角色 + `sys_data_permission` WHITELIST 白名单仅含 `datanest.e2e_s13_orders`（**不含 region**）→ 造「多表权限 fail-closed」数据
  - analyst：只读角色（DATA_ANALYST）→ 权限矩阵 403 用例
- **API/Key 前缀**：`e2e_s13_` / 路径段 `e2e-s13-`；cleanup 物理删除 data_api/api_key/api_key_binding（仿 f2-seed）+ 删血缘（lineage_record）+ 删审计（按 resource 关键词，见 §5 备注）
- **敏感度闸门造数**：直接 UPDATE metadata_table 改 e2e_s13_orders 的 sensitivity_level（PUBLIC→INTERNAL/CONFIDENTIAL），测完复位 PUBLIC + api_exempted=0（仿 f2-seed setSensitivity）

### 2.2 对外调用

- 复用 f3-seed 的 `openApiCall` 模式：`http://localhost:8080/api/data-service/open-api/v1/{path}` + `X-API-Key` 头，不登录

## 3. API 级用例（20）

> 主链路 SQL（JOIN+聚合，仿 PRD §6.2 示例，Doris 语法）：
> ```sql
> SELECT r.region_name, SUM(o.amount) AS total
> FROM datanest.e2e_s13_orders o
> JOIN datanest.e2e_s13_region r ON o.region_id = r.region_id
> WHERE o.order_date >= :startDate
> GROUP BY r.region_name ORDER BY total DESC
> ```

### A. 创建（AC-2 / V1 / V3 / V4）

| ID | 用例 | 操作 | 预期 |
|----|------|------|------|
| CS-API-01 | 创建成功 | POST /apis {queryType:'CUSTOM_SQL', datasourceId:-1, databaseName:'datanest', sqlText:主链路SQL, sqlParams:[{name:'startDate',type:'DATE',required:true}], name/path/paginated:1} | code 200；detail 含 queryType=CUSTOM_SQL、sqlText、involvedTables=[orders,region]（2 张） |
| CS-API-02 | 只读校验拒绝 | sqlText 分别替换为 `UPDATE ...` / `DELETE ...` / `DROP TABLE ...` / `SELECT 1; DELETE FROM ...`（多语句） | 全部 code **9001**，message 含「只读」或「多语句」 |
| CS-API-03 | 参数不一致拒绝 | ① SQL 用 `:startDate` 但 sqlParams 空；② sqlParams 定义 SQL 里没有的 `:foo`；③ 参数类型非法（type='XXX'） | ①② code **9018**；③ 9018 或参数校验 400（按实现定） |
| CS-API-04 | 涉及表解析落库 | 创建后查 `data_api.involved_tables`（psql 直查） | JSON 数组含 e2e_s13_orders + e2e_s13_region（datasourceId/database/table） |
| CS-API-05 | 敏感度闸门 fail-closed | e2e_s13_orders 改 CONFIDENTIAL → 创建；改 INTERNAL 未开白 → 创建；开白(exempt=1) → 创建 | 前两次 code **9019** 且 message 指明具体表；开白后成功；finally 复位 PUBLIC |
| CS-API-06 | 数据权限闸门 fail-closed | 用 engineer（WHITELIST 仅 orders）创建含 JOIN region 的 SQL | code **9019**，message 指明无权限表 region；只查 orders 单表的 SQL 创建成功 |
| CS-API-07 | 选表形态不受影响 | 不带 queryType（默认 TABLE_SELECT）创建 | 与一期行为一致（成功 + queryType=TABLE_SELECT） |

## 5. 执行备注与风险

1. **超时用例（CS-API-14）**：Doris 无 `pg_sleep`；方案 A：Nacos 把 timeout-seconds 调到 2s + Doris 大表慢查询；方案 B：临时建一个 PG 数据源指向 middleware-test-postgres 用 `pg_sleep(30)`。执行期选 A 优先，B 兜底。
2. **血缘断言（CS-API-19）**：需确认 `lineage_record` 表结构（来源类型枚举值 = 'API'？来源ID字段名？）与血缘写入时机；sprint7 lineage 用例可参考。
3. **审计断言（CS-API-20）**：复用 sprint11 `helpers/audit-seed.ts` 的 findAudit 模式；清理时按 resource 关键词 `e2e_s13_` 物理删审计记录。
4. **前端选择器**：t3 代码落地前 UI 用例仅为设计稿；落地后按实际 DOM/文案修订（尤其向导步骤名、按钮文案）。
5. **环境**：Doris 为外部主机 192.168.119.135，宿主无 mysql client；建表/插数一律走平台 SQL 终端 API（`POST /data-service/sql-console/execute`，admin token），幂等 DROP+CREATE+INSERT。
6. **执行顺序**：API 级 spec 先跑（不依赖前端），UI 级在后；两 spec 各自 beforeAll/afterAll 播种清理，串行（workers=1 已配置）。
7. **清理产物**：跑完清理 test-results* / %TEMP% 临时文件（AGENTS.md §4 纪律）。
