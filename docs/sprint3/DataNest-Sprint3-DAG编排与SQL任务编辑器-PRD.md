# Sprint 3：DAG 编排与 SQL 任务编辑器 PRD

> **版本**：v2.1 | **日期**：2026-07-29 | **作者**：产品通
>
> **Sprint 目标**：让数据工程师在可视化 DAG 画布上编排数据开发流水线——将 SQL 任务和批量同步任务串联成有依赖关系的执行链，支持手动触发和
> Cron 调度。SQL 任务执行后，新产生的表自动注册到元数据管理。

---

## 1. 问题陈述

### 1.1 为什么 Sprint 3 做这件事

Sprint 2 完成了数据的"搬运"——把外部数据源的表同步到内置 Doris。但现在工程师面临新问题：

- **任务之间是孤岛**：订单同步任务跑完 → 手动创建 SQL 任务清洗数据 → 再手动创建另一个 SQL 任务做聚合，完全靠人记住执行顺序。
- **没有统一的编排视图**：同步任务在「批量数据同步」里，如果再加 SQL 任务，工程师需要记住"先跑这个再跑那个"，出错了也不知道是卡在哪一步。
- **数据开发能力空白**：内置 Doris 里已经有数据了，但工程师没有一个地方能写 SQL 去加工数据——"搬运完就完了，不能加工"。

所以 Sprint 3 的核心命题是： **在可视化 DAG 画布上，把同步任务和 SQL 任务编排成流水线，一���执行到底**。

### 1.2 当前用户怎么做的（痛点）

| 现在                                   | Sprint 3 之后                                           |
|----------------------------------------|---------------------------------------------------------|
| 同步任务和后续加工靠人脑记顺序         | DAG 画布上连线，上游完成自动触发下游                    |
| 写 SQL 要在 Doris 客户端或命令行里操作 | 平台内置 SQL 编辑器，语法高亮、格式化、选中即执行       |
| SQL 加工产生的新表，元数据里看不到     | 执行后自动注册到元数据管理，立即可查                    |
| 不知道整个数据流水线的执行状况         | DAG 画布上每个节点实时显示状态（等待/运行中/成功/失败） |
| 同步任务只能 1 源表 → 1 目标表         | 一个同步任务可选多个源表，一次性同步多张表              |

### 1.3 Sprint 3 要达到的状态

> 工程师进入「数据开发」→ 新建 DAG → 从左侧拖入「同步任务」节点选已有同步任务 → 拖入「SQL 任务」节点写清洗 SQL → 连线 → 保存 →
> 点击执行 → 画布上每个节点依次变绿 → 元数据管理中自动出现 SQL 任务产出的新表。

### 6.4 DAG 画布

点击「新建 DAG」或「编辑」进入 DAG 画布页。画布为全屏布局，顶部工具栏 + 左侧节点面板 + 中间画布 + 右侧属性面板。

#### 6.4.1 顶部工具栏

```
┌────────────────────────────────────────────────────────────────────────────────────────────────────────┐
│ [← 返回列表]  DAG 名称：[订单数据流水线______]  触发方式：[定时 ▼]  Cron：[0 0 2 * * ?]  调度状态：[启用 ●] │
│                                                                                           [保存] [执行] │
└────────────────────────────────────────────────────────────────────────────────────────────────────────┘
```

- DAG 名称：可直接在工具栏编辑，失焦自动保存
- 触发方式：手动 / 定时。选择定时时出现 Cron 输入区，CronPicker 组件（同采集任务的 12 预设 + 六字段 Quartz 表达式 + 预览）
- 调度状态：启用 / 停用开关。停用时 Cron 配置保留但不触发；手动任务不受调度状态影响
- 「保存」：保存 DAG 配置（含所有节点和连线）。 **快捷键 Ctrl+S 等效。**
- 「执行」：触发一次 DAG 执行。仅当 DAG 处于「启用」状态时允许执行
- 「← 返回项目 DAG 列表」：回到项目下的 DAG 列表页。

> **启用/停用机制**：新建 DAG 默认处于「启用」状态。停用的 DAG 在列表中显示「⏸ 已停用」标签，既不能手动执行也不会被 Cron
> 触发。工程师可零成本停用正在编辑或调试的 DAG，避免未就绪的流水线被误触发。

**未保存拦截**：当画布存在未保存的更改（新增/删除/移动节点、修改连线、编辑节点内容）时，点击「返回」或关闭页面会弹出拦截提示：

```
┌────────────────────────────────────────┐
│ 未保存的更改                           │
├────────────────────────────────────────┤
│ 当前 DAG 有未保存的更改。              │
│                                        │
│ 是否保存后再离开？                     │
│                                        │
│  [  放 弃  ]  [  保 存 并 离 开  ]     │
└────────────────────────────────────────┘
```

- 「放弃」：丢失更改，返回列表
- 「保存并离开」：保存后返回列表
- 如果用户直接关闭浏览器标签，浏览器默认拦截行为生效

#### 6.4.2 左侧节点面板

固定在画布左侧，提供可拖拽的节点类型：

```
┌──────────────┐
│   节点面板    │
│              │
│ ┌──────────┐ │
│ │ 📝 SQL   │ │
│ │   任务    │ │
│ └──────────┘ │
│              │
│ ┌──────────┐ │
│ │ 🔄 同步   │ │
│ │   任务    │ │
│ └──────────┘ │
│              │
│ 拖拽节点到   │
│ 画布上添加   │
└──────────────┘
```

**拖拽行为**：从面板拖动节点图标到画布空白区域，松开后该位置出现一个新节点（默认名称"SQL 任务-1"或"同步任务-1"），节点自动按序号递增。

#### 6.4.3 中间画布

基于 ReactFlow 实现，支持以下操作：

- **拖拽节点**：在画布上移动节点位置
- **连线**：从一个节点的输出端口拖到另一个节点的输入端口，创建依赖关系
- **删除连线**：点击连线 → 按 Delete 键或右键菜单删除

### 6.7 DAG 执行

#### 6.7.1 手动执行

点击 DAG 画布顶部工具栏的「执行」按钮，整个 DAG 开始执行。

**并发控制**：同一 DAG 同一时刻只允许一个实例执行。若已有实例在运行中，点击「执行」会弹出提示：

```
┌──────────────────────────────────────┐
│ 无法执行                             │
├──────────────────────────────────────┤
│ 该 DAG 当前正在执行中，请等待        │
│ 当前执行完成后再次尝试。             │
│                                      │
│      [  我 知 道 了  ]                │
└──────────────────────────────────────┘
```

定时触发同样遵循此规则——若 Cron 触发时间到达时已有实例在跑，本次触发被跳过。

**执行流程**：

1. 按钮短暂 loading（约 1 秒），随后恢复
2. DAG 状态变为「运行中」
3. 画布上 **无上游依赖的节点**（入度为 0）率先开始执行，状态变为「运行中」
4. 多个无依赖或依赖已完成的节点 **可并行执行**，默认最大并行度为 3（可在系统配置中调整）
5. 上游节点执行成功 → 其下游节点自动开始执行
6. 上游节点执行失败 → 其下游节点标记为「被跳过」
7. 所有可执行节点完成或跳过 → DAG 执行结束，状态变为「成功」（所有节点成功）或「失败」（存在失败或被跳过的节点）

**终止执行**：

- 执行中的 DAG 在画布顶部工具栏和「执行历史」页均显示「终止执行」按钮。
- 点击后系统向正在运行的节点发送取消信号，SQL 任务尝试中断当前语句，同步任务尝试取消当前同步实例。
- 终止后：正在运行的节点标记为「失败」，未开始节点标记为「被跳过」，DAG 整体状态为「失败」。
- 已成功的节点结果保留，不触发失败节点的下游执行。

**执行中的画布表现**：

```
┌──────────┐      ┌──────────┐      ┌──────────┐
│ 📝 数据同步 │ ✓ ──→│ 📝 数据清洗 │ ⟳ ──→│ 📝 数据聚合 │ ⌛    │
│  (成功)     │      │  (运行中)   │      │  (等待中)   │       │
└──────────┘      └──────────┘      └──────────┘
```

**执行后**：

- 成功：SQL 任务中创建的新表自动注册到元数据管理中。注册逻辑与同步任务的自动注册一致——表直接出现在「Doris（内置）」节点下对应库中，无需采集任务。
- 失败：不更新元数据。

#### 6.7.2 定时执行

DAG 的定时调度在画布顶部工具栏配置（见 6.4.1）。配置 Cron 表达式后：

- 到达触发时间，DAG 自动执行一次。执行逻辑与手动执行完全相同。
- 调度启用/停用通过工具栏中的「调度状态」开关切换。停用时，Cron 配置保留但不触发。
- 「下次执行时间」根据 Cron 表达式动态计算，展示在 DAG 列表页。

> ⚠️ **风险提示**：其余表采用「同名自动映射」策略。若不同源表存在同名字段但类型不一致、或目标 Doris
> 中字段类型不兼容，执行时会失败。前端在保存任务前进行字段名/类型一致性预校验：发现同名不同型字段时，强制用户逐表确认或修正映射关系。

**其他字段**：同步模式、触发方式、容错配置对所有源表统一生效。

已有单表同步任务创建后不可直接切换为多表模式。如需多表同步，需新建任务。

### 6.9 同步速率限流（Sprint 2 NG5）

在创建/编辑同步任务抽屉的「容错配置」区域，新增限流配置：

```
───────────── 容错配置 ─────────────

失败重试次数
[3 ▼]  次（0 表示不重试）

重试间隔
[5 ▼]  分钟（1-30 分钟）

───────────── 限流配置（可选）─────────────

☐ 启用速率限制

读取速率上限
[______]  MB/s（不填表示不限制）

写入速率上限
[______]  行/s（不填表示不限制）
```

**字段说明**：

| 字段         | 必填 | 说明                                                     |
|--------------|------|----------------------------------------------------------|
| 启用速率限制 | —    | 复选框，默认不勾选                                       |
| 读取速率上限 | 否   | 对源端数据库的读取速度限制，单位为 **MB/s**，不填不限制  |
| 写入速率上限 | 否   | 对目标 Doris 的写入速度限制，单位为 **行/s**，不填不限制 |

> **为什么读写单位不同**：读取侧主要消耗源库网络/IO 带宽，用 MB/s 更直观；写入侧直接对应 Doris 的写入行数，用 行/s
> 更便于衡量数据同步进度。
>
> 限流场景：生产环境的源库不能承受全速读取；或 Doris 集群写入压力大需要控制。

### 6.10 画布与执行体验优化

以下优化点不引入新模块，但能显著降低工程师使用 DAG 的成本：

| 优化点                | 说明                                                                                                                    |
|-----------------------|-------------------------------------------------------------------------------------------------------------------------|
| 自动布局              | 画布工具栏提供「自动布局」按钮，一键按拓扑层级重新排列节点，减少手动拖拽排版的成本                                      |
| 空 DAG / 孤立节点校验 | 保存 DAG 时校验：① 至少包含 1 个节点；② 不存在与执行起点完全孤立、永远不会被触达的节点。校验不通过则拒绝保存并提示      |
| 失败节点快速定位      | DAG 执行失败后，画布上失败节点显示「查看错误」入口，点击后在节点属性面板展示错误摘要（如 SQL 语法错误、同步连接失败等） |
| 重跑失败分支          | 在执行历史页，对状态为「失败」的执行记录提供「重跑失败节点」按钮：仅重新执行失败或被跳过的节点，已成功节点不再重复执行  |
| SELECT 结果预览       | SQL 编辑器中执行 SELECT 语句后，结果以表格形式展示在弹窗结果区，仅用于验证数据，不注册到元数据                          |
| 元数据反向链接        | 元数据管理中，由 SQL 任务或同步任务自动注册的表，在表详情页显示「来源：DAG-XXX / 节点-YYY」，点击可跳转对应 DAG         |

## 7. SQL 任务自动注册元数据详解

### 7.1 触发条件

当 DAG 中的 SQL 任务节点 **正式执行成功**（非测试执行），且 SQL 中包含以下语句时，触发元数据自动注册：

| SQL 类型                                             | 是否触发注册 | 说明                                                                                                                              |
|------------------------------------------------------|:------------:|-----------------------------------------------------------------------------------------------------------------------------------|
| CREATE TABLE / CTAS                                  |      ✅      | 新表自动注册到元数据管理                                                                                                          |
| INSERT INTO / INSERT OVERWRITE                       |      ✅      | 若目标表已注册，更新其最近写入时间；若目标表尚未注册且语法允许（如 INSERT OVERWRITE 不存在的分区表在 Doris 中不允许），不主动注册 |
| ALTER TABLE (ADD COLUMN, DROP COLUMN, MODIFY COLUMN) |      ✅      | 更新对应表的字段结构                                                                                                              |
| DROP TABLE                                           |      ✅      | 从元数据管理中移除该表                                                                                                            |
| SELECT / DELETE / UPDATE                             |      ❌      | 不产生结构变化；SELECT 结果仅在编辑器内预览，不注册                                                                               |

### 7.2 展示位置

注册后的表出现在 **元数据管理左侧树**的「🏠 Doris（内置）」节点下对应的库中，与同步任务产出的表展示方式完全一致。

### 7.3 与采集任务的关系

内置 Doris 的表元数据 **不由采集任务管理**。采集任务只负责外部数据源。SQL 任务和同步任务是内置 Doris 元数据的唯二来源。

Sprint 3 新增同步任务被 DAG 引用的约束：

| 删除对象     | 被谁引用         | 处理方式                                               |

## 10. 验收标准

### 10.1 功能验收

| #     | 验收项                 | 通过标准                                                                    |
|-------|------------------------|-----------------------------------------------------------------------------|
| AC-1  | 创建 DAG               | 点击新建 → 进入画布 → 输入名称 → 保存 → DAG 列表出现该条目                  |
| AC-2  | 添加 SQL 任务节点      | 从面板拖动 → 画布出现节点 → 双击编辑 → 填写名称和 SQL → 保存                |
| AC-3  | 添加同步任务节点       | 拖动 → 选择已有同步任务 → 保存 → 节点显示任务摘要                           |
| AC-4  | 连线依赖               | 从节点 A 输出端拖到节点 B 输入端 → 连线创建成功 → 依赖关系确立              |
| AC-5  | 删除连线/节点          | 选中连线/节点 → Delete → 确认 → 移除                                        |
| AC-6  | 手动执行 DAG           | 点击执行 → 无上游节点率先运行 → 上游成功后下游自动触发 → 所有节点完成       |
| AC-7  | 上游失败下游跳过       | 人为让上游失败 → 下游标记为「被跳过」→ DAG 状态为「失败」                   |
| AC-8  | 定时执行 DAG           | 配置 Cron → 到达指定时间 → 自动执行 → 执行日志正确记录                      |
| AC-9  | 暂停/恢复调度          | 停用调度 → DAG 不再按 Cron 触发 → 启用调度 → 恢复触发                       |
| AC-10 | SQL 测试执行           | 在编辑弹窗中点击「运行测试」→ 结果显示在弹窗内 → 不更新元数据               |
| AC-11 | SQL 正式执行注册元数据 | DAG 正式执行 → SQL 节点中的 CTAS/CREATE TABLE → 新表出现在元数据管理中      |
| AC-12 | 多表同步               | 创建同步任务时选择多个源表 → 逐个映射目标表名 → 执行后所有表被同步          |
| AC-13 | 速率限流               | 启用限流并设置 5MB/s → 执行同步 → 实际读取速率不超过 5MB/s                  |
| AC-14 | 删除引用校验           | 删除被 DAG 引用的同步任务时，弹窗阻断列出 DAG 名称                          |
| AC-15 | 权限隔离               | 治理员可查看 DAG 但不能创建/编辑/执行；分析师仅可查看                       |
| AC-16 | 循环依赖校验           | 保存存在 A→B→A 循环依赖的 DAG 时，系统拒绝保存并提示                        |
| AC-17 | 多分支并行执行         | 构建两个无依赖的并行分支 → 同时执行 → 总体耗时低于串行执行                  |
| AC-18 | 终止执行               | 运行中的 DAG 点击「终止执行」→ 当前节点停止 → 下游标记为跳过 → DAG 状态失败 |
| AC-19 | 同步任务变更感知       | 修改被引用的同步任务目标表 → 重新打开 DAG 画布 → 节点摘要显示新目标表       |
| AC-20 | SQL 测试不污染元数据   | 在 SQL 节点弹窗点击「运行测试」执行 CTAS → 元数据管理中不出现新表           |

## 13. 附录：DAG 数据模型概念

```
Project
├── projectId: string
├── name: string (全局唯一)
└── description?: string

DAG
├── dagId: string
├── projectId: string (所属项目)
├── name: string (项目内唯一，项目之间可重名)
├── triggerType: 'MANUAL' | 'CRON'
├── cronExpression?: string
├── scheduleEnabled: boolean
├── maxParallelism: number (默认 3)
├── nodes: DAGNode[]
│   ├── nodeId: string (DAG 内唯一)
│   ├── nodeName: string (DAG 内唯一)
│   ├── nodeType: 'SQL' | 'SYNC'
│   ├── position: {x, y}
│   └── config:
│       ├── (SQL 节点) sqlContent: string
│       └── (同步节点) syncTaskId: string, syncTaskName: string
└── edges: DAGEdge[]
    ├── edgeId: string
    ├── sourceNodeId: string
    └── targetNodeId: string

DAGExecution (运行实例，与 DAG 定义分离)
├── executionId: string
├── dagId: string
├── triggerType: 'MANUAL' | 'CRON'
├── startTime: datetime
├── endTime?: datetime
├── status: 'RUNNING' | 'SUCCESS' | 'FAILED' | 'TERMINATED'
└── nodeExecutions: NodeExecution[]
    ├── nodeId: string
    ├── status: 'WAITING' | 'RUNNING' | 'SUCCESS' | 'FAILED' | 'SKIPPED'
    ├── startTime?: datetime
    ├── endTime?: datetime
    └── errorMessage?: string
```

> 注：此图为概念模型，不涉及数据库表设计。核心原则是 **DAG 定义与运行时状态分离**：`DAG` 表只保存静态配置；每次执行生成一条
> `DAGExecution` 记录，节点运行状态写入 `NodeExecution`，避免多实例并发执行时互相覆盖状态。
