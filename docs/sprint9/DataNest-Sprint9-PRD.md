# Sprint 9：实时计算深化（CDC 监控 + Checkpoint 管理 + 流处理告警）PRD

> **版本**：v1.0 | **日期**：2026-08-11 | **作者**：产品通
>
> **Sprint 目标**：在 Sprint 8 打通平台第一条实时链路（CDC 管道）的基础上，让实时链路**可观测、可运维、可告警**——监控从「两个瞬时值」升级为「指标历史 + 趋势图」，Checkpoint/Savepoint 从「黑盒」变为可视可管，异常从「人盯页面」升级为「规则化邮件告警」；同时清零 Sprint 8 F2 遗留的可靠性 TODO，让实时链路达到生产可运维水位。

---

## 1. 问题陈述

### 1.1 为什么 Sprint 9 做这件事

Sprint 8 F2 交付了完整的 CDC 管道能力（向导创建 / 启停 / savepoint 恢复 / 日志 / 延迟与累计变更监控，MySQL + PostgreSQL 双源实测通过）。但作为平台的长期运行链路，它目前还是一个**「能跑但看不透、坏了没人知」的黑盒**：

**缺口一：监控只有瞬时值，没有历史。**
管道列表只能看到「当前延迟」「累计变更数」两个轮询瞬时值。工程师无法回答「这条管道昨天半夜延迟为什么飙高」「最近一周吞吐量趋势如何」「作业重启过几次」——没有指标历史，就没有容量评估与故障回溯的依据。路线图 Sprint 10「流处理监控（吞吐量、延迟、错误数）」正是为此设计。

**缺口二：Checkpoint / Savepoint 完全不可见。**
CDC 作业的容错全靠 Flink Checkpoint 与 savepoint，但平台上既看不到 checkpoint 是否健康（最近成功时间、耗时、大小），也无法手动触发 savepoint；savepoint 文件在 MinIO 上只增不减。Sprint 8 遗留 TODO 还暴露出两个可靠性硬伤：Flink 集群重启丢作业后管道**永远卡在 RUNNING**（无法停止/删除）；作业已丢失时停止操作直接失败且无降级路径。

**缺口三：异常没有主动告警。**
管道 FAILED 或延迟飙高时，平台只在管道日志里写一条记录，工程师不打开页面就无从得知。Sprint 6 起平台已有成熟的 app-alert 告警体系（规则/订阅/邮件），CDC 管道尚未接入。

所以 Sprint 9 的核心命题是：**让实时链路可观测、可运维、可告警**，对应规格文档 §15 路线图 Sprint 10「实时计算深化」。

### 1.2 当前用户怎么做的（痛点）

| 现在 | Sprint 9 之后 |
|------|----------------|
| 管道延迟飙高只能事后被业务方追问，无法回溯历史定位 | 运行监控页签展示延迟/吞吐趋势图（1h~7d），故障时段一目了然 |
| 想知道作业是否健康只能开 Flink Web UI 看裸指标 | 平台内直接展示 checkpoint 健康度（最近成功/耗时/失败次数）与作业重启次数 |
| 想手动做 savepoint 只能去 Flink REST 敲命令 | 管道操作一键「触发 Savepoint」，路径回写管道记录 |
| 集群重启后管道卡死在「运行中」，无法停止只能改库 | 作业丢失自动归并「外部停止」语义：置 STOPPED + 日志 + 可告警 |
| 管道半夜 FAILED，早上上班才发现，数据已积压数小时 | 告警规则命中即邮件通知订阅人（作业失败/延迟超阈值/外部停止） |
| savepoint 文件在 MinIO 只增不减，存储缓慢膨胀 | 删除管道时级联清理其 savepoint 文件，支持手动清理 |

### 1.3 Sprint 9 要达到的状态

> 数据工程师打开「CDC 管道」详情抽屉的「运行监控」页签，看到 `orders-sync` 管道最近 24 小时的延迟趋势在 02:00 有一次尖峰（归因于上游批量归档作业），吞吐量曲线平稳，作业重启 0 次。
>
> 同一抽屉的「检查点」页签显示最近 checkpoint 全部成功、平均耗时 1.2s；工程师在发布窗口前手动触发一次 savepoint，路径回写管道记录，随后停止管道做升级，启动后从该 savepoint 恢复不丢不重。
>
> 凌晨 03:12 管道因源库重启失败，告警规则「CDC 异常通知」命中「作业失败」条件，订阅人收到邮件（管道名 + 错误摘要 + 时间）；工程师早上按邮件进入管道详情查看趋势与日志，重启恢复。

## 6. 功能详细交互

### 6.1 导航与页面结构

### 6.2 流处理监控深化（运行监控页签）

```
┌─ 管道详情：orders-sync ── 运行监控 ────────────────────────────────┐
│  [1h] [6h] [24h ✓] [7d]                       更新于 10:22:05      │
│                                                                    │
│  ┌──────────┬──────────┬──────────┬──────────┐                     │
│  │ 当前延迟  │ 当前吞吐  │ 累计变更  │ 作业重启  │                     │
│  │ 2 秒     │ 36 行/秒  │ 120,431  │ 0 次     │                     │
│  └──────────┴──────────┴──────────┴──────────┘                     │
│                                                                    │
│  ── 延迟趋势（秒）──                                                │
│  [折线图：选定时间范围内延迟均值/峰值，超阈值区段标红]                │
│                                                                    │
│  ── 吞吐量趋势（行/秒）──                                           │
│  [折线图：选定时间范围内吞吐均值]                                    │
└────────────────────────────────────────────────────────────────────┘
```

**交互说明**：
- **指标来源**：沿用现有 5 秒监控轮询从 Flink REST 提取的指标，新增**按分钟降采样**写入指标历史表（延迟取均值+峰值、吞吐取均值、重启次数取增量）；**保留 30 天**，过期定时清理（倾向方案 T1，已确认）。
- **KPI 卡**：当前延迟 / 当前吞吐（行/秒）/ 累计变更 / 作业重启次数（运行态实时值，与列表页口径一致）。
- **趋势图**：延迟与吞吐两张折线图，时间范围 1h / 6h / 24h / 7d（默认 24h）；延迟图中超过告警阈值的区段标红提示；无数据时段断点展示，不插值造假。
- **「错误数」口径产品化**：Flink CDC 作业无直接「错误行数」指标，本期以**作业重启次数 + 失败事件（日志/告警）**作为异常度量呈现（倾向方案 T2，已确认）。
- **非运行态**：管道非 RUNNING 时 KPI 显示最后已知值并标注「已停止」，趋势图正常展示历史。

### 6.3 Checkpoint 与 Savepoint 管理（检查点页签）

```
┌─ 管道详情：orders-sync ── 检查点 ──────────────────────────────────┐
│  ┌──────────────┬──────────────┬──────────────┐                    │
│  │ 最近 Checkpoint│ 平均耗时     │ 失败（24h）   │                    │
│  │ 10:21:58 ✓   │ 1.2 秒       │ 0 次         │                    │
│  └──────────────┴──────────────┴──────────────┘                    │
│                                                                    │
│  ── Checkpoint 历史（最近 20 条）──                                 │
│  │ 触发时间          耗时     大小      状态                        │
│  │ 08-11 10:21:58   1.1s    12.3 MB   ✓ 完成                      │
│  │ 08-11 10:21:28   1.4s    12.1 MB   ✓ 完成                      │
│                                                                    │
│  ── Savepoint ──                                                    │
│  当前 savepoint：s3a://datalake/savepoints/sp-3f2a…（08-10 22:00）  │
│  [触发 Savepoint]（运行中可用）                                      │
└────────────────────────────────────────────────────────────────────┘
```

**交互说明**：
- **Checkpoint 健康度**：最近成功时间 / 平均耗时 / 24h 失败次数三卡；历史列表展示最近 20 条（触发时间、耗时、大小、状态）。
- **手动触发 savepoint**：运行中管道可点「触发 Savepoint」，完成后路径回写管道 `savepoint_path`（语义同停止时自动生成，下次启动优先从该位点恢复）；触发过程按钮 loading，失败给出明确错误。
- **Savepoint 文件治理（遗留 TODO ③）**：删除管道时**级联删除其 savepoint 文件**（MinIO S3 客户端，删文件失败不阻断删除、warn 留痕）；已编辑/重建导致失效的旧 savepoint 在替换时同步清理（倾向方案 T3，已确认）。
- **数据来源**：checkpoint 历史来自 Flink REST checkpoints 接口，**实时拉取不落库**（最小改动；历史持久化列入未来）。

### 6.4 流处理告警（复用 app-alert）

**规则配置**（系统管理 → 告警规则，对象类型新增「CDC 管道」）：

```
┌─ 新建告警规则 ─────────────────────────────────────────────────────┐
│  规则名称 *  [CDC 异常通知]                                         │
│  对象类型 *  [CDC 管道 ▼]     （新增选项，与 DAG/同步任务等并列）   │
│  告警对象 *  [☑ orders-sync  ☑ user-sync]   （按管道多选）          │
│  触发条件 *  [☑ 作业失败] [☑ 延迟超阈值] [☑ 外部停止]                │
│  接收人     [张三、李四]                                            │
└────────────────────────────────────────────────────────────────────┘
```

**交互说明**：
- **触发条件**（三选，至少一项）：
  - **作业失败**：监控轮询发现 Flink 作业 FAILED（管道置 ERROR）时触发；
  - **延迟超阈值**：同步延迟超过全局阈值（Nacos `datanest.realtime.lag.warn-threshold`，默认 30 秒）时触发；同一管道连续超阈值**只告警一次**，恢复后允许再次告警（沿用现有 lagWarned 去重语义，升级为邮件）；
  - **外部停止**：作业被外部取消/丢失（含本期新增的 404 归并场景，见 §6.5）时触发。
- **触发链路**：`CdcMonitorService` 状态变更点经 alert-api Feign（`/alert/internal/**`）上报，复用 app-alert 的规则匹配、订阅人与邮件发送；**远端失败降级只记管道日志，不阻断监控主流程**（对齐告警跨域既有约定）。
- **邮件内容**：管道名、告警类型、当前延迟/错误摘要、发生时间。
- **告警历史**：现有告警历史页可见 CDC_PIPELINE 记录（对象名经 Feign 反查 realtime，管道已删显示原始名）。
- **新增跨域反查**：app-alert 侧「可选告警对象下拉」与对象名回填需经 realtime 内部端点批量拉取管道 id + name（新增 `/realtime/internal/**` 端点，fail-open 降级空值）。

### 6.5 遗留可靠性补齐（S8 F2 TODO 清零）

| # | 遗留问题（Sprint 8 §7 记录） | 本期产品语义 |
|---|------------------------------|--------------|
| ① | 监控遇 Flink REST 404（集群重启丢作业）只 WARN 保持原状态，管道永远卡 RUNNING | **404 归并「外部停止」**：置 STOPPED + 清 flink_job_id + WARN 日志 + 触发「外部停止」告警；为防集群短暂不可达误伤，**连续 N 轮（默认 3 轮）404 才判定**（倾向方案 T4，已确认） |
| ② | 作业已丢失时 stop-with-savepoint 失败 8008，无降级路径 | 停止流程检测作业已不存在 → 提供**「强制停止」**：跳过 savepoint、置 STOPPED、清 savepoint_path 并弹窗提示「未保存位点，下次启动将按启动位点重新同步」 |
| ③ | savepoint 文件物理清理未做 | 见 §6.3（删除管道级联清理 + 替换时清理失效文件） |
| ④ | PG 源限制（REPLICA IDENTITY FULL / 仅 public schema / 无最早位点）只在文档 | 向导与预检中**产品化提示**：PG 源勾选表时对未开 REPLICA IDENTITY FULL 的表给出警示（能检则检，不能检则在向导固定提示文案） |

## 9. 验收标准

### 9.1 功能验收

| # | 验收项 | 通过标准 |
|---|--------|----------|
| AC-1 | 指标历史 | 运行中管道指标按分钟降采样落库；保留 30 天，过期数据被清理 |
| AC-2 | 监控趋势图 | 1h/6h/24h/7d 切换渲染正确，数据与指标历史一致；超阈值区段标红；无数据时段断点 |
| AC-3 | 检查点可视 | 检查点页签展示健康度三卡 + 最近 20 条历史，与 Flink REST 数据一致 |
| AC-4 | 手动 savepoint | 运行中触发成功，路径回写管道；停止→启动后从该位点恢复不丢不重 |
| AC-5 | savepoint 清理 | 删除管道后其 savepoint 文件在 MinIO 上不存在；删文件失败不阻断删除 |
| AC-6 | 404 自愈 | 重启 Flink 集群（作业丢失）后，管道在 N 轮轮询内自动置 STOPPED 并写日志 |
| AC-7 | 强制停止 | 作业已丢失的 RUNNING 管道可强制停止成功，状态与 savepoint 清理符合提示语义 |
| AC-8 | 流处理告警 | 三类触发条件分别命中时订阅人收到邮件；连续超阈值只告警一次；告警历史可查 |
| AC-9 | 告警规则 UI | 告警规则对象类型可选「CDC 管道」，对象下拉返回管道列表；删除管道后规则对象被解绑 |
| AC-10 | 权限隔离 | 分析师不可触发 savepoint/配置告警规则；各角色可见性与权限矩阵一致 |

### 9.2 非功能验收

| # | 验收项 | 通过标准 |
|---|--------|----------|
| NAC-1 | 监控开销 | 指标降采样写入不引入明显 DB 压力（单管道每分钟 ≤ 1 行）；趋势图查询 P95 < 2s |
| NAC-2 | 告警可靠性 | app-alert 不可达时监控主流程不受影响，仅降级记管道日志 |

| NAC-4 | 恢复语义 | 手动 savepoint → 停止 → 启动恢复链路实测不丢不重（对齐 Sprint 8 AC 口径） |

## 10. 风险与对策

| # | 风险 | 影响 | 对策 |

| R6 | app-alert ↔ realtime 双向 Feign（触发 + 反查）引入耦合 | 调用链复杂 | 沿用既有跨域模式（独立 internal 端点 + 降级）；两端点均无状态、失败互不影响 |
