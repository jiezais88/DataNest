# Sprint 7：数据资产目录 PRD

> **版本**：v1.0 | **日期**：2026-08-05 | **作者**：产品通
>
> **Sprint 目标**：让数据分析师拥有一站式的数据资产发现入口——找得到、看得懂、敢使用。在现有治理能力（元数据采集、血缘可视化、数据质量管理）之上，扩展数据搜索、数据详情聚合、血缘与质量联动、按数据域分类浏览五项 P0 能力，并顺带交付三项轻量增强（子 DAG 参数下发、任务模板库、自定义质量规则 Python）。

---

## 1. 问题陈述

### 1.1 为什么 Sprint 7 做这件事

Sprint 2~6 已经把数据的「采集、开发、治理、血缘、质量、告警」打通了：元数据能采上来了，血缘看得见了，质量能打分了、告警能发了。但**面向数据使用者的最后一公里——「找数据」——还是空的**：

- 分析师想找「用户订单相关的表」，当前只能靠问人或挨个翻元数据树，没有统一检索入口；
- 找到一张表后，它的**含义、负责人、来源、更新频率、质量是否可信**散落在元数据详情、血缘图、质量评分三个页面，没有聚合展示；
- 平台治理侧已经积累了质量评分、血缘关系，但资产目录（catalog）一直没交付，这些成果没有面向分析师的统一出口。

规格文档 v2.0 的「模块四：数据资产目录」（DC-01~05 P0）正是为此设计。同时，路线图中把三项轻量增强（NG5 子 DAG 参数透传、DD-09 任务模板库、DG-10 自定义质量规则）并入本期，让数据开发与数据治理侧同步补齐能力断层。

所以 Sprint 7 的核心命题是：**让分析师能搜到表、看懂表、敢用表；让开发与治理侧补齐参数透传、模板复用与自定义规则能力**。

### 1.2 当前用户怎么做的（痛点）

| 现在                                                                 | Sprint 7 之后                                                        |
|----------------------------------------------------------------------|----------------------------------------------------------------------|
| 分析师找表靠问人或挨个翻元数据树，没有统一检索                         | 「数据资产」首页大搜索框，按表名/字段/注释/标签/负责人模糊检索并排序 |
| 表的基础信息、血缘、质量评分散在三个页面，难以聚合判断可信度           | 独立「资产详情页」页签式聚合基础信息 + 字段 + 血缘 + 质量            |
| 元数据表没有负责人、没有数据域分类，资产管理「无人认领、无序归类」     | 支持为表配置负责人与数据域/主题分类，按分类浏览                     |
| 子 DAG 只能同步/异步执行，主 DAG 无法向子 DAG 传参，复杂编排受限       | 子 DAG 节点支持主→子参数下发，一次配置后续复用                      |
| 建同步/SQL 任务逐项配置，重复劳动；质量规则只支持 SQL，无 Python 规则  | 提供常用任务模板一键创建；质量规则新增 Python 类型，强化自定义 SQL  |

### 1.3 Sprint 7 要达到的状态

> 分析师打开「数据资产」首页，输入「订单」→ 秒级返回相关表列表（命中表名/字段名/注释），按相关度排序，带质量健康度徽章与数据域分类标签。
>
> 点击 `dwd.orders` 进入资产详情页，页签聚合展示：基础信息（含负责人、数据来源、更新频率）、字段列表（名/类型/含义）、上下游血缘图谱、质量评分与最近检查结果。分析师据此判断这张表「可信、敢用」。
>
> 分析师在「数据资产」左侧数据域树点「交易域」，右侧列出该域下全部资产卡片，可按质量评分排序，快速发现高质量可用表。
>
> 数据工程师在 DAG 编排中配置子 DAG 节点时，可为主 DAG 参数下发到子 DAG；用「任务模板库」一键创建同步/SQL 任务；在质量规则中选用 Python 规则模板编写自定义校验逻辑。

### 6.2 数据资产首页与搜索（DC-01）

「数据资产」首页顶部为全局大搜索框，下方为数据域分类侧栏 + 资产卡片流：

```
┌─ 数据资产 ─────────────────────────────────────────────────────────────┐
│                                                                         │
│  [ 🔍  输入表名 / 字段名 / 注释 / 标签 / 负责人，回车搜索      ]         │
│  热门：dwd_orders  dim_user  ads_gmv  …                                │
│                                                                         │
│  ┌──────────┬────────────────────────────────────────────────────────┐ │
│  │ 全部资产   │  dwd_orders  用户订单明细      [高]  交易域  ⭐85     │ │
│  │ ▸ 交易域   │  dwd_order_items  订单明细      [高]  交易域  ⭐78     │ │
│  │ ▸ 用户域   │  dim_user  用户维度表            [高]  用户域  ⭐92     │ │
│  │ ▸ 商品域   │  ods_orders  订单原始表          [低]  交易域  —        │ │
│  │ ▸ 营销域   │  …                                                     │ │
│  │ 未分类     │                                                        │ │
│  └──────────┴────────────────────────────────────────────────────────┘ │
└─────────────────────────────────────────────────────────────────────────┘
```

**搜索交互**：
- **搜索范围**：按表名、字段名、注释、标签、负责人五类字段全局匹配，模糊搜索（LIKE 或全文索引）。
- **相关度排序**：命中表名 > 命中注释 > 命中字段名 > 命中标签/负责人；表名前缀命中优先。
- **结果卡片**：表名、注释、所属数据源/库、质量健康度徽章（复用 `QualityScoreBadge`）、数据域分类标签、最近更新。
- **性能**：响应 < 2 秒（首屏搜索结果），支持防抖。
- **来源复用**：扩展现有 `searchMetadataTree(keyword)`（仅表名）为多维度搜索接口，新增相关度得分返回。

> **标签搜索说明**：标签能力（DC-06）本期不做，但 DC-01 的搜索维度预留「标签」字段（当前无标签则跳过该维度），避免后续扩展时改接口。

**交互说明**：
- **基础信息页签**：聚合 `metadata_table` 基础字段 + 新增「负责人」「数据域分类」展示；数据来源、更新频率沿用元数据采集结果。
- **字段列表页签**：复用现有元数据详情字段列表。
- **血缘图谱页签**：复用治理血缘图组件（`getLineageByTargetTable`），无血缘时展示空态。

- **导航**：资产详情页可独立路由（如 `/asset-catalog/{tableId}`），分析师入口统一从数据资产首页进入。

> **复用**：现有「元数据管理」详情页已含基础信息/字段/血缘/质量页签，资产详情页复用之并新增负责人/分类聚合展示；两处入口并存（治理侧元数据管理、分析侧数据资产）。

### 6.4 数据分类浏览（DC-05）

数据资产首页左侧为「数据域/主题分类树」，右侧为该分类下的资产卡片列表：

```
┌─ 数据资产 → 交易域 ───────────────────────────────────────────────────┐
│  ▸ 全部资产     [分类下的资产]                                          │
│    ▸ 交易域 ●   dwd_orders      用户订单明细     ⭐85   每日更新        │
│      ▸ 订单     dwd_order_items 订单明细         ⭐78   每日更新        │
│      ▸ 支付     ods_orders      订单原始表       —     实时             │
│    ▸ 用户域                                                            │
│    ▸ 商品域                                                            │
│    ▸ 未分类                                                            │
└─────────────────────────────────────────────────────────────────────────┘
```

**交互说明**：
- **分类体系**：数据域（一级）→ 主题（二级），支持治理员自定义增删改、排序。
- **表分配**：在元数据管理详情或资产详情页为表分配「数据域 + 主题」，也可批量设置分类。
- **分类浏览**：点击左侧分类节点，右侧展示该分类下资产卡片（表名/注释/质量徽章/更新频率），支持按质量评分排序、按数据源筛选。
- **未分类**：未配置分类的表归入「未分类」节点，便于治理员补分类。
- **新增字段**：`metadata_table` 新增分类字段（数据域/主题，或关联分类表），负责人字段一并新增（DC-02 使用）。

> **权限**：分类体系维护（增删改、分配）仅治理员/超管；分析师只读浏览。

### 6.5 子 DAG 参数下发（NG5）

子 DAG 节点配置弹窗在「同步执行 / 异步执行」基础上，新增**参数下发**配置：

```
┌─ 子 DAG 配置 ─────────────────────────────────────────────────────────┐
│  节点名称 *  [子 DAG]                                                   │
│  选择子 DAG *  [交易 DAG ▼]                                            │
│  执行方式    ● 同步执行   ○ 异步执行                                    │
│                                                                         │
│  ⚙ 参数下发（可选）                                                    │
│  主 DAG 参数 → 子 DAG 参数映射：                                        │
│  主参数              子 DAG 参数          操作                            │
│  ${biz_date}    →   ${sub_date}       [删除]                            │
│  ${env}         →   ${env}            [删除]                            │
│  [+ 添加映射]                                                          │
│                                                                         │
│  说明：下发的主 DAG 参数在执行子 DAG 前解析为实际值，作为子 DAG 的运行参数。│
│                                                                         │
│                    [取消]  [保存]                                      │
└─────────────────────────────────────────────────────────────────────────┘
```

**交互与边界**：
- **主→子单向下发**：仅支持主 DAG 参数下发到子 DAG 作为其运行参数；**不支持**子 DAG 结果回传主 DAG（NG1 延后）。
- **映射配置**：子 DAG 节点保存「主参数名 → 子参数名」映射列表，执行时主参数解析为实际值后注入子 DAG 参数集。
- **参数来源**：复用现有 `DagParameter` 体系（主 DAG 参数配置、TriggerParamsModal），主参数引用主 DAG 已声明参数。
- **现状**：现有 `SubDagNodeModal` 明确「本期不支持子 DAG 参数透传与覆盖」，本期补齐主→子下发。
- **执行链路**：子 DAG 触发时，将映射后的参数一并传给子 DAG 执行上下文；子 DAG 内部沿用现有参数解析（`DagParameterResolver`）。

> **仅主→子**：本期不涉及子 DAG 将自身输出回传主 DAG 的场景（如「子 DAG 产出行数返回主节点」），留待后续。

### 6.6 任务模板库（DD-09）

「数据开发 → 任务模板」提供常用任务模板，从模板一键创建任务。**区别于现有质量规则模板库（quality_rule_template）**：

> **类型范围（2026-08-08 用户确认收敛）**：本期仅 **同步任务 / 采集任务** 两类。SQL 任务平台无独立任务实体（仅为 DAG 节点类型）、数据导出功能不存在，均不在本期范围；模板类型保留扩展位（服务层白名单，无 DB CHECK）。

```
┌─ 任务模板 ─────────────────────────────────────────────────────────────┐
│  全部  同步任务  采集任务   内置  自定义                                 │
│  ┌────────────────────────────────────────────────────────────────┐  │
│  │  整表同步（内置）     源→目标整表同步，含数据源/库表占位符       │  │
│  │  增量同步（内置）     按增量字段每日定时同步，含调度 Cron 占位   │  │
│  │  元数据全量采集（内置）从源库全量采集元数据（库/表/字段）        │  │
│  │  ...                                                             │  │
│  └────────────────────────────────────────────────────────────────┘  │
│  [+ 新增模板]                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

**交互说明**：
- **模板维度**：按任务类型（同步/采集）提供常用模板，含占位参数（如 `{source_table}`、`{target_db}`、`{schedule_cron}`；数据源类占位参数渲染为数据源下拉）。
- **一键创建**：点模板卡片 → 填充模板中占位参数 → 生成对应类型任务草稿（同步任务落 `sync_job`，采集任务落 `collect_task`）→ 保存后进入任务编辑/调度配置。
- **自定义模板**：支持用户将已配置好的任务保存为模板复用（另存为时配置原样保留，单表同步任务的源表与定时 Cron 自动占位化）。
- **内置模板**：平台预置，禁改禁删，可复制为自定义后修改。
- **与质量模板库区别**：任务模板库面向**数据开发任务**（同步/采集），质量模板库（quality_rule_template）面向**质量规则**，两者对象、字段、落地表完全独立。

### 6.7 自定义质量规则增强（DG-10）

#### 6.7.1 新增 Python 规则类型

规则类型从四类扩展为**五类**：完整性 / 唯一性 / 值域范围 / 自定义 SQL / **Python**。

```
┌─ 新增规则（类型：Python） ─────────────────────────────────────────────┐
│  规则名称 *  [金额波动 Python 校验]                                      │
│  规则类型 *  [Python ▼]                                                 │
│  选择表 *    [dwd.orders ▼]                                             │
│  检查字段    [amount]                                                    │
│  Python 脚本 *                                                          │
│  [def check(df):            # 脚本约定见下                             │
│   │    null_rate = df['amount'].isnull().mean()                        │
│   │    return {'null_rate': null_rate}   # 返回 dict 统计值             │
│  ]                                                                      │
│  返回指标 *  [null_rate]                                                │
│  警告阈值    [0.01]    严重阈值 [0.05]                                  │
│  权重        [2]                                                       │
│  [测试脚本]  [预览]                                                     │
│                    [取消]  [保存]                                      │
└─────────────────────────────────────────────────────────────────────────┘
```

**Python 规则约定**：
- **脚本入口**：约定函数签名（如 `def check(df)` 接收目标表 DataFrame），返回 `dict` 统计值（指标名 → 数值）。
- **执行环境**：在 worker 执行节点运行（复用质量执行 handler），需安装 Pandas 等基础依赖。
- **结果指标**：脚本返回的指标名映射到规则结果指标，后续沿用分级判定（警告/严重阈值）。
- **测试脚本**：提供「测试」能力对单条规则执行并预览返回统计值。

#### 6.7.2 强化自定义 SQL 规则

在现有 `CUSTOM_SQL` 基础上增强：

| 增强点     | 现状                                           | Sprint 7                                                        |
|------------|------------------------------------------------|-----------------------------------------------------------------|
| SQL 模板化 | 直接填 SQL                                      | 支持保存为自定义模板（复用规则模板库），含占位符                 |
| 参数化     | 无                                             | SQL 支持 `${table}`/`${column}`/`${min}`/`${max}` 等占位（复用 RuleSqlGenerator） |
| 结果指标   | 默认单一统计值                                  | 支持多指标返回与指定结果指标                                    |
| 预览       | 已有 preview-sql                               | 保留，增强多指标返回预览                                        |

## 10. 风险与对策

| #  | 风险                             | 影响           | 对策                                                                    |
|----|----------------------------------|----------------|-------------------------------------------------------------------------|
| R1 | 搜索性能（多字段模糊匹配）       | 响应慢         | 采用索引/全文检索；首屏防抖；千级表可先 LIKE，量大再上全文索引          |
| R2 | Python 规则执行环境依赖          | 执行失败       | worker 预装 Pandas 等基础依赖；执行超时中断；失败标记不可用不误告警     |
| R3 | 资产详情页聚合数据源多、加载慢   | 页面卡顿       | 页签懒加载；血缘/质量按页签进入时拉取；接口返回可聚合                  |
| R4 | 分类体系缺失导致资产无归属       | 浏览价值低     | 「未分类」节点兜底；分类维护引导；搜索不受分类影响                     |
| R5 | 子 DAG 参数下发参数名冲突        | 执行异常       | 映射时校验主参数存在、子参数名唯一；冲突提示                             |
| R6 | 任务模板占位符解析失败           | 任务创建失败   | 模板占位符统一约定；创建时校验必填占位符已填充                         |
| R7 | 质量 Python 规则与既有分级判定脱节 | 结果不可比    | Python 规则沿用统一 result_level 判定与 quality_check_detail 落库       |
