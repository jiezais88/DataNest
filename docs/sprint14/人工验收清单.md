# DataNest Sprint 14 人工验收清单（页面操作版）

> **给谁看**：不熟悉代码和接口的产品、测试或业务验收人员。  
> **怎么用**：从第 0 节开始，按顺序执行；每完成一项就勾选对应的 `- [ ]`。除“验收前准备”和标有“辅助操作”的步骤外，全部按页面操作。  
> **验收范围**：企业 SSO（OIDC/OAuth2）、LDAP/AD 登录、角色映射、混合/仅 SSO 登录模式、本地密码策略、密码过期、失败锁定、账号绑定与解绑、权限和审计。  
> **自动化基线**：Sprint 14 已完成 API 17/17、UI 9/9，共 26/26 通过。本清单不是自动化报告的重复版，重点补验真实浏览器交互、配置热生效、恢复能力和人工可观察结果。

## 0. 验收规则和优先级

### 0.1 优先级

| 标记 | 含义 | 建议处理 |
|---|---|---|
| P0 | 登录、权限或安全主链路，失败则不能通过 Sprint 14 | 必须通过 |
| P1 | 管理体验、审计、异常提示或补充安全场景 | 原则上通过；若环境限制无法执行，要记录原因 |
| 辅助 | 需要测试负责人使用接口或数据库准备数据，不是普通用户操作 | 由熟悉环境的人员执行，验收人只看页面结果 |

### 0.2 执行纪律

1. 所有用例串行执行，不要同时用多个浏览器修改身份认证配置。
2. 修改“登录模式、角色映射、密码策略”的用例，必须记录原值，并在用例结束时恢复。
3. Nacos 配置热生效可能需要几秒。保存后等待 3～10 秒，再刷新页面或重新登录，不要因为立即读到旧值就判定失败。
4. 不要在验收过程中执行 `docker compose up`。该操作可能触发 Nacos 初始化，把 SSO 配置恢复为默认关闭状态。
5. 每个失败项记录：用例编号、操作到哪一步、页面提示、实际结果、截图和时间。
6. 看到密码、Token、客户端密钥等敏感信息时，不要截图或粘贴到缺陷单；截图前先遮挡。
